# V_pk_fma

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#114](https://github.com/ROCm/Tensile/pull/114) · **Merged:** 2017-10-02 · **Author:** @amcamd

**Inclusion reason:** kernel path 'Tensile/BenchmarkProblems.py'; keyword 'gemm'

## Summary (from upstream PR description)

Changes to get hgemm to call 32 bit vectorized_packed_fma in place of 16 bit multiply and add. Note that this pull request has no changes for load and store commands. The plan is to address these in assembly code, not with half4 or half8 loads.
There is a change to initialize matrices with random values in [-max,max] rather than values in [0,max]. The reason for this change is to reduce the accumulator value in the reduction sums. This is achieved by having negative and positive values in the reduction sum. This is required because the 16 bit reduction sums for matrix size 4096 were giving overflow and underflow to inf or -inf.
