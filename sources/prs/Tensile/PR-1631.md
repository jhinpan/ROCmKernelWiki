# Report errors if any tuned kernels fail to generate or compile

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1631](https://github.com/ROCm/Tensile/pull/1631) · **Merged:** 2023-01-06 · **Author:** @AlexBrownAMD

**Inclusion reason:** kernel path 'Tensile/TensileCreateLibrary.py'; keyword 'kernel'

## Summary (from upstream PR description)

Rocblas does not report errors at build time if a tuned kernel fails to generate or compile. Lack of error reporting is caused by enabling either merge files or lazy-loading features. The problem is current error checking is based on number of files generated, and when files are merged expected output is always 1 unless all kernels fail to build.
This change updates the code to error out if any kernels fail to generate or compile. Error checking can be disabled by setting the errorTolerant option. Using the library to do things like test or benchmark will run in error tolerant mode by default. Error messages are normally only enabled when building kernels from a previously generated library logic file (like during a rocblas build).
Tested locally using valid logic files and ones with errors introduced and produces anticipated results.
Also tested a full rocblas build and it detected an invalid tuned kernel - I'll work on an update to the logic files that will need to be merged into rocblas before this change is used.
