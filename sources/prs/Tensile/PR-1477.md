# Add option to write different architectures to different TensileLibrary files

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1477](https://github.com/ROCm/Tensile/pull/1477) · **Merged:** 2022-03-11 · **Author:** @JeremyAdamHart

**Inclusion reason:** kernel path 'Tensile/Common.py'

## Summary (from upstream PR description)

A large contributor to the time required to initialize Tensile is the parsing of the TensileLibrary.dat/yaml file. While only the code object files for the used architecture are loaded with hipModuleLoad, Tensile reads and processes all of the architectures found in the TensileLibrary file (unless only a single architecture is built).
To reduce the time to load the library file, I've added a separate-architectures option that writes each architecture into a different TensileLibrary_gfxXXX.dat file. This has been tested and works with TensileCreateLibrary and rocBLAS (pending some modifications to use the option).
Some of this functionality is similar to the PackageLibrary option which I notice hasn't been updated in a while and is listed for possible deprecation. When using the PackageLibrary option, TensileCreateLibrary fails to build. I've put my changes alongside this option, although some of the functionality is the same.
