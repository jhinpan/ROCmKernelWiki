# Custom kernel alternative to replacement kernels

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1302](https://github.com/ROCm/Tensile/pull/1302) · **Merged:** 2021-05-03 · **Author:** @JeremyAdamHart

**Inclusion reason:** kernel path 'Tensile/BenchmarkProblems.py'; keyword 'gemm'

## Summary (from upstream PR description)

I've left the Replacement Kernel system intact and introduced a new alternative which should allow for an easier introduction of user specified kernels (Hopefully allowing for replacement kernels to be deprecated at some point). Part of the reason for this is due to the fact that in this system the custom kernels aren't "replacing" anything, and the name replacement kernel is misleading.
Benchmarking
Custom kernels are benchmarked alongside conventionally generated kernels within its BenchmarkProblemSizeGroup. To include a custom kernel, list its name (Without file extension) under the "CustomKernels" category. During the benchmarking process, it will find the assembly kernel with this name (within the CustomKernels directory by default), and use it directly -- bypassing kernel generation. Beyond this, it is treated exactly like a normal kernel.
Example config file:
  - # sgemm NN
    - # ProblemType
      OperationType: GEMM
      DataType: s
      TransposeA: False
      TransposeB: False
      UseBeta: True
      Batched: True

    - # BenchmarkProblemSizeGroup
      CustomKernels: ["TestKernel"]
      InitialSolutionParameters:
      BenchmarkCommonParameters:
        - KernelL
