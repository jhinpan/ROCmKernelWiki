# Tuning automation fixes and improvements

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1258](https://github.com/ROCm/Tensile/pull/1258) · **Merged:** 2021-02-05 · **Author:** @benjaminulmer

**Inclusion reason:** keyword 'gemm'

## Summary (from upstream PR description)

This PR is part of an effort to better automate the Tensile tuning process, and is the beginning of the first step of that process: cleaning up and fixing the current automation scripts and tools.
Improved automation workflow:

Can now use existing local copies of Tensile and rocBLAS for tuning

This is especially important for rocBLAS, as previously, each tuning exercise would build its own copy


The Tensile directory (whether provisioned or provided) is no longer polluted with files for the tuning exercise
All scripts use the same working/output directory. This reduces the number of arguments that must be provided to scripts and ensures all outputs and artifacts from Tuning are contained in one directory

General script improvements:

.sh scripts should now be robust to paths with spaces
Other safety fixes, such as exiting after failed directory changes
Removed unused arguments and other dead code
Removed “stroolean” (strings representing boolean) variables from Python tools

Script interface changes:

Required arguments now passed in positionally
Ability to force redoing previously done steps. This allows iterating on a Tuning exercise in the same working directory

Bug fixes:
