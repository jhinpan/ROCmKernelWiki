## Summary (from upstream PR description)

The two-tier solution selection proposal
Currently, the solution selection logic for handling exact size matches and the selection logic for non-exact matches (sometimes called known and unknown sizes, respectively) are not independent. That is, adding tuning results for a new size changes the distance matching table and consequently changes how unknown sizes get mapped to solutions. This interdependence means special workarounds are necessary if a kernel should only be used for the exact size match and not participate in general solution selection for unknown sizes. Furthermore, recent experiments show that we can get better performance, on average, for unknown sizes by using different distance tables for unknown sizes or other methods all together.
The proposed solution to both of these issues is to have two tiers of solutions selection: primary and fallback. The primary tier will handle exact size matches and operates almost identically to the current distance based solution selection---the only difference being it will only return exact matches.
