# Refactor runtime contraction input type checks

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1144](https://github.com/ROCm/Tensile/pull/1144) · **Merged:** 2020-08-27 · **Author:** @cgmillette

**Inclusion reason:** kernel path 'HostLibraryTests/hip/RunGEMMKernel_test.cpp'; keyword 'gemm'

## Summary (from upstream PR description)

Currently contraction input types as determined from runtime inputs use a cascading branching structure e.g.  if (typeA == A && typeB == B && typeC == C && typeD ==D && typeAlpha == alpha && typeBeta == beta)... else if (typeA ==  ....)...
Worst case scenario there are 6 * numCases comparisons, which grows unfeasibly as the support for more input cases increases.
We can reduce this to 1 single check by assembling a bit field and using it with a switch table and compile time meta-info.
DataType::Count is small enough to allow us to combine enums for AType, BType, CType, DType, AlphaType and BetaType into a single 32 bit bitfield, with no collisions.
This can help reduce a lot of pressure on CPU branch prediction and stands to improve performance in this area.
Added more aliases to commonly used TypedContractionInputs. Helps to improve readability and reduce error prone repetitive template instantiations.
