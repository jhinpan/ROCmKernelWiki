# Client, Transform the data type of sources to the type of Accumulator when doing the multiplication.

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1393](https://github.com/ROCm/Tensile/pull/1393) · **Merged:** 2021-08-19 · **Author:** @vin-huang

**Inclusion reason:** kernel path 'Tensile/Source/client/source/Reference.cpp'; keyword 'kernel'

## Summary (from upstream PR description)

At the Client, cast the Data/DestData/ComputeDataType to the type of Accumulator before doing the multiply op when the highPrecisionAccumulate is true.
Exception: I8/I32/I32, I8x4/I32/I32, B/B/S + !HPA
Issue:
For cases H/H/H + HPA, H/H/S + HPA, H/S/S+ HPA,  B/B/S + HPA, B/S/S+ HPA,
When Client is calculating the rC=A*B and D = Alpha * (rC) + Beta * C.
The type of A, B, Beta, and Alpha are not casting to the higher precision data type even HPA is enabled.
This may cause the result value which precision not as expected (expected same as the HIP/ASM kernel)
Solution:
Transform the data type of A/B to Accumulator if A!=ACC or B!=ACC, but filter out cases, I8/I32/I32 and I8x4/I32/I32
Implementation:
Three cases need to check the need_trasnform

AxB
alpha x rC
Beta x C

The idea here is whether these two input types are consistent or not; if not, then needs to do the type transform.
Also, we need to filter out cases when A=i8 or A=i8x4
Here are conditions to do the transformation

AxB : (A!=ACC or B!=ACC) and A!=I8 and A!=I8x4
Alpha x rC : (Alpha!=ACC or rC!=ACC)
Beta x C : (Beta!=ACC or C!=ACC

And here is the result of doing the transformation or not, the expected need cast is the same
