# Solution selection selection

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1526](https://github.com/ROCm/Tensile/pull/1526) · **Merged:** 2022-06-10 · **Author:** @nielenventer

**Inclusion reason:** kernel path 'Tensile/Source/lib/include/Tensile/ContractionProblem.hpp'

## Summary (from upstream PR description)

Currently in Tensile there is a mechanism to select libraries benchmarked using device efficiency or using per CU efficiency, at runtime. This change makes this selection more generic so we can use it to test alternative solution selection strategies e.g. the ML based approach proposed by Bill, or Henry's distance metric.
The "Experimental" option is added as a catch-all option for any experiments we want to try (or allow other users to try).
The "DeviceEfficiency" and "CUEfficiency" options are preserved for the sake of compatibility, although ideally I think we'd like to deprecate them for the sake of simplifying the user experience. If one or the other are better for a use-case, we should make that decision and the selection should happen under the hood.
