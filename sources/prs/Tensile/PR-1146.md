## Summary (from upstream PR description)

(Updated 11 Nov 2020: rebased & moved to independent Jenkins pipeline)
The patch introduces integration test to ensure (to an extent) that TensileCreateLibrary, with its various build options, does not regress when invoked on up-to-date rocBLAS logic yamls.

Logic yamls are pulled from public rocBLAS Git repo. To make tests quick, only selected archs (gfx900/906/908) and selected problems (SGEMM/HGEMM/BF16-GEMM) are built
TensileCreateLibrary is tested with different build options: --[no-]merge-files, [--no-legacy-components], --library-format [yaml or msgpack], --[no]-short-file-names
For each of the above build combinations, a Tensile client will run a few problems (up to 16 for each type) sampled from the logic yaml to make sure the build artifacts' integrity

Known fail cases that've been marked xfail:

--library-format msgpack: Tensile client segfaults when loading up the library
--short-file-name: Can be reproduced by setting global parameter ShortNames = True

Misc:

Enables benchmarking tuned solution with new client by defining LibraryClient: in config yaml
