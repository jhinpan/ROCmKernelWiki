# Tensile cluster tuning tool

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1246](https://github.com/ROCm/Tensile/pull/1246) · **Merged:** 2021-01-07 · **Author:** @cgmillette

**Inclusion reason:** kernel path 'Tensile/BenchmarkSplitter.py'; keyword 'lds'

## Summary (from upstream PR description)

TensileBenchmarkCluster classes
Motivation: Tensile tuning on a single machine can take a very long time. We can split it up between machines, but managing this overhead is tedious and manual. Cluster management systems such as SLURM can take care of the overhead for us, so we need a tool to help us communicate with the cluster.
Workflow:

Split benchmark config into smaller 'task' sized units. For now 'task size' is defined as a subset of the 'ProblemSizes' section for each benchmark group. (Init)
Generate binary executables that the cluster will invoke for each task. (Deploy)
Submit all tasks to cluster. (Run)
Combine all the resulting logic files from each task into the final logic file. (Results)

TensileBenchmarkCluster script facilitates benchmark splitting and result logic merging (Init and Results), while delegating generation of benchmarking executables and task submission to the cluster backend class (Deploy and Run).
For Tensile we use a SLURM cluster, so the backend class BenchmarkImplSLURM is provided as a default:

Builds a docker image with the tensile_client executable and run script as the docker target. (Deploy)
Creates bash scripts that will load the docker image
