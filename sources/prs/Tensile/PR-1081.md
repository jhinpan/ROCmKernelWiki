# Benchmark tuning parts

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1081](https://github.com/ROCm/Tensile/pull/1081) · **Merged:** 2020-09-08 · **Author:** @wbgilmartin

**Inclusion reason:** kernel path 'Tensile/BenchmarkProblems.py'; keyword 'kernel'

## Summary (from upstream PR description)

updates to tensile to support a modular based approach to tuning using separates steps in the tuning process and provides functions (api's) which enable these steps.
Step one is the creation of the tensile client.
Step two is the creation of a tensile library which includes the solutions which are used for bench-marking.
Step three runs the actual bench-marks using the which are inputs to the api.
The set of solutions is defined by a configuration. Here I striped down the generation of the solutions based on how we do the tuning in practice, this only includes the common and forked parameters.
The unit and pre_checking tests pass on my local machine.
