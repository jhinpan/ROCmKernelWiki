# Have separate-architectures flag include hip solutions

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1480](https://github.com/ROCm/Tensile/pull/1480) · **Merged:** 2022-03-18 · **Author:** @JeremyAdamHart

**Inclusion reason:** kernel path 'Tensile/TensileCreateLibrary.py'; keyword 'kernel'

## Summary (from upstream PR description)

rocBLAS was seeing test failures when trying to use the separate-architectures flag from PR #1477 due to hip solutions not being included in the architecture specific TensileLibrary files. This PR makes two changes to fix this:

Adds hip solutions to each architecture file
Remove reindexing (which ensured each solution in a TensileLibrary file had a distinct index from solutions in other TensileLibrary files) The first change results in duplication of the hip solutions for each .dat file. There are a total of 707 hip kernels per architecture, compared to 40,000 kernels in total. The second change was originally intended for easy dynamic c++ library merging at runtime, however that code was cut from PR #1477, and at this point it introduces more risk of error, while not helping any current functionality. I think it would be worthwhile for me to revisit these changes after the release to create a separate TensileLibrary_hip.dat file with all of the hip solutions in it, and then reintroduce the reindexing and dynamic merging code when we have more time to confirm it's working correctly.
