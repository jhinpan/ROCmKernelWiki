# Refactor kernel source and header creation

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#2017](https://github.com/ROCm/Tensile/pull/2017) · **Merged:** 2024-09-24 · **Author:** @bstefanuk

**Inclusion reason:** kernel path 'Tensile/Parallel.py'; keyword 'kernel'

## Summary (from upstream PR description)

Summary:
buildKernelSourceAndHeaderFiles in TensileCreateLibrary is a large function that has multiple responsibilities. This PR aims to refactor logic into single-responsibility functions, improve the clarity of the code, and add unit tests.
Outcomes:

buildKernelSourceAndHeaderFiles renamed to generateKernelSourceAndHeaderFiles.
Logic related to the control of which files should be generated has been moved into its own function: collectFilesToWrite.
The renamed generateKernelSourceAndHeaderFiles is now parameterized only by the kernel lookup (hash) table returned by collectFilesToWrite.
The combined usage of the two new functions is identical in behaviour to the previous function -- confirmed via unittests that were written before the refactor.

Testing and Environment:

collectFilesToWrite is only tested end-to-end within larger tests, which matches the existing behaviour of buildKernelSourceAndHeaderFiles.
Standard unit testing suite, static analysis, and TensileManifest.txt consistency before and after change.
Environment: ROCm 6.3, Ubuntu 22.04
