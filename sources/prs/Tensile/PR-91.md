# v3.0.0 improving benchmarking thoroughness

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#91](https://github.com/ROCm/Tensile/pull/91) · **Merged:** 2017-05-10 · **Author:** @guacamoleo

**Inclusion reason:** kernel path 'Tensile/BenchmarkProblems.py'; keyword 'gemm'

## Summary (from upstream PR description)

Benchmarking can now specify multiple problem-size-groups, this will handle 4kB stride issues.
It can now also specify multiple problem-size-ranges during final benchmarking phase; this will allow for tuning for a list of specific sizes.
Unfortunately the 2nd improvement is implemented in such a way that it compiles and runs multiple executables, but the implementation required many fewer code changes than one executable that operates on many problem sizes.
API now supports multiple devices/schedules, getting the string name of the solution being enqueued, and getting a function pointer rather than enqueueing.
