# Optimize MessagePackLoadLibraryFile

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1471](https://github.com/ROCm/Tensile/pull/1471) · **Merged:** 2022-02-23 · **Author:** @cgmb

**Inclusion reason:** kernel path 'Tensile/Source/lib/source/msgpack/MessagePack.cpp'

## Summary (from upstream PR description)

This change provides a 13% reduction in the time spent in MessagePackLoadLibraryFile. Most of this optimization comes from changing how the file is read. The construct
std::vector<uint8_t> data((std::istreambuf_iterator<char>(in)),
                          std::istreambuf_iterator<char>());
is--from a performance perspective--the worst commonly used way to read a whole file into memory in C++ (see benchmarks). It is an order of magnitude slower than a call to fread. Simply replacing that call with a naive C function to read the whole file provides a ~10% overall speedup in MessagePackLoadLibraryFile.
As an additional optimization, the msgpack streaming API can be used to parse the data in chunks. Interleaving the file reads with parsing allows the OS prefetcher some time to cache the next chunk while the CPU does useful parsing work. I didn't carefully tune the chunk size, but 512 KiB worked well on my machine.
