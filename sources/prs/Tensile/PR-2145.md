# Update treatment of msgpack in cmake support

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#2145](https://github.com/ROCm/Tensile/pull/2145) · **Merged:** 2025-06-07 · **Author:** @davidd-amd

**Inclusion reason:** kernel path 'Tensile/Source/lib/CMakeLists.txt'

## Summary (from upstream PR description)

Summary:
Tensile has a build time dependency on msgpack. In particular, Tensile depends on the msgpack header files to build. When consuming msgpack in the current build system we link a version specific target:
- msgpackc <= v5

msgpack-cxx > v5

msgpack-cxx is an interface target and provides paths to msgpack header files. Whereas, msgpackc is shared library target. As a consequence, this introduces an unnecessary dependency on libmsgpack.so. Ideally, we don't link libraries that we do not require. More importantly, in some of our test environments, libmsgpack.so is propagated to librocblas as a runtime dependency and fails because libmsgpack.so cannot be found:
error while loading shared libraries: libmsgpackc.so.2: cannot open shared object file: No such file or directory

In this patch, we set the msgpack target depending on if:

v6 or greater is detected
v5 or older is detected

We then query the msgpack target for the INTERFACE_INCLUDE_DIRECTORIES and add these directories as a build requirement for the tensile host target. The goal of using the INTERFACE_INCLUDE_DIRECTORIES directly is to future proof against future changes in msgpack that might reintroduce a runtime depend
