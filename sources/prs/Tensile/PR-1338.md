# Add OpenCL backend solution adaptor

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1338](https://github.com/ROCm/Tensile/pull/1338) · **Merged:** 2021-05-13 · **Author:** @cgmillette

**Inclusion reason:** kernel path 'HostLibraryTests/KernelArguments_test.cpp'; keyword 'gemm'

## Summary (from upstream PR description)

Add const_iterator object to KernelArguments to facilitate argument loading for openCL
Add run-time check for 'argument logging' in KernelArguments when const_iterator is used (required)
Add Solution Adapter object to load, launch and profile kernels in OpenCL environment.
Add tests for new Solution Adapter
Add cmake project option TENSILE_USE_OPENCL for using opencl
Add tests to ensure HIP and openCL based solution adapters can be used at the same time
Add OclAMDGPU object with query for minimal device properties, with tests comparing to HipAMDGPU

Tests:
RunGEMMKernelTests currently only uses the HIP device backend for setting up and running kernel tests.
Due to demand for an OpenCL backend, the test code needs to be a bit more flexible to be able to use OpenCL device backend.

Add a layer of abstraction "DeviceBackend" to handle resource and device management, with an interface to populate contraction inputs, solve contraction problems and invoke kernels.
