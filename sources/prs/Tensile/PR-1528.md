# Tensile lazy library loading

**Repository:** [ROCm/Tensile](https://github.com/ROCm/Tensile) · **PR:** [#1528](https://github.com/ROCm/Tensile/pull/1528) · **Merged:** 2022-06-22 · **Author:** @JeremyAdamHart

**Inclusion reason:** kernel path 'HostLibraryTests/llvm/KernelLanguagePredicate_test.cpp'; keyword 'kernel'

## Summary (from upstream PR description)

Introduces build option for loading the TensileLibrary.dat/yaml and code object files lazily at runtime to speed up initialization.
Overview of changes

PlaceholderLibrary introduced to the TensileLibrary hierarchy. Any libraries following it in the library order will be placed in a separate file (along with any solutions)

When the TensileLibrary.dat/yaml file is loaded this class will initially have an empty pointer to its sub-library. The first time that findBestSolution attempts to use that library it will load the file containing the remaining stages of the library hierarchy.
Currently this is placed towards the end of the library order and will contain all solutions matching a given transpose and datatype combination
LoadLibraryFile has a new argument that allows for files corresponding to a specific datatype to be loaded in the initial call, instead of when findBestSolution is called


The code object files have been separated in a similar fashion as the TensileLibrary.dat/yaml files. The name of the file is the same, but with the extension ".co" or ".hsaco" (sometimes with xnack+/- included)

The required code object file is included as a field of the ContractionSolution cl
