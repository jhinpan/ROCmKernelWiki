# Improve XDL to WMMA porting for grouped conv fwd

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3456](https://github.com/ROCm/composable_kernel/pull/3456) · **Merged:** 2025-12-19 · **Author:** @bartekxk

**Inclusion reason:** kernel path 'include/ck/tensor_operation/gpu/device/impl/device_batched_gemm_gemm_xdl_cshuffle.hpp'; keyword 'wmma'

## Summary (from upstream PR description)

Proposed changes
This pull request refactors the way the number of XDL (matrix multiply-accumulate) instructions per wave is calculated and used in the grouped convolution forward implementations, especially to better support WMMA (Wave Matrix Multiply-Accumulate) instructions and 16x16 tiles. The changes  use of MXdlPerWave instead of NXdlPerWave to increase number of waves per M dim.
Key changes include:
Refactoring and Standardization of XDL Per Wave Calculation:


Replaced the GetNXdlPerWave and GET_NXDL_PER_WAVE_IMPL macros with GetMXdlPerWave and GET_MXDL_PER_WAVE_IMPL, and updated all related usage to use MXdlPerWave instead of NXdlPerWave for both 32- and 64-thread warps. This also enforces the use of 16x16 instructions for WMMA [1] [2] [3] [4] [5].


Updated template parameters and macro expansions in grouped convolution and GEMM kernel definitions to use the new MXdlPerWave approach, including correct propagation of tile sizes for WMMA [1] [2] [3] [4].


Updates to Kernel and GridwiseGemm Instantiations:


Changed the instantiation of GridwiseGemm types to use the new MXdlPerWave and tile size parameters, ensuring correct behavior for both standard and WMMA ported kernels
