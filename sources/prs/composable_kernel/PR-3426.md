# ck:tf32:complement CK_ENABLE_TF32 controls

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3426](https://github.com/ROCm/composable_kernel/pull/3426) · **Merged:** 2025-12-19 · **Author:** @yingluAMD

**Inclusion reason:** kernel path 'library/include/ck/library/tensor_operation_instance/gpu/grouped_convolution_backward_data_xdl.inc'; keyword 'gfx942'

## Summary (from upstream PR description)

Proposed changes

Remove target control ( __gfx942__  & __gfx950__ )in config.h.in because this is for user side which is CPU code.
Complement all the functions controlled via CK_ENABLE_TF32.

Discussion
CK_ENABLE_xx is defined as "ON" in config.h.in and CMakeLists.txt. But in the library usage, it is used as #ifdef CK_ENABLE_xx which doesn't check its status.
Should we change all of those as status check to let user control whether to enable those macros? Eg: Use #if CK_ENABLE_xx == 1 control whether involve these functions.
