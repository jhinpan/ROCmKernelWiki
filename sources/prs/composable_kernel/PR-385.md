# Padding for attention: bmm+scale+softmax+bmm kernel

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#385](https://github.com/ROCm/composable_kernel/pull/385) · **Merged:** 2022-08-30 · **Author:** @shaojiewang

**Inclusion reason:** kernel path 'example/32_batched_gemm_scale_softmax_gemm/CMakeLists.txt'; keyword 'gemm'

## Summary (from upstream PR description)

Padding for attention needs a proper padding value because of softmax computation policy.
This PR uses (-nan) as padding value of matrix A and matrix B0 and uses 0 as padding value of matrix B1.
After bmm0, we get Acc0=A*B0. Then in scale process, we do
if (!valueIsNan)
    Acc = Acc * scale;
else
    Acc = -infinity

When computing softmax, the (-infinity) values do not pollute the max number of line. And they will be ret to 0 because exp(-inifinity) = 0. So at bmm1, the values on padding  position of Acc0 matrix is set to 0.
Performance will drop because of MNPadding.
Test:
make example_padded_batched_gemm_scale_softmax_gemm_xdl_fp16 -j16
./bin/example_padded_batched_gemm_scale_softmax_gemm_xdl_fp16 1 1 1 1020 1020 64 64 4 -1 -1 -1 -1 -1 -1 -1 -1 1
