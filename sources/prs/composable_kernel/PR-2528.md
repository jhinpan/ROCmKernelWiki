# [CK_TILE] Support WMMA (gfx12) in FMHA

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2528](https://github.com/ROCm/composable_kernel/pull/2528) · **Merged:** 2025-10-29 · **Author:** @ex-rzr

**Inclusion reason:** kernel path 'example/ck_tile/01_fmha/CMakeLists.txt'; keyword 'mfma'

## Summary (from upstream PR description)

Proposed changes
Changes worth mentioning:

The split KV combine kernel is more universal now, it supports any power-of-2 number of warps, any number of splits and kN1 = 16, see e08a84d
Some of hardcoded values (M0 of the dot bwd kernel, N1 of the split KV combine kernel) are set based on tile size, N1 of the split KV combine kernel is ensured to be consistent with the split KV kernel.
Instances (tile size + pipeline) are checked for duplications and proper ordering of paddings (from non-padded to fully padded).
A workaround for a compiler bug (SWDEV-559729) in bwd kernels with padding.
WarpGemmDispatcher is used when possible instead of a concrete warp gemm implementation.
Some tile distributions are updated to support different tile sizes and warp size.
Initially this PR included a big change for supporting 16x16 warp tiles in BlockDropout, they were merged to develop as a part of #2836.

The main change is about supporting different architectures in one binary (for example, tests and examples) without a need to compile separate binaries for WMMA+warpsize32 and MFMA+warpsize64.
I extended the KernelComponentFactory mechanism, already existing in fwd, now all APIs work in this way
