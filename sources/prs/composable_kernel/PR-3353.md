# [CK_TILE] Add splitk support to ck tile conv bwd data

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3353](https://github.com/ROCm/composable_kernel/pull/3353) · **Merged:** 2025-12-23 · **Author:** @jakpiase

**Inclusion reason:** kernel path 'include/ck_tile/ops/grouped_convolution/kernel/grouped_convolution_backward_data_kernel.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

This PR adds support for splitk > 1  values into conv bwd data kernel. Now conv bwd data kernel supports both splitting among N in case of too large tensors and splitting among K. I have tested perf on some cases and the mean boost was around ~5%. Splitk is handled mostly by tensor descriptors and we are not using tensor offsets(that's how GEMM splitk is implemented), so we don't have to worry about memory violations since descriptors use paddings if we try to access an element that is out of tensor.
