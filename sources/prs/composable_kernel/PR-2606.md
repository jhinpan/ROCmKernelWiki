# [CK] Extend XDL kernel to support RDNA3/4 (option 2)

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2606](https://github.com/ROCm/composable_kernel/pull/2606) · **Merged:** 2025-08-22 · **Author:** @linqun

**Inclusion reason:** kernel path 'include/ck/tensor_operation/gpu/block/blockwise_gemm_pipeline_xdlops_base.hpp'; keyword 'mfma'

## Summary (from upstream PR description)

Proposed changes
Problem:
CK contains a lot of well-designed XDL kernel, it is limited on MI cards, CK also have some WMMA kernel for RDNA3/RDNA4, but the supporting is much less XDL kernel.
Consider RDNA3/RDNA4 are more and more used in ML, and our future HW architecture will close to RDNA too, we need improve the support of WMMA kernel.
After compare the WMMA kernel with XDL kernel, it looks the architecture and algorithm is almost same between them. The major differences are:

XDL kernel based MfmaSelector + Mfma instruction, which doesn't support any WMMA instructions
XDL kernel assume warp size is constant and it fixed to 64.

Template parameter BlockSize, MPerBlock, NPerBlock, MPerXDL, NPerXDL, MXdlPerWave and NXdlPerWave causes warp size is hard code to 64
WaveSize is widely used as static constexpr variable, and hardcode to 64.



Proposal:

To reduce the efforts of code maintain, I think it is better to extend exist XDL kernel to support both XDL and WMMA, instead of duplicate XDL kernel to WMMA kernel.
To eliminate the difference between WMMA and XDL (MFMA), I think we can


Extend  MfmaSelector + Mfma instruction to support all WMMA instruction.
Ignore NXdlPerWave in dev
