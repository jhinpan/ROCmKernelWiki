# Fix a bug in the non-PrefillCase path of  qr_ks_vs_async_trload pipeline

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3271](https://github.com/ROCm/composable_kernel/pull/3271) · **Merged:** 2025-11-24 · **Author:** @qianfengz

**Inclusion reason:** kernel path 'include/ck_tile/ops/fmha/kernel/fmha_fwd_kernel.hpp'; keyword 'attention'

## Summary (from upstream PR description)

The bug leads to approximately 12 failed cases when running the ROCm/xformers branch develop_upgrade (which updated the ck to latest commits).   The reason is that the code-line
static constexpr bool kKLoadOnce = BlockFmhaShape::kM0 >= 64;  will let the k_dram_view creation codes in
constexpr auto kDramTileK = to choose tile_size kQKHeaddim rather than kK0,  inconsistent with the tile size used in MakeKLdsBlockDescriptor()
To reproduce the issue
#>  git clone -b develop_upgrade  https://github.com/ROCm/xformers
#>  git submodule update --init --recursive                                // using the latest ck develop branch
#>  pip install --no-build-isolation -e ./
#>  pytest tests/test_mem_eff_attention.py::test_forward -k "not triton"
To verify the fixing
#>  cd/third_party/composable_kernel_tiled
change  the ck  branch from ck develop to  fix_qr_ks_vs_async_trload  and do the same xformers building the testing
