# Refactor block to C tile map

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#235](https://github.com/ROCm/composable_kernel/pull/235) · **Merged:** 2022-05-20 · **Author:** @rosenrodt

**Inclusion reason:** kernel path 'include/ck/tensor_operation/gpu/device/device_batched_gemm_reduce_xdl_cshuffle.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

The patch is for easier integration of upcoming Block2CTileMap variant that have been shown in Tensile to be beneficial to global memory access. This PR has no functionality changes so it should be easier to do PR review.

GridwiseGemm implementations use one of the 2 following BlockToCTileMap's

BlockToCTileMap_M00_N00_M01_N01 for gemm and batched gemm
BlockToCTileMap_KSplit_M00_N00_M01_N01 for split-k
One more BlockToCTileMap to come


Generic GridwiseGemm::CheckValidity that doesn't couple with any particular BlockToCTileMap variables (eg M01, N01)
DeviceCTileIndexCheck=true can relax the host side validity check, by shifting the burden to device side kernel
To simplify CalculateGridSize() implementation, batched gemm kernel uses gridDim.z to embed batch count instead of explicitly passing it as kernel argument removed according to feedback
