# [CK] Allow tensors larger than 2GB in grouped conv bwd weight

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3169](https://github.com/ROCm/composable_kernel/pull/3169) · **Merged:** 2026-01-08 · **Author:** @johannes-graner

**Inclusion reason:** kernel path 'include/ck/tensor_operation/gpu/grid/gridwise_gemm_xdl_cshuffle_conv_v3.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
Due to the limit of using 32-bit pointers for memory addresses, a 2GB tensor limit was in place for backward weight convolutions. This PR implements a circumvention of that problem, enabling larger tensors.
Instead of directly addressing memory for each split-k batch (e.g. 0-15 for split-k 1, 16-31 for split-k 2), we instead use offsets that "reset" the pointer to 0 for each batch (0+0-15 for split-k 1, 16+0-15 for split-k 2). This ensures that the pointer arithmetic does not overflow, and allows us to change the limit from 2GB per tensor to 2GB per split-k batch, in practice removing the limit on tensor size.
This change is sensitive, and there is a number of conditions which must be fulfilled in order to enable this workaround, all such checks are implemented. To verify, the full dataset in test_data has been generated and run through with this change, and all relevant test cases pass (cases where both output and reference show infinite values are ignored since they occur due to small data types such as fp16, and are not influenced by this change).
