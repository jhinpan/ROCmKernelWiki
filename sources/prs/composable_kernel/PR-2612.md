# Implement batched gemm gemm for RDNA (3 and 4)

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2612](https://github.com/ROCm/composable_kernel/pull/2612) · **Merged:** 2025-09-04 · **Author:** @krithalith

**Inclusion reason:** kernel path 'example/31_batched_gemm_gemm/CMakeLists.txt'; keyword 'wmma'

## Summary (from upstream PR description)

Proposed changes
I added a batched gemm gemm operation for RDNA 3 / 4, with the same functionality as the existing batched gemm gemm xdl. I added a new device struct and gridwise struct, which are similar to the XDL one and also to batched gemm softmax gemm permute wmma, which already existed and uses the older wmma backend.
The new gridwise struct makes use of the new blockwise wmma pipelines (v1 / v3, inter / intra wave) for the first gemm. The second gemm still uses an old blockwise wmma struct. The reason for this is that the new blockwise pipelines are actual pipelines, i.e. they handle an entire big K loop with prefetching etc. This is not relevant for gemm1, which is performed one "big K" iteration at a time, in a custom explicit loop which calls a full gemm0 pipeline for each gemm1 K.
The new device operation supports fp16, bf16, fp8, and int8. It supports padding modes default (none), and MNKO. It supports RCRR and RCCR layouts. It supports the v1 and v3 pipelines. It support intrawave and interwave scheduling.
I added a large number of instances to the library, tests for fp16 and bf16, and examples for all data types.
I found two latent issues in the wmma v3 blockwise pip
