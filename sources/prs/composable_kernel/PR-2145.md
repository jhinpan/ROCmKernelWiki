# Stream-K Reduction option as Runtime parameter and Compilation Error Fix (SK- Reduction)

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2145](https://github.com/ROCm/composable_kernel/pull/2145) · **Merged:** 2025-06-11 · **Author:** @ozturkosu

**Inclusion reason:** kernel path 'example/01_gemm/common.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
Previously, the Stream-K reduction value was hardcoded as a compile-time template parameter (as atomic).

 It has now been refactored to be configurable at runtime as follows

./example_gemm_xdl_fp16_streamk_v3 -h
arg1: verification (0=no, 1=CPU, 2=GPU, 3=CPU and GPU)
arg2: initialization (0=no init, 1=integer value, 2=decimal value)
arg3: time kernel (0=no, 1=yes)
arg4 to 9: M (256x), N(128x), K(32x), StrideA, StrideB, StrideC
arg10: stream-k select (-1: default config, 0: all DP, 1: 1-tile SK, 2: 2-tile SK)
arg11: Grid_size(-1 for max occupancy)
arg12: Reduction strategy (0: Atomic, 1: Reduction)
Reduction option is experimental !!!

 After reduction option is provided, we encountered compilation error due to type convertion in dynamicbuffer for bf16 & fp8 data type. This PR also address this problem and fix it.
