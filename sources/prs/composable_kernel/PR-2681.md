# [CK Tile] Stream K GEMM Kernel HostArgs and Kernel Classes

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2681](https://github.com/ROCm/composable_kernel/pull/2681) · **Merged:** 2025-08-19 · **Author:** @ecamartins

**Inclusion reason:** kernel path 'include/ck_tile/ops/gemm.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
As part of initial steps to integrate Stream K into CK Tile, this PR adds a two new classes: 1) StreamKHostArgs and 2) StreamKKernel. Similarly, to other CK Tile GEMM kernels, the StreamKKernel injects the UniversalGemmKernel to add necessary functionality for GEMM.
We are basing our initial Stream K implementation off old CK's example/01_gemm/gemm_xdl_streamk.cpp. Thus, we will be basing our TilePartitioner (coming in a future PR) off BlockToCTileMap_GemmStreamK in include/ck/tensor_operation/gpu/grid/block_to_ctile_map.hpp.
Similarly to Stream K in old CK, an instance of the TilePartitioner class is a kernel argument. The reason for this is because, for Stream K, old CK's BlockToCTileMap_GemmStreamK must be instantiated to determine important member variables like sk_num_blocks and reduction_start_block_idx which are required to determine the appropriate grid size and workspace buffer size. In other words, while the existing tile partitioners in CK Tile contain mostly static functions, this is not the case for Stream K's tile partitioner as most information is instance-specific.
