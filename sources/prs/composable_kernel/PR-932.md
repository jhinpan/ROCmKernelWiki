# Refactoring cmake files to build data types separately.

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#932](https://github.com/ROCm/composable_kernel/pull/932) · **Merged:** 2023-09-21 · **Author:** @illsilin

**Inclusion reason:** kernel path 'example/01_gemm/CMakeLists.txt'; keyword 'gemm'

## Summary (from upstream PR description)

This change will move the filtering to build different data types separately from the individual cmake files into just a few functions in the main cmake files for examples, tests, and instances folders.
Instead of using the exclusive logic, where instances only get built if they do not contain any other types than the selected ones, the new logic will be inclusive, i.e., we will build all instances in case any of the types match any of the selected ones. E.g., to build gemm_fp8_fp16 it would be enough to enable either fp16 or fp8, not necessarily both.
