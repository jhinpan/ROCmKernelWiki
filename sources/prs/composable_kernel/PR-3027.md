# Wave Tile Transfer supporting global load with transpose

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3027](https://github.com/ROCm/composable_kernel/pull/3027) · **Merged:** 2025-10-16 · **Author:** @EnricoDeg

**Inclusion reason:** kernel path 'example/01_gemm/gemm_wmma_fp16_v3.cpp'; keyword 'wmma'

## Summary (from upstream PR description)

Proposed changes
Summary:

new thread group transfer ThreadGroupTransferGlobal which supports transpose load. In case no transpose is needed, buffer loads are used because they are faster than global loads.
Refactor AB transfer in ABTransferThreadTiles. It removes about 50% of code duplication for A and B matrices and it allows to support different methods for AB transfer by defining new structs with same internal API.
ABTransferWaveTiles new struct which can be used instead of ABTransferThreadTiles supporting new method:

grid descriptor is defined in terms of wave tiles. Each lane in a wave loads 8 elements with buffer load or global load with transpose
in the struct the wave distribution for loading from gmem are defined
block descriptor defines block layout. Elements in a wave are stored contiguously with chunk of 8 elements and the waves are then stored first in the K dimension. This allows to have a better LDS access
wmma tile descriptor is defined in such a way to avoid any change to the pipelines, using the new block layout.


Improvement of pipeline v1 (less registers and instructions ordering)
