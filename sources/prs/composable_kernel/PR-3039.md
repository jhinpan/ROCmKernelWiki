# [CK_TILE] Fix Stream-K Validation Errors on gfx950 for BF16

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3039](https://github.com/ROCm/composable_kernel/pull/3039) · **Merged:** 2025-10-17 · **Author:** @ecamartins

**Inclusion reason:** kernel path 'example/ck_tile/40_streamk_gemm/run_gemm_example.inc'; keyword 'gemm'

## Summary (from upstream PR description)

Stream-K smoke tests were added in PR #2974. When computing the relative and absolute tolerance, the k_batch corresponding to the number of accumulations performed in a given macro tile in C was set to 1. However, in various Stream-K test cases, there are multiple workgroups atomically adding to the same macro tile in C; in these cases, the computed relative and absolute tolerance based on k_batch of 1 is too small, leading to validation errors and failed test cases, specifically on gfx950 for bf16.
To fix this issue, we estimate the number of accumulations using the instance of the Stream-K tile partitioner; we then use this estimate to compute the relative and absolute tolerance that is more accurate for problem instances with more than one workgroup contributing to the same macro tile in C.
Note: Locally on gfx950, I have run these tests in a loop 150 times for 3 repetitions. All tests pass locally.
