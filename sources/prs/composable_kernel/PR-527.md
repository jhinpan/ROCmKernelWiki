# Make sure that GEMM sizes in K dimension are supported.

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#527](https://github.com/ROCm/composable_kernel/pull/527) · **Merged:** 2022-12-08 · **Author:** @illsilin

**Inclusion reason:** kernel path 'include/ck/tensor_operation/gpu/device/impl/device_batched_gemm_xdl.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

This is an additional check to catch the exception handled by asserts in develop mode when running a release build.
With this fix calls like "./bin/ckProfiler gemm 1 3 1 2 0 0 128 128 133 -1 -1 -1" will no longer produce wrong results and instead every kernel will issue an error message "does not support this problem".
I've also checked that other gemm sizes like
"./bin/ckProfiler gemm 1 3 1 2 0 0 128 133 128 -1 -1 -1"
or
"./bin/ckProfiler gemm 1 3 1 2 0 0 133 128 128 -1 -1 -1"
are also throwing the error. So no additional checks may be necessary.
