# Fix DL GEMM instances with too large vector size

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#901](https://github.com/ROCm/composable_kernel/pull/901) · **Merged:** 2023-09-18 · **Author:** @bwroblew

**Inclusion reason:** kernel path 'include/ck/tensor_operation/gpu/device/impl/device_gemm_dl.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

This PR changes the irregular DL GEMM instances to use vector size = 1 for either KM or KN layouts. It's necessary since we use padding for those instances and unpadded M, N dimensions might not be divisible by any larger vector size.
Before this change, the vector size was set to 4 what led to incorrect results for cases with M, N not divisible by 4.
This change also introduces a check in the IsSupported method of DL GEMM so such cases will be reported as unsupported in the future (instead of supported but giving incorrect results).
