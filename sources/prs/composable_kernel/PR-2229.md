# Convert CK (GeMM MulMul Weight Preshuffle) instances to use 16x16 xdl tile

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2229](https://github.com/ROCm/composable_kernel/pull/2229) · **Merged:** 2025-06-10 · **Author:** @tenpercent

**Inclusion reason:** kernel path 'library/include/ck/library/tensor_operation_instance/gpu/gemm_multiply_multiply_wp.hpp'; keyword 'mfma'

## Summary (from upstream PR description)

Proposed changes
Having a mix of 16x16 and 32x32 xdl tiles complicates storing the weights (a separate weight matrix copy is needed with preshuffle pattern differing per tile size, plus appropriate storage needs to be chosen at the execution time)
This PR reduces the tile size option to 16x16 only. The existing 32x32 instances are retained in a separate tuple which is not being added to the ckProfiler instance pool.
As a result, kernel run time fluctuates, in rare cases it improves, most often the best time reported by ckProfiler regresses within 10% of elapsed time (with instances using different threadblock tile sizes from the instances being modified).
One thing left to explore is whether adding more instances with different m/n xdl per tile can reduce the run time regression.
