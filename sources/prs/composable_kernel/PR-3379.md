# [CK] Integrate GPU reference into ckProfiler for convolutions

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3379](https://github.com/ROCm/composable_kernel/pull/3379) · **Merged:** 2025-12-18 · **Author:** @johannes-graner

**Inclusion reason:** kernel path 'example/09_convnd_fwd/run_convnd_fwd_example.inc'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
ckProfiler should be able to use GPU references for validation, this PR implements that for (grouped) convolutions.
The naive GPU reference kernels have been completely refactored in order to support grouped convolutions with arbitrary memory layout.
Tests have been implemented that ensure GPU reference is the same as CPU reference. These are not very extensive, but show that common cases work as expected. This includes multiple memory layouts and grouped convolutions.
One existing profiler-using test per direction have been changed to use the GPU reference. Since these tests were passing with CPU reference, they can be viewed as extra tests for the GPU reference during review.
Running the updated test_grouped_conv_fwd test with extra instrumentation in the profiler shows on average a ~500x speedup for creation of reference, and a ~6.5x total test time speedup. This test has time_kernel disabled in the profiler, so each real kernel is only run once. Many instances of real kernels are still run per reference creation.
