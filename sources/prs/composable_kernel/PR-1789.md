# [CK_TILE] fmha fwd splitkv optimization for decode (seqlen_q=1)

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#1789](https://github.com/ROCm/composable_kernel/pull/1789) · **Merged:** 2025-01-07 · **Author:** @poyenc

**Inclusion reason:** kernel path 'example/ck_tile/01_fmha/codegen/ops/fmha_fwd_splitkv.py'; keyword 'mfma'

## Summary (from upstream PR description)

Proposed changes
Using matrix-core is the usual method to speed-up computation for attention operation, even when the size of the query sequence is very small. Thus obvious wasting of computation often occurred with decoder fmha-fwd since seqlen_q == 1
For the decoder fmha-fwd, this PR tries to reduce the wasting of computation
by taking advantage of the very common situation of mqa and gqa where nhead_q is much bigger than nhead_kv.  When nhead_q is bigger, the implementation merges the nhead_q/nhead_kv size to seqlen_q so that one Gemm has at least nhead_q/nhead_kv size for GemmM, a big reduction of wasting for usually WarpGemm MFMA_16x16x16
The implemented optimization is only done with fmha fwd splitkv kernels (since decoder cases are handled by splitkv kernel). We only enable it for hdim=128 in codegen now to reduce compiling-time
Benchmark
Run following command on MI300X:
./bin/tile_example_fmha_fwd -prec=fp16 -mode=0 -b=64 -h=16 -h_k=4 -d=128 -s=1 -s_k=4096 \
  -lse=0 -iperm=1 -operm=1 -vlayout=r -num_splits=2 \
  -bias=n -p_drop=0.0 -warmup=5 -repeat=20 -kname=1
