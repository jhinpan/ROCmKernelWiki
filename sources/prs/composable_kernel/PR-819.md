# Update tuning parameter & compilation options of DeviceGemmXdl<> instance (layout=TT)

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#819](https://github.com/ROCm/composable_kernel/pull/819) · **Merged:** 2023-08-02 · **Author:** @poyenc

**Inclusion reason:** kernel path 'library/src/tensor_operation_instance/gpu/gemm/CMakeLists.txt'; keyword 'mfma'

## Summary (from upstream PR description)

Similar to #813, we are using less efficient thread-mapping for reading global memory. But we still can improve the kernel a bit more by altering tuning parameter & compilation options.
Jeffrey found that we can apply MFMASmallGemmSingleWaveOpt  and removing the LLVM option -amdgpu-enable-max-ilp-scheduling-strategy for the layout=TT instance without causing performance regression. And this is confirmed after I
updated the ABlockTransferThreadClusterLengths_K0_M_K1 from S<4, 64, 1> to S<8, 32, 1>.
The enhancement isn't noticeable because we still spend much time on reading B tiles. In order to solve this problem, we must seek a way to implement better thread-mapping into existing kernels.
