# [CK_TILE] Split-K autodeduction

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3351](https://github.com/ROCm/composable_kernel/pull/3351) · **Merged:** 2025-12-10 · **Author:** @vpietila-amd

## Summary (from upstream PR description)

Proposed changes
Add option to automatically deduce the best split-K value for grouped backward weight convolutions in CK Tile kernels. The same functionality was introduced for old CK in #2491. The logic is based on selecting split-K value $K_{\text{split}}$ such that the number workgroups is equal to the available theoretical capacity, i.e.,
$$\lambda_{\text{occupancy}}\times N_{\text{cu}} = M_{\text{tiles}} \times N_{\text{tiles}} \times N_{\text{batch}} \times K_{\text{split}}$$,
where $\lambda_{\text{occupancy}}$ is the maximum occupancy for the GEMM kernel that we can calculate with hipOccupancyMaxActiveBlocksPerMultiprocessor and $N_{\text{cu}}$ is the number of compute units. $M_{\text{tiles}}$ and $N_{\text{tiles}}$ are the number of output tiles for the GEMM $M$ and $N$ dimensions, and $N_{\text{batch}}$ is the number of GEMM batches.
The automatic deduction of the split-K value can be triggered by providing a negative split-K value.
