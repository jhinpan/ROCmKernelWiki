# [CK TILE] Support fp8/fp16 with pk_int4_t as data types for tensors A and B

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2805](https://github.com/ROCm/composable_kernel/pull/2805) · **Merged:** 2025-09-09 · **Author:** @CongMa13

**Inclusion reason:** kernel path 'example/ck_tile/03_gemm/gemm_utils.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
Problem solved in this PR
There is a group of conversion functions in include/ck_tile/ops/elementwise/unary_element_wise_operation.hpp that convert pk_int4_t to other types.
The issue is that these functions are not consistent with each other on


Bias of pk_int4_t
This function i4_to_half4 assumes pk_int4_t has a bias of 8, meaning 0b0000 is converted to fp16(-8). But amd_assembly_i4_to_fp8x8 assumes the bias is 0,  meaning 0b0000 is converted to fp8(0).


Order of output
For example, when input is packed int4 7, 3, 6, 2, 5, 1, 4, 0, the output sequence of i4_to_half4 will be fp16(7, 3, 6, 2, 5, 1, 4, 0). But output sequence of amd_assembly_i4_to_fp8x8 will be fp8(7, 6, 5, 4, 3, 2, 1, 0).


Need to make these conversion functions consistent with each other.
What are implemented

Add support for tensor A/B in both fp16+pk_int4_t and fp8+pk_int4_t formats
Implement A(bf8) B(i4) support in universal GEMM
Use new implementation for i4 to fp8 conversion in Block Scale

All use bias 8
All generate output 7, 3, 6, 2, 5, 1, 4, 0 from input 0x76543210
Call permute_vectors_i4x4_b on the tensor of pk_int4_t on host side, so the tensor will be shuffled in both host code and d
