# [CK_TILE] Support f32 in FMHA (fwd and bwd)

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2836](https://github.com/ROCm/composable_kernel/pull/2836) · **Merged:** 2025-09-27 · **Author:** @ex-rzr

**Inclusion reason:** kernel path 'example/ck_tile/01_fmha/codegen/cpp_symbol_map.py'; keyword 'mfma'

## Summary (from upstream PR description)

Proposed changes
This PR add support of fwd and bwd FMHA (splitkv, appendkv, pagedkv are not yet implemented).
This branch includes 2 cherry-picked commits from #2528 that enable support of 16x16 warp tiles in BlockDropout.
Since fp32 FMHA is not widely used, fp32 instances are not built by default.
They can be enabled by adding --receipt 800 example/ck_tile/01_fmha/CMakeLists.txt:
set(FMHA_FWD_CODE_GEN_COMMON_ARGS
  ${CMAKE_CURRENT_LIST_DIR}/generate.py
  --api ${FMHA_FWD_APIS}
  --receipt 800
  --optdim 32,48,64,128,256
  # --filter fmha_fwd...
)
set(FMHA_BWD_CODE_GEN_COMMON_ARGS
  ${CMAKE_CURRENT_LIST_DIR}/generate.py
  --api bwd
  --receipt 800
  --optdim 32,48,64,128,256
  # --filter fmha_bwd_dot...@fmha_bwd_convert...@fmha_bwd...
)
This also means that the tests must be run manually, not in CI.
I'm not sure whether building fp32 instance should be enabled by default, let me know if it should.
There is another receipt: --receipt 801, it builds a very small subset of instances.
When --receipt 800 or --receipt 801 are used, no other types (fp16, bf16, fp8) are built!
