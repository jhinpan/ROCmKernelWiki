# [CK_TILE] Enhance RMSNorm Accuracy: New Pipeline Pass for Selectable Implementation

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2409](https://github.com/ROCm/composable_kernel/pull/2409) · **Merged:** 2025-07-16 · **Author:** @MHYangAMD

**Inclusion reason:** kernel path 'example/ck_tile/10_rmsnorm2d/example_rmsnorm2d_fwd.cpp'; keyword 'kernel'

## Summary (from upstream PR description)

Proposed changes
There are precision gaps between the vllm hip implementation and CK when testing some models.
The results with this patch are much more closer to vllm hip, but still have some differences.
Example reduction output:
CK: float = 26543.632812, raw = 46cf5f44
vllm: float = 26543.630859, raw = 46cf5f43
The 1 bit difference occurs right after the reduction, and such 1 bit difference may cause incorrect rmsnorm results up to the level of 1e-2.
We suspect that the issue relates to the reduction method used in the native VLLM implementation (rocprim. block reduce warp-reduce) because the original CK implementation performs summation sequentially. Additionally, in the VLLM implementation, RMSnorm is done in a T5-like manner, where an intermediate value needs to be cast to BF16 (temp = bf16(residual_v * s_variance)). We adopted this approach to achieve similar value distribution, ultimately improving model accuracy (verified through the GSM8K test set).
