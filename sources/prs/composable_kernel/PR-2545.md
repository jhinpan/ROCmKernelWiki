# [CK_TILE] Refactor async loads to work on all GPUs

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2545](https://github.com/ROCm/composable_kernel/pull/2545) · **Merged:** 2025-07-27 · **Author:** @doru1004

**Inclusion reason:** kernel path 'include/ck_tile/core/arch/amd_buffer_addressing.hpp'; keyword 'gfx942'

## Summary (from upstream PR description)

The current implementation does not take into consideration the fact that the src_immediate_addr_offset must be an immediate argument except in the case of gfx950. When compiling for gfx942 for example, a compiler with assertions enabled will fail to compile a code using the llvm_amdgcn_raw_buffer_load_lds intrinsic with this error:
immarg operand has non-immediate parameter
  %10 = load i32, ptr %src_immediate_addr_offset.addr.ascast, align 4, !tbaa !12
  call void @llvm.amdgcn.raw.buffer.load.lds(<4 x i32> noundef %4, ptr addrspace(3) noundef %7, i32 noundef 4, i32 noundef %8, i32 noundef %9, i32 noundef %10, i32 noundef 0) #27

fatal error: error in backend: Broken module found, compilation aborted!

With this PR we allow the correct compilation for other architectures by fixing this argument to zero (for now) just like we do in the case of gfx950. An assert has been added to catch the cases where the value passed in is not zero to allow the special casing in the future or the development of a more robust solution if needed.
