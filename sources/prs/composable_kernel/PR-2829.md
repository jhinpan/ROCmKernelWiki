# Verify `HostTensorDescriptor` when it is created

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2829](https://github.com/ROCm/composable_kernel/pull/2829) · **Merged:** 2025-09-26 · **Author:** @emezh

**Inclusion reason:** kernel path 'example/01_gemm/run_gemm_example.inc'; keyword 'wmma'

## Summary (from upstream PR description)

Proposed changes
Verify tensor descriptor is valid, specifically tensor dimensions vs strides.
For example, a 128x128 matrix can't have a stride of 64 in the outer dimension.
Issues
LWPCK-3425 [gemm_multiply_add] accuracy issue observed with multiple tests
LWPCK-3417 [gemm_fastgelu] accuracy issue observed with multiple tests
LWPCK-3405 [gemm_add_relu] accuracy issue observed with multiple tests
LWPCK-3403 [gemm_add_relu_add_layernorm] accuracy issue observed with multiple tests
In all the issues above, ckProfiler is invoked with invalid parameters and these are not checked, hence the incorrect results.
The Fix
The fix is to verify tensor descriptor (HostTensorDescriptor) when it is created using a new HostTensorDescriptor::ValidateStrides.
PR #2638 did something similar, but requires calling validate function explicitly. The solution in this PR is more generic and, essentially, it reverts changes in PR #2638.
