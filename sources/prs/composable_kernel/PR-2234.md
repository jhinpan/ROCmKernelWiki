# Add catch blocks in example GEMM apps to enable better error handling (Issue: 1928)

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2234](https://github.com/ROCm/composable_kernel/pull/2234) · **Merged:** 2025-05-28 · **Author:** @AviralGoelAMD

**Inclusion reason:** kernel path 'example/ck_tile/03_gemm/gemm_basic.cpp'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
This PR adds try-catch blocks to the main() functions in several CK Tile example applications (gemm_basic, gemm_universal, flatmm_basic, grouped_gemm, etc.) to handle std::runtime_error exceptions more robustly.
Previously, if invalid arguments were passed (e.g., -m=128 -n=128 -k=32) and the kernel rejected them via:
if (!Kernel::IsSupportedArgument(kargs)) {
    throw std::runtime_error("Wrong! Arguments not supported! Skipping gemm!");
}
the application would:

Abort via std::terminate(), causing a SIGABRT (signal 6),
Skip stack unwinding (no destructors called),
And potentially hang the Docker container, requiring a manual restart.

This behavior was reported in Issue #1928, though I could not reproduce it freezing of the container part.
