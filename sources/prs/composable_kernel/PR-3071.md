## Summary (from upstream PR description)

Proposed changes
This pull requests adds some initial "factory tests" - these check that the instances which are used in MIOpen are actually present in CK. The main reason for this is documentation and sanity checking. Its likely that these tests get outdated fast, so we'll have to maintain them, but fortunatenly this is quite straight forward and shouldn't take a lot of time once they are in place.
Design
The main idea is straight forward: Each test corresponds to one or a few "device operations" (structs which specialize DeviceOperationInstanceFactory), and checks whether all instances defined in that factory are present. To this end, I've added some utilities so that the test file itself is very easy to write:

InstanceSet represents a set of instances, either obtained from a factory, or from a statically defined list. InstanceSet::from_factory<DeviceOp> can be used to query DeviceOperationInstanceFactory directly, while the initializer-list constructor can be used for statically defined list of (expected) instances.
