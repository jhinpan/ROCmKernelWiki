# Add 0 as an acceptable arguement for strides in CK GEMM example (Issue 2037)

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2268](https://github.com/ROCm/composable_kernel/pull/2268) · **Merged:** 2025-06-03 · **Author:** @AviralGoelAMD

**Inclusion reason:** kernel path 'example/01_gemm/common.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
When running a CK Tile example from command line passing 0 as a value for stride argv(s) is considered acceptable. 0 implies that the example will deduce the strides for matrices from their shape.
This behavior is slightly different in classic CK GEMM examples where -1 is the equivalent. However, 0 would not trigger stride calculations and the kernel will run with strides = 0.
Logically, 0 is not a valid value and results in naive_gemm_kernel to crash.
This problem is reported in #2037
We fix this issue by extending the classical CK examples to accept both -1 and 0 as acceptable arguments and triggering default stride calculations when 0 or -1 is passed.
