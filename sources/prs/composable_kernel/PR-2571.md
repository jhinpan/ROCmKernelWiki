# [CK_TILE] Fix UB and corner cases in f32/f16 to/from f8 conversion

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2571](https://github.com/ROCm/composable_kernel/pull/2571) · **Merged:** 2025-07-31 · **Author:** @ex-rzr

**Inclusion reason:** kernel path 'include/ck_tile/core/numeric/float8.hpp'; keyword 'fp8'

## Summary (from upstream PR description)

Proposed changes

There are UBs when very small values are converted to f8: bitshifts can be larger that type width. Using unsigned long long does not help because exponent_diff >= 64 in such cases.
This causes that values like 2.117582368e-22 are converted to non-zero f8 in host validation of FMHA tests: f32 to f8 conversion is used after softmax that produces mostly zeros or close-to-zero values and a few larger values (<= 1 before scaling), values around 1e-22 were incorrectly converted on host to values around 1e-3..1e-2 affecting final results of host validation code.
Other manifestations of UB: test_f8 crashes with segfault in completely irrelevant code like GTest internals or produces incorrect and non-deterministic results.
Fix FNUZ conversion to return NaN for NaN inputs.
Fix compilation error (due to uint8_t << 8) in OCP e5m2 to f16 conversion.
Add tests.
