# Fix argument order for calls to profile_batched_gemm_impl()

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2277](https://github.com/ROCm/composable_kernel/pull/2277) · **Merged:** 2025-06-18 · **Author:** @krithalith

**Inclusion reason:** kernel path 'profiler/include/profiler/profile_batched_gemm_impl.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
I found  a bug in the gtest tests for batched_gemm_xdl and batched_gemm_multi_d_dl. They both call profile_batched_gemm_impl() to perform the tests, but they mistakenly swapped the order of the regular strides and the batching strides. This made the profiler create tensors which were way too big for the problem. The tests were still functionally correct, but would run too slow and also increasing the problem sizes even slightly could lead to allocations larger than the available GPU memory.
I fixed the argument order for all calls to profile_batched_gemm_impl() that occur in the codebase, which is only in the mentioned 2 gtest tests. I checked that the tests still gave the correct results and checked the allocated sizes for the tensors, as well as the total runtime for the test. You can see these results here:
TESTED ON INTERNAL SERVER WITH gfx90a (AMD Instinct MI210): 
results before and after fix (->):
test_batched_gemm_xdl:
Biggest allocs:
A size 17 MB -> 0.4 MB
B size 33 MB -> 0.4 MB
C size 67 MB -> 0.8 MB

Total test runtime: 30.11s -> 2.17s

test_batched_gemm_multi_d_dl:
Biggest allocs:
A size 33.5 MB -> 0.2 MB
B size 4.2 MB -> 0.1 MB
C size 67.0 MB -> 0.4 MB
