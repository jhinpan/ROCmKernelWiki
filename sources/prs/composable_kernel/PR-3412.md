# [CK Grouped Gemm] Fix workspace stride in two stage kernel

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3412](https://github.com/ROCm/composable_kernel/pull/3412) · **Merged:** 2025-12-19 · **Author:** @johannes-graner

## Summary (from upstream PR description)

Proposed changes
With the changes from #3405 applied, a separate crash appeared in the profile_grouped_gemm.sh tests.
This memory access violation was due to the usage of non-padded C stride in the workspace, fixed by using the correct padded stride depending on output layout.
The stride used before was the one supplied by the user, which could be incompatible with the layout after padding.
