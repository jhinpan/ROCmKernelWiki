# Fix the issue: Missing kernel on gfx950

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#2560](https://github.com/ROCm/composable_kernel/pull/2560) · **Merged:** 2025-07-24 · **Author:** @CongMa13

**Inclusion reason:** kernel path 'test/ck_tile/gemm/test_gemm_pipeline_smoke_util.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

Proposed changes
template <typename PrecType, ck_tile::index_t M_Warp_Tile>
constexpr ck_tile::index_t get_k_warp_tile()
{
#if defined(__gfx950__)
    constexpr bool is_8bit_float =
        std::is_same_v<PrecType, ck_tile::fp8_t> || std::is_same_v<PrecType, ck_tile::bf8_t>;
    if constexpr(M_Warp_Tile == 32)
        return is_8bit_float ? 64 : 16;
    else
        return is_8bit_float ? 128 : 32;
#else
    if constexpr(M_Warp_Tile == 32)
        return 16;
    else
        return 32;
#endif
}

Here __gfx950__ is a macro only defined for device code.
So when PrecType is fp8 and M_Warp_Tile is 32, this function get_k_warp_tile returns 64 in device code and 16 in host code.
This leads to a problem that the kernel generated in host code does not match the kernel in device code if return value of get_k_warp_tile is used as template parameter of the kernel.
In this PR, a commit was cherry-picked in which CK_GFX950_SUPPORT, a macro defined in CMake script is used to replace __gfx950.  And it works when gfx950 is the only explicitly specified target to CMake which is what all CI pipes do.
