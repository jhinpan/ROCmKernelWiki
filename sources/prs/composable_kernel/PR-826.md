# Implement DPP8-based GEMM for Navi21

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#826](https://github.com/ROCm/composable_kernel/pull/826) · **Merged:** 2023-08-14 · **Author:** @bwroblew

**Inclusion reason:** kernel path 'example/01_gemm/CMakeLists.txt'; keyword 'gemm'

## Summary (from upstream PR description)

This PR introduces a functional implementation of DL GEMM kernel that uses DPP8 modifier to reduce the amount of data loaded from LDS to registers. The kernel divides the data between the threads in such a way that 8 consecutive threads need the same chunk of matrix A or B, so all can pull that data from just a single thread (it's possible since they belong to the same lane group).
This change doesn't necessarily improve performance of the current DL GEMM kernels, further performance optimizations will come in separate PRs. This is mostly a functional change now. But for some cases performance is already better.
The new kernel utilizes the existing DeviceGemmDl and GridwiseGemmDl_km_kn_mn_v1r3, differs in the implementation of blockwise and threadwise parts.
As for now, the new kernel supports only Navi21 architecture and fp16 datatype. Will be extended in future PRs.
