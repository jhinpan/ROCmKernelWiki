# [CK_BUILDER] Put global CK functions in a CK namespace

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#3232](https://github.com/ROCm/composable_kernel/pull/3232) · **Merged:** 2025-11-19 · **Author:** @shumway

**Inclusion reason:** kernel path 'client_example/31_grouped_gemm_bf16Aint8B/grouped_gemm_bias_fastgelu_xdl_bf16_i8.cpp'; keyword 'wmma'

## Summary (from upstream PR description)

This PR move some CK utility functions from the global namespace to the ck namespace. This change requires a lot of small updates to our examples and tests for CK, too.
Motivation: We cannot currently combine source code from CK and CKTile because not all of old CK is in the CK namespace. For example, the ck utility hip_check_error in  include/ck/host_utility/hip_check_error.hpp is in the global namespace, and thus creates ambiguity errors when included with CKTile code.
While it might be tempting to just keep the codebases separate, this is not possible if we want to have the builder able to instantiate both CK and CKTile kernels.
Furthermore, the fact that CK leaks symbols into the global namespace is bad for any library users. This needs to be fixed.
The simplest thing is to move these global symbols into the ck namespace. There might be more elegant design choices, but this is the most general and least likely to break existing CK code.
There are a lot of places where we have to then add using declarations like this:
