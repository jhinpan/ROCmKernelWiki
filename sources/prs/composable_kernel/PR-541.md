# [Navi3x-LWPCK-545] Block-wise GEMM + Real GEMM_WMMA_FP16

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#541](https://github.com/ROCm/composable_kernel/pull/541) · **Merged:** 2023-01-17 · **Author:** @aska-0096

**Inclusion reason:** kernel path 'example/01_gemm/CMakeLists.txt'; keyword 'wmma'

## Summary (from upstream PR description)

This PR including three coupled topics.
Block-wise GEMM

Device side Backend API for v_wmma_xx_16x16x16_xx  built-function inside include/ck/utility/amd_wmma.hpp
New Wave-wise op WMMA abstraction inside include/ck/tensor_operation/gpu/warp/wmma_gemm.hpp
include/ck/tensor_operation/gpu/block/blockwise_gemm_wmma.hpp have two type of block-wise pipeline, the one with "FIFO" postfix is designed for inline assembly WMMA.

Real GEMM

Grid-wise GEMM with C shuffle implemented  inside include/ck/tensor_operation/gpu/grid/gridwise_gemm_wmma.hpp
Device OP API in include/ck/tensor_operation/gpu/device/impl/device_gemm_wmma.hpp
Finally we have a example MK_NK_MN GEMM here example/01_gemm/gemm_wmma_fp16.cpp, tile size using M128xN128xK64, as we can benefit from larger unroll-K while not suffer occupancy loss as gfx1100 provide sufficient VGPRs. (maximum 128x128x96)

test_wmma_op update

As unexpected HIP compiler behavior observed during the development of Real GEMM, one of two kernels inside the test_wmma_op is updated to LDS enable version, to have better coverage of compiler quality.
