## Summary (from upstream PR description)

Proposed Changes
This pull request adds the setup for a CK-Builder based device operation test framework. It supports multiple goals:

A unified test framework for testing CK and CK Tile device operations.
Dogfooding of CK-Builder by creating a sort of internal consumer of the API. This allows us to think about the API from an outside perspective, find missing or weird bits, etc.
Take the opportunity to design a test system for a GPU-first world, where input generation, reference computations, and validation are all performed on the GPU.

Design
A device operation test follows a Given-When-Then pattern. In short:

Given: An operation and inputs

A signature and algorithm to define the operation.
A set of runtime arguments (tensor dimensions, filter dimensions, etc)
A set of input tensors with data


When: Run the device operation

Invoke the device operation using the runtime arguments and input data, to produce output data.


Then: Validate the outputs

Invoke a reference operation (on the GPU).
Compare the results.
