**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#370](https://github.com/ROCm/composable_kernel/pull/370) · **Merged:** 2022-08-23 · **Author:** @rosenrodt

## Summary (from upstream PR description)

Add device level function DeviceBatchedGemmSoftmaxGemmPermute_Xdl_CShuffle. Replacements:

CLayout -> CPermuteNumDims_G_M_Gemm1N which is a Sequence<>
StrideC, BatchStrideC -> c_gs_ms_os_lengths, c_gs_ms_os_strides which are std::vector<index_t>'s

I do not implement full contraction-based solution because I have concerns about interface design of current contraction ops, mainly that TensorSpecialization::Packed seems broken unless having an extra input "DimOrder".
