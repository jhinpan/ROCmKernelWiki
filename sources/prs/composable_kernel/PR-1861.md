# [CK_TILE] Improve RMS/Layer Normalization 2 Pass Pipeline Performance

**Repository:** [ROCm/composable_kernel](https://github.com/ROCm/composable_kernel) · **PR:** [#1861](https://github.com/ROCm/composable_kernel/pull/1861) · **Merged:** 2025-03-25 · **Author:** @ruanjm

**Inclusion reason:** kernel path 'example/ck_tile/02_layernorm2d/generate.py'; keyword 'kernel'

## Summary (from upstream PR description)

Improve RMS Normalization Performance
Mainly forcus on tile shape 64 x 65536.
NoteCurrent setting may not be optimal for other tensor shapes especially for the cases that m is not 64.


Set RepeatN as 1 for vectorized-8 cases.
Fine tuned thread grid size for various vectorized size under 64 x * cases. Note that performance tests are based on aiter test https://github.com/ROCm/aiter/blob/main/op_tests/test_rmsnorm2d.py. Smoke tests in CK (https://github.com/ROCm/composable_kernel/tree/develop/example/ck_tile/10_rmsnorm2d/script) is only used for reference.
In fused-add-store cases, use residual buffer in 2nd pass for saving memory transactions and calculations.

Update 2025.3.24:
Additionally, this PR includes a new epilogue which is firstly used in rmsnorm operator for outputing quant and unquant results at the same time as @valarLip requests..
Update 2025.3.25:
Tuned cases about 128x640 and 128x1024 as @valarLip requests.
