ISSUE ID: #8997
Motivation
The CK Tile dispatcher could already generate and launch regular GEMM through the
TileEngine → Dispatcher bridge, but it had no path for the multi-tensor
gemm_multi_abd op. Multi-ABD is used when a GEMM needs to combine several A and
B operands and fuse several D operands in the epilogue
(E = cde_op(a_op(As) @ b_op(Bs), {Ds})), which is a real Old-TE capability with no
dispatcher equivalent. This PR closes that gap so Python callers can drive multi_abd
through the dispatcher at parity with the legacy Tile Engine version, without touching
C++.
It follows the divergent-ABI pattern established by the grouped bridge (#9000) because
multi_abd needs arrays of A/B/D device pointers, not the single-pointer regular
GEMM ABI. The capability set matches the Old-TE gemm_multi_abd_instance_builder.py
exactly: fp16, rcrr layout, configurable A/B/D tensor counts, and the element-wise
op set {PassThrough, AddScale, MultiDMultiply, MultiDAdd}.
