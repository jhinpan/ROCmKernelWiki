Created a persistent kernel version of the attn_fwd as attn_fwd_persistent. Decided to create a separate kernel, because adding the while loop makes the code more complex to read and necessitates some minor changes (e.g. no return statements allowed inside while loop, which are used in attn_fwd).
In _attention.forward a command line argument -persistent controls which version of the kernel gets to run. With attn_fwd_persistent we only launch CUs * GRID_CU_MULTIP number of workgroups which then loop over the tiles. By specifying -persistent dynamic you activate dynamic scheduling of the tiles with atomic instructions (useful when causal=True).
Added a unit test for the persistent version test_op_persistent_fwd. Also fixed the calculation of FLOPs with unequal seqlen_q/k in the benchmark.
