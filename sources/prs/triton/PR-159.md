# [dotOp] [rocMLIR] Add RockToGPU Conversion pass

**Repository:** [ROCm/triton](https://github.com/ROCm/triton) · **PR:** [#159](https://github.com/ROCm/triton/pull/159) · **Merged:** 2023-03-16 · **Author:** @zhanglx13

**Inclusion reason:** kernel path 'test/dot-rocMLIR/Conversion/RockToGPU/emptykernel.mlir'; keyword 'kernel'

## Summary (from upstream PR description)

This PR adds the RockToGPU conversion pass from the rocMLIR repo.

Modify the existing conversion passes to use the per-pass autogenerated macros (reference).
Add {kernel = 0} as an attribute of the mlir::func::FuncOp. This is required by the RockToGPU pass to convert the func.func into a gpu.func
Add unit test for the RockToGPU pass

This pass

Convert the func.func into gpu.func
Create a gpu.module inside the top level Module to wrap the gpu.func
Add a gpu.container_module attribute to the top level Module
Lower rock.alloc as an attribution to the gpu.func.

One note about lowering rock.alloc().  Triton has its own Allocation and AllocationAnalysis class to manage shared memory. However, rock.alloc() can also be used to "allocate" LDS memory and it is handled in a different way. Fortunately, in dot lowering process, rock.alloc() is only used to allocate private memory. Therefore, the management of shared/LDS memory is still under control by Triton.
