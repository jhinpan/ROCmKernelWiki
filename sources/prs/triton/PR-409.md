# Non pow 2 seqlen

**Repository:** [ROCm/triton](https://github.com/ROCm/triton) · **PR:** [#409](https://github.com/ROCm/triton/pull/409) · **Merged:** 2023-12-04 · **Author:** @vgokhale

## Summary (from upstream PR description)

Add kernel to support non power of 2 sequence lengths. Main changes include:


Add non power of 2 sequence lengths in both the fwd_op test and the benchmark. These lengths are meant to "correspond" to their pow2 counter parts for perf and correctness comparisons. So for example, seqlen 1989 can be compared to seqlen 2048.


The mechhanism in which this is handled is, we first compute the QK GEMM using the nearest multiple of block size sequence length. For the very last loop, where we overflow, we use masking, similar to causal masking, to set the higher elements to -inf. When put through softmax, this will effectively ignore these elements, and zero them out when we do the exp.


I've set the benchmark to only use 128 for now. I am not sure why, but both 64 and 128 run together cause an out of memory error.
