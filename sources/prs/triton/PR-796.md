# [AMD] Enable async pingpong for F16 GEMMs

**Repository:** [ROCm/triton](https://github.com/ROCm/triton) · **PR:** [#796](https://github.com/ROCm/triton/pull/796) · **Merged:** 2025-05-15 · **Author:** @raikonenfnu

**Inclusion reason:** kernel path 'third_party/amd/backend/compiler.py'; keyword 'gemm'

## Summary (from upstream PR description)

This main motivation behind this commit is to add support for PingPong with AsyncOps for GEMMs on FP16. In order to accomplish that we made these changes:

Fork "determineDotMemoryOps" to "determineDotAsyncMemoryOps" that handles async memory ops.
Refactor validation and pruning of memory ops to "pruneDotMemoryOps" S.T we can have clean interface for it's async memory ops counterpart "pruneAsyncDotMemoryOps".
Add a reordering controlled by TRITON_HIP_ENABLE_F16_ASYNC_PINGPONG on StreamPipeliner S.T it can adjust AsyncWait stage/cluster to hoist first AsyncWait and allow set AsyncWait towards the end of the loop to make it easier for 4 PP cluster to move it before the 3rd dot-slice / 2 s_barrier before localLoads this is to ensure no race conditions.
Modified 4 PP cluster to handle asyncOps
Add check to enable handling of dotSOps (dot scaled) VS dotOps (dot)
Move comesFromAsyncWait to it's own AsyncUtility S.T we can reuse it on AliasScope analysis.
Add support for LLVM::BrOp and UnrealizedConversionCastOp for comesFromAsyncWait to handle AliasScope
