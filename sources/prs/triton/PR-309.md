# refine gemm tuning scripts

**Repository:** [ROCm/triton](https://github.com/ROCm/triton) · **PR:** [#309](https://github.com/ROCm/triton/pull/309) · **Merged:** 2023-09-07 · **Author:** @scxiao

## Summary (from upstream PR description)

This PR is for a tuning script for GEMM execution. It is to reduce use the tuning configs save tuning time. It uses two kernels for different input size, kernels with SPLIT_K can cause overhead for kernel do not need SPLIT_K.
Meaning of each input option:

--specify_type indicate data type, default is fp16, supported types are fp32, fp16, and bf16
--specify_size indicate input size is read from input -m, -n, and -k. If not use --specify, input matrix size is read from a yaml file from the argument of --gemm_size_file.
-v indicate whether print out the best tuing config for the corresponding input matrix size
--rocprof indicate using rocprof to measure kernel time, if not set, kernel time is from do_bench
--comapre if set, it will compare correctness of triton outputs to torch outputs.

Some example commands
python matmul.py --specify_size -m 1024 -n 1024 -k 1024
python matmul.py --specify_size -m 1024 -n 1024 -k 1024 --compare
python matmul.py --specify_size -m 1024 -n 1024 -k 1024 -v --rocprof
python matmul.py --gemm_size_file gemm_ex.yaml -v --rocprof
An example gemm_ex.yaml file is like:
- {'M': 16, 'N': 16, 'K': 16}
- {'M': 256, 'N': 256, 'K': 256}
- {'M': 64, 'N': 128, 'K': 51
