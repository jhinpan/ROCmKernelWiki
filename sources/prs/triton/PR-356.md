# Improve FA fwd kernel with causal=True

**Repository:** [ROCm/triton](https://github.com/ROCm/triton) · **PR:** [#356](https://github.com/ROCm/triton/pull/356) · **Merged:** 2023-10-12 · **Author:** @zhanglx13

## Summary (from upstream PR description)

Optimizations for causal=True (triton-lang#2332)

split the loop into 2 and only pay the masking overhead in the second loop

Optimizations for MI GPUs

add pre_load_v as a tuning parameter

It turns out on MI250, causal=False likes to preload v but causal=True does not like it


do not define N_CTX as constexpr
perform the second dot before sum
remove qk_scale out of the inner loop

Autotuning

Added configs in autotuner to tune waves-per-eu, pre_load_v and num_stages.

waves-per-eu: on MI250, both causal=False and True picked 3 as waves-per-eu
pre_load_v: As mentioned before, causal=False picked True and causal=True picked False
num_stages: both picked 1, a.k.a. with stream-pipelining disabled


With D=64, block size is fixed to BLOCK_M=128, BLOCK_N=64

Will enable tuning for block size with D=128 in #340 or after it's merged



Impacts to bwd kernel (resolved)
This PR does not take any optimizations for bwd kernel from triton-lang#2332. And due to autotuner, ctx.grid becomes a function and ctx.grid[0] no longer works. Will fix this in the future PR.
