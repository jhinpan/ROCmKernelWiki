# Move cuda2gcn.bc files to third_party

**Repository:** [ROCm/triton](https://github.com/ROCm/triton) · **PR:** [#193](https://github.com/ROCm/triton/pull/193) · **Merged:** 2023-04-17 · **Author:** @jataylo

**Inclusion reason:** kernel path 'python/triton/language/math.py'

## Summary (from upstream PR description)

Additional context: ROCm/frameworks-internal#3367 (comment)
When triton is installed via python setup.py install the required cuda2gcn.bc file is not copied over to the package location.
This results in some UT failures in pytorch
Failed to load /opt/conda/envs/py_3.8/lib/python3.8/site-packages/triton/language/cuda2gcn.bcTranslate to LLVM IR failedLLVM ERROR: Failed to translate TritonGPU to LLVM IR.
Proposed solution:
To alleviate this issue I have proposed to move the cuda2gcn files to third_party to ensure the file is copied over without a change to setup.py.
As of pytorch/pytorch#98096 we have moved to install triton from source in the ROCm docker images for upstream pytorch CI and run into this issue where triton is installed with pip install "git+https://github.com/ROCmSoftwarePlatform/triton@de3f5436247e391b062a7dd7fd42d2a55c2cd524#subdirectory=python"
Reproducing torch UT:
pytest test/inductor/test_torchinductor_dynamic_shapes.py -k "test_any_dynamic_shapes_cuda" --verbose
