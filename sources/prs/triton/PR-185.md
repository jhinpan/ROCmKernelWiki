# [dotOp] [rocMLIR] Make k-loop in test_gemm work

**Repository:** [ROCm/triton](https://github.com/ROCm/triton) · **PR:** [#185](https://github.com/ROCm/triton/pull/185) · **Merged:** 2023-04-19 · **Author:** @zhanglx13

**Inclusion reason:** kernel path 'python/setup.py'; keyword 'gemm'

## Summary (from upstream PR description)

This PR enables k-loop for single block kernels (see test_gemm.py). For multiple block kernels, it does not work when BLOCK_SIZE_N > N. This will be fixed in the next PR.
Here is a summary of what this PR does:

lower dotOp with blockwise_gemm_v2 with k-loop
Removed RockToGPU pass
Update the LLVM binary version and removed rock-linalg-align pass
Copied insert_slice op from tensor dialect into TritonGPU dialect in the same way as extract_slice op
Use opaque pointers for LDS buffers
Lower AsyncCommitGroupOp -> rock::LDSBarrierOp -> amdgpu::LDSBarrierOp
Introduce LDS encoding in pipeline pass and InserSliceOpConversion
Fixed the issue with tensor_to_memref when the src points to inside an allocated LDS buffer
disable the prefetch pass
