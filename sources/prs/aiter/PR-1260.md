# Kernel naming: add reusable constexpr repr helper and testing it with gemm_a16w16

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1260](https://github.com/ROCm/aiter/pull/1260) · **Merged:** 2025-11-04 · **Author:** @Boss2002n

## Summary (from upstream PR description)

Add config-aware naming to kernels
Introduces a repr mechanism for kernels that embeds compile-time configuration parameters directly into kernel names, making performance traces significantly more informative.

Created make_kernel_repr() helper in "aiter/ops/triton/utils/_triton/kernel_repr.py"

Examples:
Before: _gemm_a16_w16_kernel
After: _gemm_a16_w16_kernel_BLOCK_SIZE_M_128_BLOCK_SIZE_N_256_BLOCK_SIZE_K_64_GROUP_SIZE_M_8_NUM_KSPLIT_1_SPLITK_BLOCK_SIZE_32_cache_modifier_CG_activation_NONE_use_activation_0
This will help us correlate performance with specific kernel configurations and enable config-level analysis in traces
How to use make_kernel_repr() helper:
_kernel_repr = make_kernel_repr("kernel_name", ["PARAM1", "PARAM2", ...])
@triton.jit(repr=_kernel_repr)
def my_kernel(...):
...
