# [Misc] Add DSv4-Pro MTP spec-decoding tuned GEMM (a8w8 N=7168 K=7168 up to M=65536, bf16 N=384 K=7168)

## Summary (from upstream PR description)

Summary
Two new shapes detected when running DSv4-Pro with MTP speculative decoding (`--method mtp --num-speculative-tokens 1`) on gfx950 / cu_num=256.
1. a8w8_blockscale_bpreshuffle: N=7168, K=7168 (extended to M=65536)
MTP speculative decoding pushes the effective M beyond the previous 32768 ceiling — observed M up to 65524 in atom_server log. Adds 75 rows covering:
```
1, 2, 4, 8,
16..256 step 16,
288..1024 step 32,
1088..2048 step 64,
4096, 6144, 8192, 10240, 12288, 14336, 16384,
20480, 24576, 28672, 32768, 40960, 49152, 57344, 65536
```
Tuned with `--libtype all` (ck/cktile/asm), 75/75 success, ~6 min on 8x MI355X.
2. bf16: N=384, K=7168, bf16 → bf16 (53 new rows)
Distinct from the previously-skipped `otype=fp32` Indexer variant — this is the bf16→bf16 path that surfaces under spec decoding. 67 M values submitted, 53 unique rows after dedupe against kimik2 (next section).
Tuned with `--libtype asm,flydsl,skinny,torch,triton` — hipblaslt explicitly excluded.
3. kimik2_bf16 dedupe (side effect)
The tuner's merge dedupe removed 10 overlapping `(N=384, K=7168)` rows from `kimik2_bf16_tuned_gemm.csv` that are now superseded by the dsv4 entries. Same behavior as PR #3113.
