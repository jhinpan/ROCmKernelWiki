# perf(sampling): replace ternary-search TopKRenorm with radix-select +…

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3217](https://github.com/ROCm/aiter/pull/3217) · **Merged:** 2026-05-24 · **Author:** @chuanbowang2026

**Inclusion reason:** kernel path 'csrc/cpp_itfs/sampling/sampling.cuh'; keyword 'kernel'

## Summary (from upstream PR description)

The current TopKRenormProbKernel uses ternary search to find the k-th largest probability, requiring O(log(V)) iterations with multiple __syncthreads() per iteration.
For large vocabularies (D=128K), the DeviceSamplingFromProb function also suffers from excessive synchronization due to per-chunk BlockReduce calls (~64 syncs per
do-while iteration).
This PR replaces the ternary search with a deterministic radix-select algorithm and optimizes the sampling kernels with thread-local accumulation, significantly reducing
synchronization overhead.
Technical Details
TopKRenorm (radix-select replacement):

Replace TopKRenormProbKernel (ternary search) with a 3-pass 11-bit oneblock radix-select (radix_topk_one_block_kernel)
Add TopKRenormWriteOnlyKernel for fused pivot-threshold renormalization write-back
Deterministic: no cross-block sync, no floating-point convergence dependency
Update top_k_renorm_probs.cpp.jinja and .py to call new host orchestration function topk_renorm_from_probs()

DeviceSamplingFromProb / TopP / TopKTopP (thread-local accumulation):

Phase 1: remove per-chunk BlockReduce(Max) for last_valid_id, use thread-local max + single reduce after loop
Phase 2: replace per-chun
