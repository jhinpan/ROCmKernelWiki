# fix: del asm layernorm

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2571](https://github.com/ROCm/aiter/pull/2571) · **Merged:** 2026-04-01 · **Author:** @TennyWang1223

**Inclusion reason:** kernel path 'aiter/ops/norm.py'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation
Remove the hand-written ASM LayerNorm kernels (layer_norm.co / layer_norm_qnt.co) targeting gfx942. These ASM kernels are limited to n == 8192 and m % 2 == 0 with bf16-only support, while the existing CK (Composable Kernel)
tile-based LayerNorm implementation already covers the same functionality with broader shape and dtype support. Keeping the ASM variants adds maintenance burden without providing additional value.
Technical Details

Removed module_asm_layernorm entry from aiter/jit/optCompilerConfig.json.
Removed layernorm2d_with_add_asm and layernorm2d_with_add_smoothquant_asm Python wrappers from aiter/ops/norm.py.
Deleted the CUDA/HIP source file csrc/py_itfs_cu/asm_layernorm.cu.
Deleted pre-compiled ASM binaries hsa/gfx942/layer_norm.co and hsa/gfx942/layer_norm_qnt.co.
Cleaned up test files op_tests/test_layernorm2d.py and op_tests/test_layernorm2dFusedAddQuant.py to remove all run_asm references and ASM-related assertions.

Test Plan

Run op_tests/test_layernorm2d.py to verify LayerNorm with fused-add still passes using the CK implementation.
Run op_tests/test_layernorm2dFusedAddQuant.py to verify LayerNorm with fused-add smooth quantization still passes using t
