# [TRITON] Add Positional Encoding (PE) support to Triton MHA kernels

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1184](https://github.com/ROCm/aiter/pull/1184) · **Merged:** 2025-10-17 · **Author:** @brunomazzottiamd

**Inclusion reason:** kernel path 'aiter/ops/triton/_triton_kernels/mha.py'; keyword 'attention'

## Summary (from upstream PR description)

Motivation
DeepSeek models (DeepSeek-V2 and DeepSeek-V3) rely on Multi-head Latent Attention (MLA). MLA splits $Q$ and $K$ tensors into non-positional (NOPE) and positional (ROPE) parts:

The head dimensions of $Q$ and $K$ tensors are 192, 128 elements for NOPE part plus 64 elements for ROPE part. In Triton, all block sizes must be a power of 2, so the next power of 2 after 192 is 256. This inherent design of Triton ends up with 192 / 256 = 75% use along head dimension, with 64 elements being zeroed or masked out of computations.
This PR decouples NOPE and ROPE parts of $Q$ and $K$ tensors in Triton MHA kernels, so we can achieve a 100% use given that both NOPE and ROPE parts are powers of 2. For instance, instead of doing just one matrix multiplication with head dimension equals to 256, we can do two equivalent matrix multiplications with head dimensions 128 and 64.
Technical Details

Added support for forward and backward passes. Kernel wrappers figure out if we're dealing with non-PE case (DQ = DK = DV) or PE case (DQ = DK, DK > DV).
