# [OPUS] enhance opus UT by adding more tests

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2040](https://github.com/ROCm/aiter/pull/2040) · **Merged:** 2026-02-14 · **Author:** @carlushuang

**Inclusion reason:** kernel path 'op_tests/opus/device/setup.py'; keyword 'mfma'

## Summary (from upstream PR description)

Expand OPUS device-kernel test suite from 3 tests to 25 tests and enhance the OPUS library with unified scaled MFMA support and predicated load/store APIs.
OPUS library changes (opus.hpp)
Two major enhancements to the core OPUS header:
Unified scaled MFMA — The standalone struct mfma_scale has been folded into struct mfma via new operator() overloads that accept runtime scale parameters. A compact mfma_vtype_t helper (SFINAE-based) resolves vector types for packed data types like fp4_t. The DISPATCH_MFMA_SCALE_ macro targets __builtin_amdgcn_mfma_scale_f32_* intrinsics, and the old mfma_scale_f32_* aliases now redirect to the unified mfma_f32_*.
Cherry-pick PR #2020 — predicated load/store & free function API — Adds load_if, store_if, and async_load_if to both gmem and smem, each accepting a callable predicate over the layout issue-space. New operator+ on layout_linear / layout_cached creates offset copies of layouts. Type traits (is_gmem_v, is_smem_v, is_mem_v) and free function wrappers (opus::load, opus::store, opus::load_if, etc.) eliminate the .template syntax burden in dependent contexts. Also fixes vectorize_issue_space to divide by the requested vec rather than vec_from_iss
