# Fix FlyDSL split-k HGEMM correctness and precision issues

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2567](https://github.com/ROCm/aiter/pull/2567) · **Merged:** 2026-04-01 · **Author:** @XiaobingSuper

**Inclusion reason:** kernel path 'aiter/ops/flydsl/kernels/splitk_hgemm.py'; keyword 'gemm'

## Summary (from upstream PR description)

Before, we only tested num_concurrent=16 GSMK accuracy. For num_concurrent=65, we observed accuracy regression for kimi2. This is caused by a split-k issue for some shapes.
This PR fixes correctness and numerical precision issues in the FlyDSL split-k HGEMM path when split_k > 1.
Previously, the split-k C tile zero/load/store coverage used floor division, which could skip tail rows for shapes such as tile_m=48, leading to NaNs and large output mismatches.
This change is:
using ceil-div plus explicit bounds checks for split-k C tile coverage
As a result, the tile_m=48 split-k regressions are removed, and the NaNs disappear.
