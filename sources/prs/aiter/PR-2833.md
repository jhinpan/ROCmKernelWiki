# [FIX] fix other lse addr compute issue in fmha bwd v3

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2833](https://github.com/ROCm/aiter/pull/2833) · **Merged:** 2026-04-22 · **Author:** @JaxChen29

**Inclusion reason:** keyword 'kernel'

## Summary (from upstream PR description)

Motivation
fmha_bwd_v3 still had SBHD-specific regressions in the D128 path after the earlier A16 fixes.
Technical Details
Fixed the remaining D128 A16 fp16 pddv source shaders:
poc_kl/mi300/fmha_bwd_asm/shaders/FP16_FMHA_BWD_D128_1TG_4W_16mx1_48nx4_A16_Gen.sp3
poc_kl/mi300/fmha_bwd_asm/shaders/FP16_FMHA_BWD_D128_1TG_4W_16mx1_48nx4_A16_cas_kb_Gen.sp3
In the non-causal A16 Gen path, switched the Lse/D base computation to use the runtime BHS metadata already carried in the packed ABI.
In the causal A16 cas_kb path, kept the SGPR-safe heuristic variant for rebuilding the BHS batch offset under SBHD.
Fixed the active D128 A32 direct source shaders used by the current gfx942 runtime path:
poc_kl/mi300/fmha_bwd_asm/shaders/BF16_FMHA_BWD_D128_1TG_4W_16mx1_48nx4_A32.sp3
poc_kl/mi300/fmha_bwd_asm/shaders/FP16_FMHA_BWD_D128_1TG_4W_16mx1_48nx4_A32.sp3
poc_kl/mi300/fmha_bwd_asm/shaders/BF16_FMHA_BWD_D128_1TG_4W_16mx1_48nx4_A32_cas_kb.sp3
poc_kl/mi300/fmha_bwd_asm/shaders/FP16_FMHA_BWD_D128_1TG_4W_16mx1_48nx4_A32_cas_kb.sp3
For these A32 kernels, corrected the SBHD Lse/D batch-base computation so the kernels no longer infer BHS side-buffer addressing from layout-dependent s_BAs.
