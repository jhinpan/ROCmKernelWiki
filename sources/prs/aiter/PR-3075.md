**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3075](https://github.com/ROCm/aiter/pull/3075) · **Merged:** 2026-05-21 · **Author:** @samremes

## Summary (from upstream PR description)

This pull request introduces significant improvements to the kernel dispatch and tuning infrastructure for blockscale GEMM operations, focusing on more robust error handling, a shift to name-based kernel dispatch, and enhanced code maintainability. The main changes are grouped below:
1. Name-based Kernel Dispatch and Registry

The C++ runtime dispatcher for gemm_a4w4_blockscale now uses a name-keyed lookup (by kernelName string) instead of tuple-keyed shape-based lookup, aligning with the approach already used by a8w8 blockscale modules. This makes kernel selection more robust and easier to maintain.
Added write_name_keyed_lookup_header in chip_info.py and integrated it into the codegen pipeline, enabling generation of C++ lookup tables keyed by kernel name. [1] [2] [3]
The Python kernel registry now includes a kernels_by_name mapping for efficient reverse lookups and CSV filtering.
