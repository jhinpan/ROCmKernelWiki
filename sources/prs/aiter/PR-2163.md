# Corrects `arg_size` type from `int` to `size_t` for hip graph compatability

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2163](https://github.com/ROCm/aiter/pull/2163) · **Merged:** 2026-03-05 · **Author:** @Micky774

**Inclusion reason:** kernel path 'csrc/cpp_itfs/mha_bwd.cu'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation
We were seeing mysterious failures in TE when using AITER V3 kernels with HIP Graph enabled. We traced the issue down to ridiculous kernelargs_size values in the HIP Graph capture/initialization. This was then further traced to the usage of int arg_size which is then used to pass &arg_size -- an int* -- which is later read as a size_t* leading to junk values occasionally causing crashes when performing memory copies based on the junk sizes.
Technical Details
arg_size is now declared as size_t to match HIP Graph's expectations and downstream usage. See CUDA graph documentation and hip graph usage
Test Plan
Test with TE to see if it resolves the original issue.
Test Result
Tested with TE build and confirmed that it resolved the noticed issues.
