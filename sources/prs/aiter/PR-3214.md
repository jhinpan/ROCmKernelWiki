# configs: add DSv4-Flash shape to dsv4_fp8fp4_tuned_fmoe.csv

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3214](https://github.com/ROCm/aiter/pull/3214) · **Merged:** 2026-05-20 · **Author:** @XinyuJiangCMU

**Inclusion reason:** kernel path 'aiter/configs/model_configs/dsv4_fp8fp4_tuned_fmoe.csv'; keyword 'gemm'

## Summary (from upstream PR description)

Co-authored-by: @JessicaJiang-123
Problem
aiter/configs/model_configs/dsv4_fp8fp4_tuned_fmoe.csv ships only DSv4-Pro shapes:



model_dim
inter_dim
expert
topk




7168
512 / 768 / 1536
384 / 385
6 / 7



DSv4-Flash has a different shape — (model_dim=4096, inter_dim=256, expert=256, topk=6) per-rank on TP=8 — and has no entry.
Runtime fmoe dispatch MISSes for every Flash MoE call and falls back to the default CK heuristic, which trips:
RuntimeError: Unsupported kernel config for moe heuristic dispatch

because the underlying CK template has no Run() overload for FP8 act × FP4_mxfp4 weight stage1.
Fix
Add 34 rows (17 token buckets 1..131072, each with a primary all-FlyDSL row and a flydsl_fallback cktile_a8w4 row) for Flash. Same dtype combo as Pro rows:

q_dtype_a = torch.float8_e4m3fn
q_dtype_w = torch.float4_e2m1fn_x2
q_type = QuantType.per_1x32
dtype = torch.bfloat16, act_type = ActivationType.Silu

Data is produced by running gemm_moe_tune.py end-to-end on this shape on 8x MI350X (gfx950, cu_num=256). All us / tflops / bw numbers in this patch are real per-bucket measurements.
