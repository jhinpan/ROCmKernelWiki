# flydsl/common: per-kernel parallelism + configurable AOT pool size

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3133](https://github.com/ROCm/aiter/pull/3133) · **Merged:** 2026-05-13 · **Author:** @tenpercent

## Summary (from upstream PR description)

Problem
The FlyDSL AOT pre-compile stage in setup.py calls
aiter.aot.flydsl.common.start_aot(cache_dir), which previously spun up a
ProcessPoolExecutor(max_workers=2) and submitted exactly two tasks
(run_aot_worker for \"moe\" and \"gemm\"). Each worker then iterated its
own kernel list serially via a list comprehension.
Net effect: at most 2 concurrent FlyDSL compiles regardless of host size,
on a stage where the bulk of wall time is per-kernel codegen inside FlyDSL
itself.
On a 64+ core build host (typical CI / cluster build node) this leaves ~95%
of the machine idle for the FlyDSL stage.
Change
start_aot now flattens the kernel job lists from both kinds (MoE + GEMM)
into a single submission queue and dispatches each kernel as its own task
to a single shared ProcessPoolExecutor. Pool size:

AITER_FLYDSL_AOT_WORKERS (env override)

min(os.cpu_count() or 4, 64)
