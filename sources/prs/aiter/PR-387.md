# [TRITON] Causal Attention XCD balancing and MHA Scale

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#387](https://github.com/ROCm/aiter/pull/387) · **Merged:** 2025-05-13 · **Author:** @Chi-Chu319

## Summary (from upstream PR description)

Authors: @juuso-oskari, @Chi-Chu319
This PR is based on the following issue: ROCm/triton-internal#771. It fixes the grid traversal in order to have good workload balance between XCDs, and L2 caching for consecutive sequence blocks and grouped query heads.
The current grid traversal order (batch, head q, seqlen) essentially handles workload balancing between XCDs (round robin of assigning workgroups to XCDs increments batch id and head q id before seqlen id => assigned workgroups have most likely the same workload as workload only changes based on seqlend id). This brings benefit especially with the "bshd" layout, where we might otherwise have significantly imbalanced workloads between XCDs.
But this traversal order significantly reduces L2 caching (observed as lowered L2 cache hit rate) because consecutive seqlen blocks are unlikely to be assigned concurrently to the same XCD. This hurts the performance with the "thd" layout, where we don't even benefit from the load balancing, because the variable sequence lengths already take care of that.
