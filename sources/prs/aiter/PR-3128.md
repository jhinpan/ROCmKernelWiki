# hsa/gfx942/mla: fix BF16 mla_qh8 LDS size + add FP8 mla_qh8 kernel

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3128](https://github.com/ROCm/aiter/pull/3128) · **Merged:** 2026-05-19 · **Author:** @alexioslyrakis-amd

**Inclusion reason:** keyword 'mfma'

## Summary (from upstream PR description)

Summary
Two fixes for MLA qh8 (8 query heads, GQA ratio 8:1) kernels on gfx942 (MI300X):
1. BF16 LDS size fix
mla_a16w16_qh8_qseqlen1_gqaratio8_v3.co declared group_segment_fixed_size: 163840 (160 KB), exceeding the gfx942 hard limit of 64 KB. The HIP runtime silently rejected the kernel at registration, causing hipModuleLaunchKernel to return hipErrorIllegalState. The kernel had never been functional on MI300X.
Fix: Rebuilt with group_segment_fixed_size: 65536.
2. FP8 kernel (new)
Add mla_a8w8_qh8_qseqlen1_gqaratio8_v1.co — the FP8 E4M3FNUZ variant adapted from the BF16 kernel. Key changes from BF16:

MFMA instruction: v_mfma_f32_16x16x32_fp8_fp8 (K=32, 18 iterations vs BF16's 36)
K LDS layout: ds_write_b64/ds_read_b64 with halved spacing constants for 1-byte elements
Q LDS read: ds_read_b64 with corrected group stride for FP8 element size
K ACC refresh: Bulk K_lds_rd at cl_gemm0/cl_gemm1 end with part=0/part=1 wave-parity split
CKV preload scheduling: pa_fuse_alu starts CKV loads from actual cl_gemm0 count (5 for FP8 vs 8 for BF16), with a drain loop for remaining loads
V transpose: FP8-specific CKV_V_tr packing 4 bytes per dword
Descale factors: descale_q * descale_k baked into
