# [CK_TILE] Fix bpreshuffle compile failure due to stale CShuffleEpilogueProblem arg

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2811](https://github.com/ROCm/aiter/pull/2811) · **Merged:** 2026-04-22 · **Author:** @DDEle

**Inclusion reason:** kernel path '3rdparty/composable_kernel'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
CK PR ROCm/rocm-libraries#5863 removed TiledMMAPermuteN_ from CShuffleEpilogueProblem template parameters. This broke the build of module_gemm_a8w8_bpreshuffle_cktile when using the updated CK.
Technical Details
In csrc/cktile_gemm_a8w8_bpreshuffle/include/gemm_a8w8_bpreshuffle_cktile_common.cuh, the CShuffleEpilogueProblem instantiation had a trailing false argument that previously mapped to TiledMMAPermuteN_=false. After CK PR #5863, the TiledMMAPermuteN_ parameter was removed, so the false now maps to BlockedXDLN_PerWarp_=0 (an index_t), which causes an integer division by zero during template instantiation (NumNXdlPerWavePerShuffle / BlockedXDLN_PerWarp), reported as a substitution failure.
Fix: remove the stale false argument so BlockedXDLN_PerWarp_ falls back to its default value of 1.
Test Plan
Run op_tests/test_gemm_a8w8.py with the previously failing case:
python3 test_gemm_a8w8.py -d bf16 -q fp8 -mnk 192,1280,8192 --pad_a 128
