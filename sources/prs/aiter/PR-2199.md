# Enhance fused_qk_norm_rope_cache_quant functions by adding rotary_dim

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2199](https://github.com/ROCm/aiter/pull/2199) · **Merged:** 2026-03-20 · **Author:** @zhentaocc

**Inclusion reason:** kernel path 'aiter/ops/fused_qk_norm_mrope_cache_quant.py'; keyword 'attention'

## Summary (from upstream PR description)

Description
Add rotary_dim parameter to fused_qk_norm_rope_cache_pts_quant_shuffle to support partial rotary embedding handling. Update relevant C++ and Python files to accommodate this change, including new tests for partial rotary embeddings.
Motivation

Qwen3.5 (and its MoE variant) uses a hybrid attention architecture where head_dim=256 but only a fraction of each head receives rotary position embeddings. The model config specifies partial_rotary_factor=0.25, which means rotary_dim = int(256 * 0.25) = 64. During the attention forward pass, RoPE should only be applied to the first 64 elements of each Q/K head vector, while the remaining 192 elements pass through unchanged after RMSNorm.
In the SGLang model implementation (sglang/srt/models/qwen3_5.py), the fused kernel is called with rotary_emb.rotary_dim (line 711):
aiter.fused_qk_norm_rope_cache_pts_quant_shuffle(
    qkv, qw, kw, cos_sin, positions_1d,
    num_tokens, num_heads_q, num_heads_k, num_heads_v, head_size,
    rotary_emb.is_neox_style, eps,
    q_out, k_cache, v_cache, slot_mapping,
    k_scale, v_scale,
    k_out, v_out, True,
    use_shuffle_layout, block_size, x,
    rotary_emb.rotary_dim,  # <-- partial rotary:
