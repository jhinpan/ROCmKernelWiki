# Fix accuracy issues in top-p sampling kernels

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2035](https://github.com/ROCm/aiter/pull/2035) · **Merged:** 2026-02-12 · **Author:** @kliuae

**Inclusion reason:** kernel path 'csrc/cpp_itfs/sampling/sampling.cuh'; keyword 'flash'

## Summary (from upstream PR description)

Motivation
This PR addresses and fixes issues in aiter's top-p sampling kernels.
In aiter's top-p rejection sampling, torch generator is used to generate random numbers from which pivots are selected. However, when running these top-p sampling kernels under TP settings, different ranks occasionally sample different tokens at the same generation step, despite receiving identical probability vectors. This causes corrupted generation outputs in inference frameworks.
This issue manifests in vLLM's use of top-p sampling kernels. As reported in vllm-project/vllm#32413, this leads to repetitive generation patterns on models like DeepSeek-R1. Additionally, lm_eval shows accuracy degradation when using top-p or top-k+top-p sampling.

Technical Details
This PR identifies and fixes two specific issues:
Out-of-sync ranks
The RNG reads the seed and offset but fails to update them after consumption, causing RNG states to become out of sync across ranks and generating repetitive outputs. Following flashinfer's approach, this PR manually updates the offset based on inputs that are identical across all ranks. After consuming random numbers, it explicitly invokes set_state to advance the offset by t
