# [TRITON] mHC-post: Apply post-stream and res-stream mixing

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2967](https://github.com/ROCm/aiter/pull/2967) · **Merged:** 2026-05-13 · **Author:** @waqahmed-amd-fi

## Summary (from upstream PR description)

Co-authors: @waqahmed-amd-fi @anhminhnguyenhoang
Motivation
Implements the post-mix step of mHC (manifold-constrained Hyper Connection) (arXiv:2512.24880v2) as a fused Triton kernel for AMD Instinct GPUs (MI300X / MI355X). Companion to  mhc_pre, they fuse one full mHC layer.
mhc_post combines the layer output (layer_input, x) with the multi-stream residual via the coefficients produced by mhc_pre:
out[m, j, c] = post_mix[m, j] * x[m, c] + sum_h comb_mix[m, h, j] * residual[m, h, c]

i.e. one bf16/fp16 GEMV per stream j over the n source heads, plus a per-token broadcast of the post-mix gate over x.
Technical Details
mhc_post() exposes a single fused Triton kernel _mhc_post_kernel (aiter/ops/triton/_triton_kernels/fusions/mhc.py):

Persistent grid (cdiv(M, BLOCK_M),). Each program owns one M-tile and loops internally over C in BLOCK_C-sized chunks. Reduces launch grid by C / BLOCK_C.
Per-token coefficient hoisting. post_mix (BLOCK_M, n) and the comb_mix rows (BLOCK_M, n_dst) are loaded once per program into a register-resident tuple to eliminates ~C/BLOCK_C × redundant reloads of the small per-token matrices.
