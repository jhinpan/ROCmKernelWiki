# [gfx942]Add new GEMM configuration files for DSKR1

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2024](https://github.com/ROCm/aiter/pull/2024) · **Merged:** 2026-02-12 · **Author:** @zhentaocc

**Inclusion reason:** kernel path 'aiter/ops/triton/configs/gemm/gfx942-GEMM-A8W8_BLOCKSCALE-N=2112-K=7168.json'; keyword 'gemm'

## Summary (from upstream PR description)

For N=3072-K=1536 N=7168-K=2048, CK implementation shows better performance, however it doesn't perform well on N=2112-K=7168. On SGLang side, we might consider tune CK N=2112-K=7168 and call CK gemm instead.

Introduced three new JSON configuration files for GEMM operations:

gfx942-GEMM-A8W8_BLOCKSCALE-N=2112-K=7168.json
gfx942-GEMM-A8W8_BLOCKSCALE-N=3072-K=1536.json
gfx942-GEMM-A8W8_BLOCKSCALE-N=7168-K=2048.json


Each file contains detailed settings for different matrix dimensions, including block sizes, group sizes, and warp configurations.
These configurations aim to optimize performance for specific matrix multiplication scenarios.

Motivation
The default A8W8 blockscale GEMM configuration (gfx942-GEMM-A8W8_BLOCKSCALE.json) provides generic tuning parameters that work across a wide range of matrix shapes. However, DeepSeek-V3/R1 MLA attention uses specific (N, K) shapes during decode that are not well served by the generic config. Adding shape-specialized GEMM configurations allows the Triton autotuner to select optimal tile sizes, split-K factors, and warp counts for these critical decode-path GEMMs, improving end-to-end decode throughput on MI300X (gfx942).
