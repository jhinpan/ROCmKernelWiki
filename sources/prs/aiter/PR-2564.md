# fix(hip): launch FMHA Philox, sampling, and MM kernels on current stream

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2564](https://github.com/ROCm/aiter/pull/2564) · **Merged:** 2026-04-01 · **Author:** @kkHuang-amd

**Inclusion reason:** kernel path 'csrc/ck_tile_gemm_moe_2stages/moe_cktile2stages.cu'; keyword 'gemm'

## Summary (from upstream PR description)

Summary

FMHA: ParsePhiloxCudaState / hipLaunchKernelGGL now uses the same HIP stream as mha_fwd / mha_bwd (at::hip::getCurrentHIPStream()) on both asm and CK py_itfs paths.
sample_kernels: Greedy / random / mixed / exponential sampling paths use <<<grid, block, 0, stream>>> instead of omitting the stream argument.
custom_kernels: MMGPUKernel passes the active stream into the matrixMultiplyShared kernel launch.
moe_cktile2stages: Remove no-op at::hip::getCurrentHIPStream() calls.

Related to stream-ordering issues such as ROCm/aiter#2520 when callers use non-default streams (e.g. overlap scheduling).
Motivation
Kernels launched on the default stream (stream 0) or with an explicit null stream are not ordered with respect to work queued on the current PyTorch HIP stream. That breaks correctness when users run AITER ops on a non-default stream or overlap execution with other stream-ordered work.
This PR aligns Philox-related FMHA launches, sampling kernels, and the shared matmul helper with the current HIP stream used by the surrounding ATen/PyTorch context, so ordering matches mha_fwd / mha_bwd and other stream-aware paths.
