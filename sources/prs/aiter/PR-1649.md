# Add FP8 support for batch_prefill with per-tensor quantization

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1649](https://github.com/ROCm/aiter/pull/1649) · **Merged:** 2025-12-30 · **Author:** @poyenc

**Inclusion reason:** kernel path '3rdparty/composable_kernel'; keyword 'attention'

## Summary (from upstream PR description)

Summary
This PR adds FP8 (float8_e4m3) support to the batch_prefill kernel with per-tensor quantization, enabling efficient mixed-precision attention for paged KV cache scenarios.
Changes


Core Implementation:

Extended mha_batch_prefill to support FP8 input with BF16 output (fp8bf16 mode)
Added per-tensor quantization support via q_descale, k_descale, v_descale parameters
Updated kernel selection logic to handle FP8 data type and quantization scale types



API Changes:

Added optional q_descale, k_descale, v_descale parameters to mha_batch_prefill_func
Updated C++ interface to support quant_scale_enum (per-tensor vs no-scale)
Extended Python bindings with descale parameters



Testing:

Added comprehensive FP8 test suite (test_batch_prefill_fp8_output) comparing FP8 vs BF16 kernels
Added cross-validation test comparing batch_prefill (paged) vs flash_attn_varlen implementations
Verified correctness across multiple configurations (causal/non-causal, various sequence lengths, logits



Test Plan
All existing batch_prefill tests pass

✅ New FP8 tests validate output accuracy within threshold (max_diff < 0.055)
✅ Cross-validation between batch_prefill and flash_attn_varlen implementa
