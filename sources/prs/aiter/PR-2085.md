# pa_decode_gluon_aot C++ api

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2085](https://github.com/ROCm/aiter/pull/2085) · **Merged:** 2026-03-16 · **Author:** @amd-yilizhao

## Summary (from upstream PR description)

Triton paged attention decode (gluon) C++ API
Motivation
aiter's Triton-based paged attention decode kernels are currently only accessible via Python. C++ inference frameworks cannot use them without a Python runtime in the serving path. This PR exposes the kernels as a C++ API to enable direct integration.
Usage scenario
The API is packaged as a shared library (pa_decode_gluon_aot_lib.so). C++ callers link against it and invoke aiter::pa_decode_gluon_aot() with standard PyTorch C++ tensors.
Performance implications

The underlying GPU kernels are identical to the Python path -- no performance difference in kernel execution.
The C++ dispatch path avoids Python interpreter and GIL overhead, which benefits latency-sensitive serving scenarios with high request throughput.
First invocation per kernel variant incurs a one-time Triton JIT compilation cost; subsequent calls use cached kernel handles with negligible dispatch overhead.
