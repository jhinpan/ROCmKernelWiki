# Add fp8 mla decode kernel for sub_kv=64, sub_qh=8 (gqa_ratio=8, qseql…

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3014](https://github.com/ROCm/aiter/pull/3014) · **Merged:** 2026-05-06 · **Author:** @JohnNikolay84

**Inclusion reason:** kernel path 'aiter/mla.py'; keyword 'fp8'

## Summary (from upstream PR description)

csrc/py_itfs_cu/asm_mla.cu: new gqa_ratio==8 fp8/fp8 dispatch branch setting sub_Q=8 and config_max_seqlen_q=1 to match the kernel's per-TG Q tile size.
hsa/gfx950/mla/mla_asm.csv: register the new kernel object.
aiter/mla.py: add 8: 64 to get_block_n_fp8 so the metadata picker knows the per-split kv block size for nhead=8.
op_tests/test_mla.py: include nhead=8 in the fp8 decode test path.

Accuracy parity with the nhead=16 padded path was confirmed on hardware (cos_diff within +/-15% across ctx_len in {256, 1024, 4096} and batch in {1, 16}, all far below the 3e-2 fp8 threshold).
Motivation
We do have bf16 kernel with qh8 support that gives a good improvement for bf16 kv cache compared to padding solution.
Technical Details
This is a rework of the SUB_Q=16 existing kernel to support SUB_Q=8 for fp8 kv cache.
