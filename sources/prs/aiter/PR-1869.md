# Optimize moe_align_block_size kernel with O(E) shared memory, average improvement 18% across all configs

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1869](https://github.com/ROCm/aiter/pull/1869) · **Merged:** 2026-01-20 · **Author:** @irvineoy

**Inclusion reason:** kernel path 'csrc/kernels/moe_align_block_size_kernels.cu'; keyword 'moe'

## Summary (from upstream PR description)

Motivation
This PR addresses a critical bug and provides significant performance improvements for the moe_align_block_size_kernel:

Fix showstopper bug: The kernel previously failed for configurations with ≥128 experts due to exceeding the MI300X's 65KB shared memory limit per block
Performance optimization: Improve kernel efficiency across all expert configurations through better memory layout and parallelization

Technical Details
Core optimization: Reduced shared memory complexity from O(E²) to O(E)
Before (csrc/kernels/moe_align_block_size_kernels.cu):

Used 2D array tokens_cnts[threads][experts] requiring (E+1) × E × 4 bytes
Sequential counting within each thread, then accumulation across threads
For E=256: ~260KB shared memory  (exceeds 65KB limit)

After (this PR):

Simplified to three 1D arrays: expert_token_counts[E], cumsum[E+1], write_positions[E]
Parallel atomic counting using atomicAdd for token distribution
Clean 4-pass algorithm: (1) atomic counting, (2) prefix sum, (3) metadata write, (4) token scatter
For E=256: ~7KB shared memory  (97.3% reduction)

Shared memory savings:

E=64: 16.9KB → 1.0KB (93.9% reduction)
E=128: 67KB ❌ → 2.6KB ✅ (96.2% reduction, now support
