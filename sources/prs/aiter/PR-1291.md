# [FEAT] [Triton] Add transpose scale to the triton fused_rms_fp8_group_quant

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1291](https://github.com/ROCm/aiter/pull/1291) · **Merged:** 2025-11-04 · **Author:** @tjtanaa

**Inclusion reason:** kernel path 'aiter/ops/triton/fused_fp8_quant.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation

In vLLM, we are using torch compile to automatically replace the operation with fused function.
Currently the function is not compatible with the ck bpreshuffle block scaled gemm kernel which expect
x_scale_t = x_scale.transpose(0, 1).contiguous().view(*x_scale.shape)

  
    
      aiter/op_tests/test_gemm_a8w8_blockscale.py
    
    
         Line 71
      in
      3d6afb2
    
  
  
    

        
          
           x_scale_t = x_scale.transpose(0, 1).contiguous().view(*x_scale.shape) 
        
    
  


So, vLLM PR ([Rocm][torch.compile] Adding layernorm + fp8 block quant and silu + fp8 block quant for Aiter ): vllm-project/vllm#25693 is conflicting with vLLM PR ([ROCm] [AITER] Add block scaled bpreshuffle gemm) : vllm-project/vllm#27652
When this vLLM PR ([ROCm] [AITER] Add block scaled bpreshuffle gemm) : vllm-project/vllm#27652 ,
we found that this overhead is too large that if not fused with the kernel, end-to-end integration performance degrade.
x_scale.transpose(0, 1).contiguous().view(*x_scale.shape)
That is why aiter_per1x128_quant( input_2d.contiguous(), quant_dtype=dtypes.fp8, transpose_scale=self.is_weight_swizzled)
also support an argument transpose_s
