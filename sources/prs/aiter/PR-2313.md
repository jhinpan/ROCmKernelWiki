# Add blockPerCu support for CKTile GEMMs and CKTile MOE tuning

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2313](https://github.com/ROCm/aiter/pull/2313) · **Merged:** 2026-03-20 · **Author:** @amd-yashagar

**Inclusion reason:** kernel path 'aiter/configs/a8w8_blockscale_tuned_gemm.csv'; keyword 'gemm'

## Summary (from upstream PR description)

Add configurable blockPerCu (1-4) to CKTile GEMM kernels (blockscale, bpreshuffle, MOE) and add CKTile to MOE tuner.
Motivation
CKTile GEMM kernels currently use a fixed blockPerCu, which may not be optimal for all problem shapes. This PR extends the tuning search space to include blockPerCu variants.
Technical Details

Expand CKTile kernel instances with blockPerCu 1-4 via expand_blockpercu()
Add kernel_name-based dispatch to CKTile MOE gemm1/gemm2
Add CKTile stage1/stage2 task generation to gemm_moe_tune.py
Add --blockPerCu CLI arg to blockscale, bpreshuffle, and MOE tuners
Only rows where a blockPerCu improved over the previous best were updated in tuned configs

Test Plan
All tuning performed on MI355X with blockPerCu values 1–4.
To isolate the effect of blockPerCu from other tuning changes (e.g. different CKTile tile sizes winning over CK), each changed shape was re-run with CKTile blockPerCu=1 only as a baseline. The tables below report the pure blockPerCu gain = CKTile(BPC=1) / CKTile(BPC=best).
Blockscale GEMM (a8w8_blockscale_tuned_gemm.csv)
