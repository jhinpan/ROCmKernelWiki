# [MoE] Align FlyDSL MXFP4 rounding

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3153](https://github.com/ROCm/aiter/pull/3153) · **Merged:** 2026-05-13 · **Author:** @XiaobingSuper

**Inclusion reason:** kernel path 'aiter/ops/flydsl/kernels/mixed_moe_gemm_2stage.py'; keyword 'gemm'

## Summary (from upstream PR description)

Summary

Align FlyDSL fused FP4 conversion with the MXFP4 reference/HIP round-to-nearest-even behavior.
Cover both the split-K post-activation quant kernel and the stage1 fused quant epilogue.
Add a focused FlyDSL Swiglu fused FP4 quant test that checks FP4 payload and sorted E8M0 scale bytes.

Accuracy impact

GPT-OSS Swiglu a4w4 MoE operator, token=1024, model_dim=3072, inter_dim=3072, E=128, topk=4: logits cosine diff improved from ~8.30e-4 to 6.16e-6.
This is about a 135x reduction in operator-level output error for the affected fused FP4 path.
Additional GPT-OSS a4w4 checks after the fix stayed low: token=512 ~6.15e-6, token=2048 ~6.18e-6.

Test plan

HIP_VISIBLE_DEVICES=1 pytest -q op_tests/flydsl_tests/test_silu_and_mul_fq.py

GPT-OSS E2E smoke: ISL=1024, OSL=1024, concurrency=8, 80/80 successful requests, output throughput 1554.69 tok/s, mean TPOT 4.97 ms.
