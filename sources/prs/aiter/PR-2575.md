# Fix _gluon_deepgemm_fp8_paged_mqa_logits instr_shape compatibility

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2575](https://github.com/ROCm/aiter/pull/2575) · **Merged:** 2026-04-03 · **Author:** @1am9trash

**Inclusion reason:** kernel path 'aiter/ops/triton/gluon/pa_mqa_logits.py'; keyword 'mfma'

## Summary (from upstream PR description)

cc @Jacob0226
Motivation

In triton PR#8213, gluon MFMA layout validation was updated to require a 3D instruction shape (M, N, K). As a result, on newer triton versions (e.g. triton 3.6.0 used in sglang), the _gluon_deepgemm_fp8_paged_mqa_logits kernel can fail during compilation when it still passes a 2D shape.
Technical Details

Following the existing compatibility pattern already used in aiter, this change adds an explicit 2D/3D layout split in _gluon_deepgemm_fp8_paged_mqa_logits:

Use 2D instr_shape=[16, 16] on older triton behavior.
Use 3D instr_shape=[16, 16, 32] on newer triton behavior.
