# [OPUS] tiled scaled MFMA and mfma_adaptor_swap_ab fixes

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2384](https://github.com/ROCm/aiter/pull/2384) · **Merged:** 2026-03-23 · **Author:** @kaiyang-1

**Inclusion reason:** keyword 'mfma'

## Summary (from upstream PR description)

Summary

Add tiled_mma_adaptor overloads that forward runtime scale_a / scale_b to the underlying MMA for gfx950-style scaled MFMA (f8f6f4), mirroring the existing non-scaled array/vector/two-arg paths.
Fix mfma_adaptor_swap_ab two-argument operator(): it previously called the three-arg overload with (b, a, ...), which double-swapped operands relative to base::operator()(b, a, ...). It now calls (a, b, ...) so AB swap semantics match the three-arg path.
Use grpk_b in mfma_adaptor::shape_b() for consistency with the documented B-tensor shape (equivalent to grpk_a).
Add scaled operator() forwards on mfma_adaptor_swap_ab so MMA{}(…, scale_a, scale_b) remains valid when the tiled path is used with the swap adaptor (derived-class operator() would otherwise hide mfma’s scaled overloads).

Motivation
Enable tiled kernels to use scaled MFMA through the same adaptor API as wave-level mfma, and correct swap-adaptor forwarding for both standard and scaled calls.
