# Add fused bias support for GMM and bias‑gradient/accumulate support for persistent TGMM

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1541](https://github.com/ROCm/aiter/pull/1541) · **Merged:** 2025-12-11 · **Author:** @sudhu2k

**Inclusion reason:** kernel path 'aiter/ops/triton/_triton_kernels/gmm.py'; keyword 'moe'

## Summary (from upstream PR description)

Motivation
This PR extends the Triton GMM/TGMM kernels and their wrappers to better match common MLP and MoE use‑cases:
GMM: support an optional, per‑expert bias term in the forward pass so that GMM can directly model out = lhs @ rhs + bias without a separate kernel.
TGMM: expose fused bias gradient computation and an ACCUMULATE mode in the persistent TGMM kernel to make it usable for efficient backward passes (e.g. MoE expert bias gradients, multi‑step accumulation) while keeping numerical behavior well‑tested against PyTorch.
These changes reduce redundant launches, enable fused gradient computation, and bring the Triton operators closer to how PyTorch Linear/MoE layers are typically used in end‑to‑end training.
Technical Details

Added an optional bias argument to the gmm kernel, allowing each group to add a bias vector to its output. The kernel and its Python wrapper now validate the shape, dtype, and memory layout of bias.
