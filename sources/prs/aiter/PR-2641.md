# [CK_TILE] Temporarily remove batch prefill KV cache overflow asserts

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2641](https://github.com/ROCm/aiter/pull/2641) · **Merged:** 2026-04-08 · **Author:** @Jeff-Huang

**Inclusion reason:** kernel path '3rdparty/composable_kernel'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation
CK commit 6e558658e (rocm-libraries#4999) added int32 overflow assertions in FmhaBatchPrefillWithPagedKVCacheKernel that abort the SGLang server process when the per-layer KV cache exceeds ~4GB with page_size < kN0 (128). This is easily triggered on MI300X (192GB HBM) with small/medium models — e.g., Llama-3.2-1B with page_size=1 allocates 6.3M tokens → 6GB per-layer K cache, causing assert() → abort() at server startup.
The assertions are correct (they catch real int32 offset overflow), but the fix for page_size < kN0 is not yet ready. This PR temporarily removes the asserts to unblock serving while the proper fix (per-tile SRD rebase) is completed in a follow-up PR.
Fixes: #2608
Related: #2517
Technical Details
Updates CK submodule to include rocm-libraries#6201, which removes 28 lines of assert() checks from fmha_batch_prefill_kernel.hpp (two identical blocks for the two MakeKargs overloads).
Note: Without the asserts, the overflow may produce silent incorrect results for page_size < kN0 with KV cache > 4GB. A follow-up PR will add proper overflow handling via per-tile SRD rebase with 64-bit pointer arithmetic.
