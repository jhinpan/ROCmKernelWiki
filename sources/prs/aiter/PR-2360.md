## Summary (from upstream PR description)

Reopening the PR from #2267 after git history related aiter/main changes.
This PR does the following:

Extend the FP8 scaling to FP8 x FP8 attention as well, not just bf16 x fp8
Add support for q scaling
Fuse the QKV descaling with the existing ops to hide the cost
Code cleanup
Extending tests to better check the correctness for the descaling/scaling
Update/simplify the kernel API while keeping the wrapper API same
Instead of inverting out_scale before kernel call and multiplying inside, divide by within the kernel, to not cause any extra torch call

Main goal is to be able to apply scaling for any FP8 input/output to better preserve accuracy, if the scales/descales provided, while not causing any extra VALU/type conversion.
