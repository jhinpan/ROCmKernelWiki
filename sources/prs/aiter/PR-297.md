# [RFC] enhance the fmoe heuristic rule for block_n selection

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#297](https://github.com/ROCm/aiter/pull/297) · **Merged:** 2025-04-18 · **Author:** @sijiac

**Inclusion reason:** kernel path 'csrc/py_itfs_cu/asm_fmoe.cpp'; keyword 'moe'

## Summary (from upstream PR description)

The current implementation of sub_X_cnt doesn’t account for cases where most experts are skipped. For example, when token_cnt = 1, ideally we should select the smallest block_n size to launch more parallel CTAs. However, the existing heuristic chooses 512 (the largest available size).
The root cause is that although the sorting kernel skips padding for empty experts, the length of sorted_expert_ids remains unchanged. In this change, we propose selecting block_n based on an estimated value derived from token_cnt. While we could directly retrieve the concrete token count from a tensor value like num_valid_ids[0], this approach might involve additional D2H operations and potentially break the CUDA graph.
With this adjustment, we’ve observed around a 2x speed-up (135us to 77us)for shapes with small M values.
