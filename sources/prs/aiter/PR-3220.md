# Fix checkclose and refactor tuner

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3220](https://github.com/ROCm/aiter/pull/3220) · **Merged:** 2026-05-26 · **Author:** @yzhou103

**Inclusion reason:** kernel path 'aiter/configs/a4w4_blockscale_tuned_gemm.csv'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
Fix two pre-existing tuner correctness gaps and give unit-test authors a
single opt-in flag for fail-fast accuracy checks.

Tuner partial-write masking: tuning candidates could inherit stale
output values from previously-run kernels. A buggy kernel that only
partially writes the output tensor (e.g. some FlyDSL bpreshuffle
variants) would appear "correct" during tuning, then fail later in
run_config validation.
generate_data fragility: returned positional tuples with magic
integer index lists, making call sites hard to read and easy to break.
checkAllclose catastrophic detection (#3220 v1 design) used a
default relative-magnitude heuristic that fired false positives on
legitimate permutation cases (sorted topk_ids with ties, sort+gather
weights with degenerate scores, byte-viewed fp4 tensors), blocking
Standard Tests (1 GPU) in CI.
