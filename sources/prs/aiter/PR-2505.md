# [Triton] Add sliding window support for sink attention

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2505](https://github.com/ROCm/aiter/pull/2505) · **Merged:** 2026-04-02 · **Author:** @kyle-256

**Inclusion reason:** kernel path 'aiter/ops/triton/_triton_kernels/attention/mha.py'; keyword 'attention'

## Summary (from upstream PR description)

Motivation
The Triton MHA path already supports sink attention, but it cannot be combined with a left sliding window today. That makes it difficult to validate and use sink + sliding-window attention in downstream integrations. This PR adds the missing left-window support while keeping the current restriction that window_size_right is still unsupported.
Technical Details

thread window_size_left through the Triton MHA wrapper into the forward kernel and one-kernel backward kernel
keep rejecting window_size_right != -1, so this change only enables the supported left-window use case
apply sliding-window masking in both forward and backward Triton kernels
add guards for fully masked blocks to avoid NaNs when a tile falls completely outside the valid window
add regression coverage in op_tests/triton_tests/attention/test_mha.py for sink + sliding window, and for sliding window without sink
