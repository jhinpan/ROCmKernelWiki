# [BUG] Fix ck-tile blockscale GEMM to use the current HIP stream

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2520](https://github.com/ROCm/aiter/pull/2520) · **Merged:** 2026-03-31 · **Author:** @zyzshishui

**Inclusion reason:** kernel path 'csrc/ck_gemm_a8w8_blockscale/include/gemm_a8w8_blockscale_cktile_common.cuh'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
Related to sgl-project/sglang#21566, fixes a stream-ordering bug in the ck-tile A8W8 blockscale GEMM path.
Technical Details
Previously, the kernel was launched with ck_tile::stream_config{nullptr, ...}, which forces execution onto the default stream. When the caller runs on a non-default HIP stream (for example, under overlap scheduling in sglang), this can break producer/consumer ordering and lead to incorrect results.
Test Plan

Test Result
After applying the change, the garbage output issue solved, and Qwen3.5-397B-A17B-FP8 got 89.9 on GQPA.
Note
It would also be worth auditing other kernels for similar patterns (nullptr/default-stream launches, or places that fetch the current stream but do not actually launch on it), since there may be other latent stream-safety issues elsewhere.
