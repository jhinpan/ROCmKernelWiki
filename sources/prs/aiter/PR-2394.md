# [OPUS] enable gfx1250 support for OPUS tests

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2394](https://github.com/ROCm/aiter/pull/2394) · **Merged:** 2026-03-22 · **Author:** @carlushuang

**Inclusion reason:** kernel path 'op_tests/opus/device/setup.py'; keyword 'mfma'

## Summary (from upstream PR description)

Summary
Enable gfx1250 (RDNA4) support in the OPUS header-only library, covering WMMA instructions, async load, waitcnt, and compilation speedups via architecture guards.
Changes to opus.hpp

WMMA instruction support (gfx1250): Add struct wmma with dispatch macros for all gfx1250 WMMA builtins — f16/bf16/f32 16x16x32, fp8/bf8 16x16x64 and 16x16x128 variants. Add wmma_adaptor, wmma_adaptor_swap_ab, and make_wmma() factory functions mirroring the existing mfma API.
Replace inline asm with LLVM IR intrinsics: gfx1250 wait instructions (s_wait_loadcnt, s_wait_dscnt, s_wait_storecnt, s_wait_kmcnt, s_wait_asynccnt, s_wait_tensorcnt) now use __asm("llvm.amdgcn.s.wait.*") bindings instead of inline assembly, exposed as s_wait_*<number<cnt>>() template functions matching native ISA.
gfx1250 async_load: Implement global_load_async_to_lds via __builtin_amdgcn_global_load_async_to_lds_b{8,32,64,128} builtins (global flat addressing, not buffer rsrc).
Architecture guards for faster compilation: Guard struct mfma / dispatch macros / type aliases with __GFX9__, and struct wmma / dispatch macros / type aliases with __gfx1250__. Host pass (!__HIP_DEVICE_COMPILE__) sees both for linking.
