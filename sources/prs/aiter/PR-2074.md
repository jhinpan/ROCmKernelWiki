# Add ENABLE_CK build option for CK-free builds

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2074](https://github.com/ROCm/aiter/pull/2074) · **Merged:** 2026-03-05 · **Author:** @sunway513

**Inclusion reason:** kernel path 'aiter/jit/core.py'; keyword 'kernel'

## Summary (from upstream PR description)

Summary
Adds ENABLE_CK environment variable (default=1) to control whether Composable Kernel is required at build time. When ENABLE_CK=0, AITER builds only non-CK modules (Triton kernels, C++ bindings, V3 ASM via shim headers), reducing build time from ~35 minutes to ~8 minutes.
This is the foundation PR for the CK-free build initiative tracked in #2073. Subsequent PRs will add Python operator fallbacks, shim headers for FMHA V3 ASM, and Triton prebuild infrastructure.
Changes
setup.py

New ENABLE_CK env var (default=1) — set to 0 for CK-free builds
Skip 3rdparty/composable_kernel copying when ENABLE_CK=0
CK directory assertion now conditional on ENABLE_CK
get_exclude_ops() calls core._get_ck_exclude_modules() to auto-exclude CK-dependent modules
MHA variant prebuild (PREBUILD_KERNELS=1) gated on ENABLE_CK (requires CK source)

aiter/jit/core.py

New _get_ck_exclude_modules() function — identifies CK-dependent modules via:

Config pattern matching (references to CK_DIR, py_itfs_ck, gen_instances, generate.py)
Hardcoded set of 20 modules with deep ck_tile:: source-level dependencies
V3 ASM modules exempted (they build with lightweight shim headers)


build_module(): CK include paths
