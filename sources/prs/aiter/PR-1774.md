# [PA] Optimization: Remove Query/Output Transpose Kernels by Direct 5D Tensor Access in PA Decode Gluon

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1774](https://github.com/ROCm/aiter/pull/1774) · **Merged:** 2026-01-14 · **Author:** @yanguahe

**Inclusion reason:** kernel path 'aiter/ops/attention.py'; keyword 'mfma'

## Summary (from upstream PR description)

Motivation
The previous implementation of the Paged Attention Decode Gluon kernel required two separate transpose operations:

Query Transpose: Transforming query tensor from [batch_size * query_length, num_query_heads, head_size] to [batch_size, num_kv_heads * query_length * query_group_size, head_size] before attention computation
Output Transpose: Transforming output tensor back from gluon layout to standard layout after attention computation

These transpose operations introduced additional memory bandwidth overhead and kernel launch latency, especially for Multi-Token Prefill (MTP) scenarios where query_length > 1.
This PR eliminates these transpose kernels by modifying the attention kernels to directly access tensors in their native 5D layout, reducing memory traffic and improving overall throughput.
Technical Details
Core Changes


Removed Transpose Kernels:

Removed transpose_query_gluon_kernel and transpose_query_gluon function
Removed transpose_output_gluon_kernel and transpose_output_gluon function



5D Tensor Layout Support:

Modified attention kernels to directly read query tensors in 5D format: [batch_size, query_length, num_kv_heads, query_group_size, head_size]
