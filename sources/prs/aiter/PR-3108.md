# [Misc] Add pid/pname to JIT build logs + DSv4-Pro a8w8 blockscale tuned configs

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3108](https://github.com/ROCm/aiter/pull/3108) · **Merged:** 2026-05-10 · **Author:** @valarLip

## Summary (from upstream PR description)

Summary
Two unrelated changes bundled together:
1. JIT build log readability (aiter/jit/core.py, aiter/jit/utils/file_baton.py)
The aiter JIT log lines for module build start/finish and FileBaton wait did not include any per-process identifier. When 8 tuner workers race on the same lock, the log shows interleaved messages with no way to tell which worker is doing the build vs. which ones are blocked.
Before:
```
[aiter] start build [module_xxx] under /...
[aiter] waiting for baton release at /.../lock_module_xxx
[aiter] waiting for baton release at /.../lock_module_xxx
```
After:
```
[aiter] [pid=2406910 pname=MainProcess] start build [module_xxx] ...
[aiter] [pid=2406925 pname=Process-3] waiting for baton release ...
[aiter] [pid=2406910 pname=MainProcess] finish build [module_xxx], cost 67.3s
```
Adds `os.getpid()` + `multiprocessing.current_process().name` to:

`aiter/jit/core.py`: `start build` and `finish build`
`aiter/jit/utils/file_baton.py`: `waiting for baton release`

2. DSv4-Pro a8w8 blockscale bpreshuffle tuned configs
New file: `aiter/configs/model_configs/dsv4_a8w8_blockscale_bpreshuffle_tuned_gemm.csv`
Three GEMM shapes detected as untuned in DeepSeek-V4-Pro server l
