# Fix indexing in cp_gather_indexer_k_quant_cache

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2954](https://github.com/ROCm/aiter/pull/2954) · **Merged:** 2026-05-08 · **Author:** @kliuae-amd

**Inclusion reason:** kernel path 'csrc/kernels/cache_kernels.cu'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation
In inferencing engines like ATOM and vLLM, kv caches of sparse MLA's top-k indexer are allocated with head size + 4 per block. In models like DeepSeek-V3.2 and GLM-5, this gives a kv cache block stride of 132.
The cp_gather_indexer_k_quant_cache_kernel uses 16-element vectors, packed as float4, to access global data shares.
However, currently the elements are indexed through packed vectors, and for KV cache blocks whose strides are not divisible by 16, this causes vector heads to land on truncated addresses, leading to incorrect data being read. This issue manifests as corrupted K tensors gathered, degrading inference accuracy.

Technical Details
This PR addresses this issue by replacing vector-based indexing with byte addressing to avoid landing vectors on truncated addresses when cache strides are not multiples of 16. GDS movements are still cast to dwordx4 to facilitate vectorized access.
