# Introduce asm 64x256 kernels for mi300

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2404](https://github.com/ROCm/aiter/pull/2404) · **Merged:** 2026-03-21 · **Author:** @JohnNikolay84

**Inclusion reason:** kernel path 'hsa/gfx942/fmoe/silu/fmoe_bf16_blockscaleFp8_g1u1_silu.csv'; keyword 'moe'

## Summary (from upstream PR description)

Motivation
This PR introduces a new bigger kernel for mi300, similar to mi355. 64x256
The kernel is expected to be used for a bigger token input > 4k where moe is bound by memory.
Technical Details
2 kernels are introduced, 64x256 persistent and 64x256 not-persistent. The persistent kernel is called psx which means it is using XCD aware scheduling. The assumption is that  mi300 GPU has 8 XCD blocks and with a bigger number of TGs per expert we try to put as many TGs from the same expert on one XCD as possible to improve L2 hit rate.
Test Plan
Run aiter tests for big token count for GLM-5-FP8 TP8 dims. xcd aware scheduling shows up as a better choice when token_cnt is sufficiently big to generate at least several TGs per expert. Especially if in TP8 mode we do not split GU. Otherwise it might be better to use non-ps kernels for moderate batch size or a regular persistent kernel. Or create a new 32x256 kernel with xcd aware scheduling.  There is a lot more that we can do for batches in the range 512-2048.
