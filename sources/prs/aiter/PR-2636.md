# Replace qseqlen fold with native qh64 kernel for nhead=64 decode on g…

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2636](https://github.com/ROCm/aiter/pull/2636) · **Merged:** 2026-04-08 · **Author:** @fangche123

**Inclusion reason:** kernel path 'aiter/mla.py'; keyword 'attention'

## Summary (from upstream PR description)

…fx950
Motivation
Previously, nhead=64 decode_qlen=1 on gfx950 used a "qseqlen fold" strategy that transformed (nhead=64, qseqlen=1) into (nhead=16, qseqlen=4) to reuse qh16_qseqlen4 kernels. This is no longer needed with the availability of native qh64_qseqlen1_gqaratio64_v3 kernels.  The new native qh64_qseqlen1_gqaratio64_v3 kernel handles nhead=64 directly without folding, fixing the small ctx_len NaN issue.
Technical Details

Add qh64_qseqlen1_gqaratio64_v3 persistent kernels (.co) with LSE support
Rename qh64_qseqlen4_gqaratio16 .co files to qh16_qseqlen4_gqaratio16_v3
Update mla_asm.csv with new kernel entries (Gqa=64, qSeqLen=1)
Add nhead=64 fp8 qseqlen=1 as natively supported in mla.py, attention.py,
v1_2_device.cuh, and test_mla_persistent.py
Remove all qseqlen_fold logic from Python, C++, and CUDA metadata code
Add fp8 gqa_ratio=64 dispatch path in asm_mla.cu

Test Plan
python3 op_tests/test_mla_persistent.py -b 256  --nhead 16,4 -d fp8 -kvd fp8 -lse -c [1024, 2048, 4096, 1, 2, 3]
python3 op_tests/test_mla_persistent.py -b 256  --nhead 64,1 -d fp8 -kvd fp8 -lse -c [1024, 2048, 4096, 1, 2, 3]
