# [opus] gfx1201/gfx1200 (RDNA4) support: parse + buffer rsrc + WMMA w32/w64

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3236](https://github.com/ROCm/aiter/pull/3236) · **Merged:** 2026-05-19 · **Author:** @carlushuang

**Inclusion reason:** kernel path 'op_tests/opus/device/test_opus_gmem_gfx1201.cu'; keyword 'wmma'

## Summary (from upstream PR description)

gfx1201 (Navi 48, RX 9070 XT) and gfx1200 (Navi 44) support in opus.hpp.
What this enables:

opus.hpp parses on gfx12 (fwd-decl adaptors, arch gates)
make_gmem<>.load/.store works (RDNA buffer rsrc config)
opus::wmma<> dispatches wave32 + wave64 16x16x16 variants
make_tiled_mma / partition_layout_* / wmma_adaptor work on gfx12
OPUS_GFX120X_IS_WAVE32 macro for constexpr wave32/64 detection
fp8/bf8 OCP format, bf16 hardware conversion for gfx12
All opus device + host tests pass on gfx1201, gfx950, gfx942

WMMA coverage (16x16x16):

wave32: f32<-f16, f32<-bf16, f16<-f16, bf16<-bf16, f32<-{fp8,bf8}x{fp8,bf8} (8 variants)
wave64: f32<-f16, f32<-bf16, f16<-f16, bf16<-bf16 (4 variants, -mwavefrontsize64)
Synthetic 16x16x32 (2x stacked) for both wave32 and wave64
Tiled WMMA via make_tiled_mma + partition_layout + gmem (f32<-f16, f32<-bf16)

Out of scope: gfx12-specific wmma_adaptor for asymmetric fragment layout (A row-dist, B/C col-dist). Current adaptor works because the shape/dim encoding computes correctly from the wmma struct params.
Tested on: RX 9070 XT (gfx1201), MI355 (gfx950), MI308 (gfx942) — all pass.
