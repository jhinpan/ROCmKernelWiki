## Summary (from upstream PR description)

Motivation
This PR addresses two issues discovered during Triton 3.7.0 compatibility testing:

torch.compile constexpr mutation regression — Triton 3.7.0 introduced a behavior change where tl.constexpr arguments in Triton kernels can be mutated during compilation, causing incorrect results when the same kernel is invoked multiple times with different parameters under torch.compile. A regression test (test_compile_constexpr_mutation.py) is added to catch this. and we update triton wheel for this issue.
Triton reinstall breaks older PyTorch — When torch < 2.9.1 is installed, reinstalling triton via install_triton.sh during setup.py can pull an incompatible version, breaking the environment. A guard is added to skip triton reinstall when torch < 2.9.1 is detected.

Technical Details

setup.py — Skip triton reinstall for torch < 2.9.1

Added _torch_version_below("2.9.1") guard before the triton install logic. When an older PyTorch is detected, setup.py prints a message and preserves the existing triton installation instead of invoking install_triton.sh, which could pull a wheel incompatible with the older torch ABI.
