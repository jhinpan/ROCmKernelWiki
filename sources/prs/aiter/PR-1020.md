# Replace multiprocessing.Pool with ThreadPoolExecutor in setup.py

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1020](https://github.com/ROCm/aiter/pull/1020) · **Merged:** 2025-09-24 · **Author:** @EmilienM

**Inclusion reason:** keyword 'rope'

## Summary (from upstream PR description)

Motivation
The multiprocessing.Pool usage violated multiprocessing guidelines by being
used at module level without proper guards. This caused fork-safety issues
and would break with spawn/forkserver start methods. ThreadPoolExecutor is
safer for this I/O-bound workload (hipcc subprocess calls) and eliminates
pickling concerns.
Fixes #980
