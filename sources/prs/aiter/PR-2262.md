# Introduce asm fmoe kernels that do not require bf16->fp8 quantization

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2262](https://github.com/ROCm/aiter/pull/2262) · **Merged:** 2026-04-24 · **Author:** @JohnNikolay84

**Inclusion reason:** kernel path 'aiter/configs/model_configs/qwen3next_80b_fp8_tuned_fmoe.csv'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
For qwen3-next model in TP4 mode there is no assembly kernel that can match h_dim=128. This PR is introducing one merged with quantization to improve latency. moe kernels are not compute bound and adding compute behind mem loads hides latency that comes with a standalone quantization.
Technical Details
This is a new asm kernel that supports 32x128/16x128 tiling and also embeds quantization for X, so it accepts X as bf16.
This approach beneficial only for model with smaller dimensions,  models like DS with > 7K model_dim will  benefit
much more from Split-K, therefore this optim. is applied heuristically only for models with model_dim <=2048.
Test Plan
qwen3-next and aiter unit tests ( dim=2048, h_dim=128, experts=512, topk=10)
