# [FIX] address overflow fix on fmha_bwd of gfx942/gfx950

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2189](https://github.com/ROCm/aiter/pull/2189) · **Merged:** 2026-03-06 · **Author:** @JaxChen29

**Inclusion reason:** keyword 'kernel'

## Summary (from upstream PR description)

Motivation
When running MHA backward pass with large tensors (e.g., batch=8, nhead=40, seqlen=75600+, hdim=128), buffer addresses can exceed the 32-bit range. The gfx950 SP3 assembly kernels compute buffer descriptor base addresses by accumulating tile, head, and batch offsets in a single 32-bit register (s_mul_i32 + s_add_u32), which silently truncates when the sum exceeds 2^32, causing incorrect memory accesses and wrong gradient outputs.
This PR applies the 64-bit address overflow fix to all FMHA backward ASM kernels on gfx950, matching the fix previously applied on gfx942.
Technical Details
SP3 assembly fix (14 files in prod_kernels/):
For each affected buffer (K, V, Q, dO, dK, dV, dQ, L, D), the fix separates the batch/group offset from the 32-bit base register and adds it to the buffer descriptor as a 64-bit addition with its own carry chain:
s_mul_i32        s_tmp0,      batch_idx,    batch_stride   // batch_low
s_mul_hi_u32     s_tmp1,      batch_idx,    batch_stride   // batch_high
s_and_b32        s_tmp1,      s_tmp1,       0xffff         // mask to 48-bit GPU address space
s_add_u32        buf[0],      buf[0],       s_tmp0         // SCC = carry
s_addc_u32       buf[1],
