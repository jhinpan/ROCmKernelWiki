# Respect MAX_JOBS environment variable with smart fallback

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1099](https://github.com/ROCm/aiter/pull/1099) · **Merged:** 2025-09-28 · **Author:** @andre-motta

**Inclusion reason:** keyword 'lds'

## Summary (from upstream PR description)

Summary
This PR fixes the issue where the MAX_JOBS environment variable was ignored, while maintaining backward compatibility through smart fallback logic.
Problem
The current setup.py had logic that would override user-specified MAX_JOBS values in certain conditions, causing:

User's explicit parallelism settings to be ignored
Excessive parallelism on high-core count machines when users tried to limit it
Build failures when users set MAX_JOBS to control resource usage

Solution
Modified the logic to:

Respect MAX_JOBS when set: If the user explicitly sets MAX_JOBS, use that value without override
Smart fallback: Only use getMaxJobs() auto-calculation when MAX_JOBS is not set
Maintain compatibility: Existing builds without MAX_JOBS continue to work as before

Testing
To reproduce the original issue:

Set MAX_JOBS=1 in environment
Run aiter build process
Before this fix: The setting could be overridden by auto-calculation
After this fix: Exactly 1 job is used, respecting the user's explicit setting

Benefits

✅ User control: Explicit MAX_JOBS settings are always respected
✅ Backward compatibility: Builds without MAX_JOBS work unchanged
