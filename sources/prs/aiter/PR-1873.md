# [CK_TILE] Fix Int32 Overflow in Deterministic FMHA BWD

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#1873](https://github.com/ROCm/aiter/pull/1873) · **Merged:** 2026-01-21 · **Author:** @DDEle

**Inclusion reason:** kernel path '3rdparty/composable_kernel'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation
This PR fixes an integer overflow issue in the deterministic FMHA backward implementation by changing batch/nhead stride variables from index_t (32-bit) to long_index_t (64-bit) for the dq_acc.
Note that dq_acc layout is changed from (nsplit, B, H, S, D) to (B, H, nsplit, S, D) due to the fact that only batch_stride_dq_acc and nhead_stride_dq_acc are promoted to long_index_t. It is because that promoting nsplits_stride_dq_acc would introduce extra overhead as a thread block of the reduction & convert kernel needs to access multiple splits in its hotloop (thus it is part of the ck tile window sliding operation rather than simple pointer arithmetic at the beginning of the kernel).
