# [Triton MoE]: Add optimized Gluon kernel for AMD CDNA3 with K-dimension unrolling

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2441](https://github.com/ROCm/aiter/pull/2441) · **Merged:** 2026-04-22 · **Author:** @jwu10003

**Inclusion reason:** kernel path 'aiter/ops/triton/_gluon_kernels/__init__.py'; keyword 'mfma'

## Summary (from upstream PR description)

Motivation
Performance optimization of MoE Int8 SmoothQuant GEMM kernel when the K dimension is small (K <= 192). This is common in the second layer (layer2) of MoE MLP blocks where the intermediate dimension is reduced.
This PR targets the new MoE path (moe_op_gemm_int8_smoothquant), adding a Gluon-optimized kernel that leverages AMD CDNA3 MFMA instructions for better performance on small K dimensions.
Technical Details
Key Optimizations

Manual LICM (Loop-Invariant Code Motion): Pre-loads A matrix data outside the N-dimension loop to reduce redundant memory traffic, since Gluon doesn't support automatic LICM
K-dimension loop unrolling: Fully unrolls the K loop (up to 3 iterations for K <= 192, BLOCK_K=64), eliminating loop overhead
Explicit BlockedLayout + MFMA: Uses gl.amd.AMDMFMALayout with v_mfma_i32_32x32x16_i8 instruction for optimal INT8 register usage
SUB_BLOCK_SIZE_N inner loop: Processes large BLOCK_N (512/1024) in 64-wide chunks for better occupancy
Buffer load/store intrinsics: Uses gl.amd.cdna3.buffer_load/store for efficient memory access

Performance Results
Benchmarked on MI308X using bench_moe_gemm_int8_smoothquant.py with proton profiler (3x100 reps averaged).
