# [CK] Add StreamLLM sink token support for batch_prefill pipeline

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#2794](https://github.com/ROCm/aiter/pull/2794) · **Merged:** 2026-04-28 · **Author:** @LJ-underdog

**Inclusion reason:** kernel path 'aiter/ops/mha.py'; keyword 'attention'

## Summary (from upstream PR description)

Dependencies
This PR depends on ROCm/rocm-libraries#6479 (CK-side change that promotes kHasSink_ to a real template parameter in fmha_fwd_batch_prefill_traits_, enabling _sink / _nsink kernel
variant codegen for the batch_prefill pipeline).

Must be merged after ROCm/rocm-libraries#6479.
The 3rdparty/composable_kernel submodule in this PR is bumped to commit feea6be, which already contains #6479.


Motivation
The existing mha_batch_prefill pipeline did not support StreamingLLM-style sink tokens: kHasSink_ was hard-coded to false in the CK traits, and sink_size was not threaded through the
AITER → C++ → CK call chain. This blocked workloads (e.g. GPT-OSS-style attention) that require a fixed prefix of always-attended KV tokens together with a sliding window and/or a virtual
sink-logit per head.
This PR adds end-to-end sink token support for mha_batch_prefill on top of the CK changes in #6479.
Technical Details
CK submodule

Bump 3rdparty/composable_kernel to feea6be (includes ROCm/rocm-libraries#6479), which makes kHasSink_ a real template parameter and emits separate _sink / _nsink kernel
instantiations for batch_prefill.

Python (aiter/ops/mha.py)

Add sink_size: int = 0 to mha_ba
