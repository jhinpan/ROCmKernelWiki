## Summary (from upstream PR description)

Add LSE output support for MLA decode qseqlen=1 persistent kernel (gfx950)


Add new ASM kernel mla_a8w8_qh16_qseqlen1_gqaratio16_lse_ps.co for fp8/fp8 decode with qseqlen=1 and LSE output enabled
Update mla_asm.csv with the new kernel config entry (fp8,fp8,gqa=16,ps=1,qseqlen=1,lse=1)
Update existing qseqlen=1 and qseqlen=4 lse kernel binaries

Previously, LSE output was only supported for qseqlen=4 in persistent mode. This enables LSE output for qseqlen=1, allowing return_lse=True in mla_decode_fwd for single-token decode scenarios.
Verified with: python3 op_tests/test_mla_persistent.py -b 256 -c 10000 --nhead 64,1 -d fp8 -kvd fp8
2.Add qseqlen fold for MLA on gfx950: use qh64 kernel instead of qh16
On gfx950 with fp8 persistent mode, when nhead=64 and decode_qlen=1, the original batch fold strategy expands batch 4x (256->1024) and dispatches to the qh16 kernel (qseqlen=1). This change introduces qseqlen fold: instead of expanding batch, expand max_seqlen_q from 1 to 4, allowing dispatch to the more efficient qh64 kernel (qseqlen=4).
Trigger condition: gfx950 + fp8(q) + fp8(kv) + persistent mode + max_seqlen_q * (nhead / 16) <= 4
