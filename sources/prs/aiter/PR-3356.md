# [csrc] activation: guard CDNA-only v_pk_mul_f32 asm in silu/swiglu kernels

**Repository:** [ROCm/aiter](https://github.com/ROCm/aiter) · **PR:** [#3356](https://github.com/ROCm/aiter/pull/3356) · **Merged:** 2026-05-27 · **Author:** @carlushuang

**Inclusion reason:** kernel path 'csrc/kernels/activation_kernels.cu'; keyword 'kernel'

## Summary (from upstream PR description)

Summary
csrc/kernels/activation_kernels.cu had 4 sites using v_pk_mul_f32 via inline asm (the silu/swiglu+mul packed-multiply fast path and the scaled silu+mul+quant variant). That instruction is CDNA-only (GFX9); on RDNA archs the compiler rejects it with
error: instruction not supported on this GPU
    asm volatile(\"v_pk_mul_f32 %0, %1, %2\" ...

This made module_activation fail to build on gfx12xx (RDNA4), forcing callers into the silu_and_mul HIP -> triton fallback added in #3354 (or SIGSEGV without the fallback).
Same pattern as the merged #3322 fix for rmsnorm_quant_kernels.cu: guard each asm with the CDNA gfx9xx macro family (gfx906/908/90a/940/941/942/950 - all GFX9 archs that expose v_pk_mul_f32) and fall back to portable element-wise C++ multiplies on every other arch (RDNA and host). On CDNA the inline asm path is preserved bit-for-bit so there is zero behavior or perf change for existing supported devices; on RDNA the compiler emits a pair of v_mul_f32 (and on the chained site, two pairs).
Sites touched (all in csrc/kernels/activation_kernels.cu):

L95   - act_and_mul_kernel packed multiply
L264  - act_and_mul_with_bias_kernel packed multiply
L433  - scaled_act_and_mul
