# [ROCm][perf] fix Aiter sparse MLA with MTP>1

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#37887](https://github.com/vllm-project/vllm/pull/37887) · **Merged:** 2026-03-31 · **Author:** @gronsti-amd

**Inclusion reason:** kernel path 'vllm/v1/spec_decode/dflash.py'; keyword 'attention'

## Summary (from upstream PR description)

Purpose
Enable speculative decoding with the MTP method and num_speculative_tokens > 1 for DeepSeek v3.2 and ROCM_AITER_MLA_SPARSE
The check in the eagle SpecDecodeBaseProposer.propose only checked the type of the last value of attn_metadata, which depends on the order of self.draft_attn_groups. A change in iteration order caused the checked type for DeepSeek v3.2 to change from ROCMAiterMLASparseMetadata to DeepseekV32IndexerMetadata, which failed the check.

Check all attention types in self.draft_attn_groups, to avoid a dependency on ordering.
Add DeepseekV32IndexerMetadata to the list of accepted types.
