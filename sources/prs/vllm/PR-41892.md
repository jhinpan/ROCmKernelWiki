# [Bugfix][Quark] Fix W8A8 INT8 garbage outputs on Step-3.5-Flash (and other 3-key fused-MoE Quark exports)

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#41892](https://github.com/vllm-project/vllm/pull/41892) · **Merged:** 2026-05-13 · **Author:** @JoursBleu

**Inclusion reason:** kernel path 'vllm/model_executor/layers/quantization/quark/quark_moe.py'; keyword 'flash'

## Summary (from upstream PR description)

Summary
After quantizing stepfun-ai/Step-3.5-Flash to W8A8 INT8 with AMD Quark, serving the checkpoint via vLLM produces garbage tokens (random tokens, frequent NaN logits). If the same weights are offline-rewritten into compressed-tensors format and served by stock vLLM (with no changes whatsoever), everything works fine — this confirms that the INT8 numerics themselves are correct and the bug is in vLLM's Quark loading path. This PR fixes three independent bugs in the Quark INT8 backend; together they are the root cause of the garbage output. After the fix, the Quark-native checkpoint (stepfun-ai/Step-3.5-Flash-Quark-W8A8-INT8) runs directly without any rewrite, and matches the compressed-tensors baseline on GSM8K and is lossless against the BF16 baseline.
The change is scoped to the Quark INT8 path and the single model class Step3p5ForCausalLM; the compressed-tensors path is untouched.
