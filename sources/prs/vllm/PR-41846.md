# Fix: Nemotron 3 rescue whitespace-only final_content, not just None

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#41846](https://github.com/vllm-project/vllm/pull/41846) · **Merged:** 2026-05-10 · **Author:** @Naveassaf

**Inclusion reason:** keyword 'fp4'

## Summary (from upstream PR description)

Summary
Nemotron3's parser overrides DeepSeek-R1's parser to handle the enable_thinking=False / force_nonempty_content=True cases, where the model is asked to skip thinking but R1's parser still routes everything into reasoning whenever it can't cleanly parse a <think>...</think>  block. To recover, the Nemotron parser swaps reasoning with final_content so the answer is delivered as content rather than reasoning.
The swap was gated on final_content is None, which misses the case where the model emits whitespace-only content (e.g. a stray "\n" or " "  after ). In that case final_content is a non-None string, the swap is skipped, and the client receives whitespace as the response while the actual answer remains stranded in reasoning.
This PR changes the Nemotron3 parser to match the upstream model-side fix shipped in the Nemotron Super checkpoint: https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4/commit/4f0cf9daaeb7a4d5e23f80a00e7ed15f0e03caf6
