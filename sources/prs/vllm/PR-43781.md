# [Bugfix][ROCm] Fix Accuracy Drop in Sparse Indexer on gfx950

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#43781](https://github.com/vllm-project/vllm/pull/43781) · **Merged:** 2026-05-28 · **Author:** @kliuae

**Inclusion reason:** kernel path 'vllm/v1/attention/ops/rocm_aiter_mla_sparse.py'; keyword 'attention'

## Summary (from upstream PR description)

Purpose
ROCm's sparse indexer path now supports DeepSeek-V4. However, currently its configuration degrades the accuracy for older models like DeepSeek-V3.2 and GLM-5 on the gfx950 path.
This PR fixes the accuracy drop. Specifically two issues are addressed.

The indexer cache layout is hard-coded to SHUFFLE and can cause erroneous cache reads when indexer cache block_size=1. This PR dispatches the shuffle layout based on the block_size setting.
On ROCm, the sparse indexer has a fast path for rotary embedding that omits tensor split/cat/copy, and that relies on the RoPE implementation mutating the input arguments in-place. However, that is not the case for the pytorch-native rotary embedding which is the default when TorchInductor is on. This PR limits the fast path to the inplace-mutating implementations, i.e. those invoked when rotary_embedding's custom_ops implementations are used.
