# [MoE] Remove inplace fused experts mechanism

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#43727](https://github.com/vllm-project/vllm/pull/43727) · **Merged:** 2026-05-28 · **Author:** @zyongye

**Inclusion reason:** kernel path 'tests/kernels/moe/modular_kernel_tools/common.py'; keyword 'gemm'

## Summary (from upstream PR description)

Summary
The inplace=True path on the fused-MoE call chain is dead code in mainline vLLM:

requirements/cuda.txt pins torch==2.11.0
disable_inplace() returns True for any torch>=2.9 (added in #26497 as a workaround for #26378, where the inplace_fused_experts torch custom op produced garbled tokens under Inductor with custom_ops disabled — torch custom ops can't soundly represent outputs aliasing inputs)
every runtime call site collapses to inplace=False under torch 2.9+

So the inplace_fused_experts / outplace_fused_experts torch op duality and the disable_inplace gate carry no value today, and the inplace torch op is a sharp edge: it is exactly the construct that broke under Inductor in #26378, and similar regressions are easy to land while the op remains registered. This PR executes the existing TODO at fused_moe.py:1585:
# TODO (bnell): replace this with modular op.  Can get rid of inplace/outplace
# torch ops.
What changed

Delete FusedMoEConfig.disable_inplace field and disable_inplace() torch version guard
Delete inplace_fused_experts / inplace_fused_experts_fake torch custom op pair and dispatch_fused_experts_func selector; route fused_experts() through torch.ops.vllm.outplac
