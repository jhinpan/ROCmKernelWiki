# [ROCm][Perf] Support N=5 in wvSplitK skinny GEMM kernels for speculative decoding

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#40687](https://github.com/vllm-project/vllm/pull/40687) · **Merged:** 2026-05-28 · **Author:** @mgehre-amd

**Inclusion reason:** kernel path 'csrc/rocm/skinny_gemms.cu'; keyword 'gemm'

## Summary (from upstream PR description)

With speculative decoding (e.g. eagle3 with num_speculative_tokens=4), the target model verification pass has batch size 5 (1 original + 4 speculative tokens). The skinny GEMM wvSplitK kernel only supported N<=4, causing fallback to torch.nn.functional.linear (hipBLAS) for the verification step.
Add case 5 to the wvSplitK dispatch switch and raise the dispatch threshold from N<=4 to N<=5 so the fast HIP kernel path is used during speculative verification.
Benchmarked on AMD Strix Halo (gfx1151, LPDDR5X-8000 128 GB):
Model: Qwen/Qwen3-8B (bf16, unquantized) with eagle3 speculative decoding input-len=128, output-len=128, num-prompts=5:
Median TPOT: 43.02 ms → 37.73 ms (12.3% faster)
Decode throughput: 23.2 tok/s → 26.5 tok/s (14.2% faster)
Reproduce:
vllm serve Qwen/Qwen3-8B --max-model-len 4096 
--gpu-memory-utilization 0.62 --max-num-seqs 1 
--no-enable-prefix-caching 
--speculative-config '{"method":"eagle3","model":"RedHatAI/Qwen3-8B-speculator.eagle3","num_speculative_tokens":4}'
vllm bench serve --model Qwen/Qwen3-8B 
--num-warmups 5 --random-input-len 128 --output-len 128 
--num-prompts 5 --max-concurrency 1 --temperature 0 
--percentile-metrics ttft,tpot,e2el
