# [XPU]fix: add XPU platform guards to DeepSeek-V4 ops

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#42950](https://github.com/vllm-project/vllm/pull/42950) · **Merged:** 2026-05-22 · **Author:** @majian4work

**Inclusion reason:** kernel path 'vllm/v1/attention/backends/mla/sparse_swa.py'; keyword 'attention'

## Summary (from upstream PR description)

Summary
Add is_xpu() guards to skip CUDA-specific features on XPU, enabling DeepSeek-V4 ops to run on Intel XPU without functional changes for CUDA/ROCm.
Changes

activation.py: route SiluAndMulWithClamp to forward_native on XPU
deepseek_v4.py: disable aux_streams, reuse ROCm forward path on XPU
deepseek_compressor.py: skip launch_pdl on XPU
fused_inv_rope_fp8_quant.py: skip launch_pdl on XPU
sparse_swa.py: skip tile_scheduler_metadata on XPU
rocm_aiter_mla_sparse.py: replace hardcoded 'cuda' with q.device, .is_cuda → not .is_cpu

Testing
Tested with DeepSeek-V4 inference on Intel XPU.
Notes

No functional change for CUDA or ROCm paths
Part of DeepSeek-V4 XPU support series (1/4)
