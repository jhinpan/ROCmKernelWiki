# [ROCm] [DSv4] [Perf] Support DeepSeek v4 MTP

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#43385](https://github.com/vllm-project/vllm/pull/43385) · **Merged:** 2026-05-24 · **Author:** @tjtanaa

**Inclusion reason:** kernel path 'vllm/model_executor/layers/fused_moe/experts/gpt_oss_triton_kernels_moe.py'; keyword 'attention'

## Summary (from upstream PR description)

Purpose
Enable MTP feature for DeepSeek V4 on ROCm.
Side task: The first PR to implement the hardware specific modeling file.
Test Plan
Run all 1319 GSM8K requests at concurrency 256 with --max-num-seqs 256 numshot 8, for both without MTP and with MTP. High concurrency is to ensure that the sparse indexer is logic is working correctly. In past experience while trying to fix the accuracy of DeepSeekV4, if the sparse indexer is not functioning correctly, the accuracy will degrade when concurrency is high. We don't need to pick num_shot 20 as the indexer top k token is shorter than in DeepSeekV3.2 and GLM5.
Ensure there are speed gain.
The server commands:
Non-MTP
#!/bin/bash

rm -rf /root/.cache/vllm

VLLM_ROCM_USE_AITER=1 \
vllm serve deepseek-ai/DeepSeek-V4-Pro \
  --host localhost \
  --port 8001 \
  --dtype auto \
  --tensor-parallel-size 8 \
  --max-num-seqs 256 \
  --distributed-executor-backend mp \
  --trust-remote-code \
  --gpu-memory-utilization 0.6 \
  --moe-backend triton_unfused \
  --tokenizer-mode deepseek_v4 \
  --reasoning-parser deepseek_v4 \
  --kv-cache-dtype fp8_e4m3 \
  --compilation-config '{"mode":3,"cudagraph_mode": "FULL_AND_PIECEWISE"}' \
| tee dsv4graph.l
