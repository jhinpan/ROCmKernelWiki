## Summary (from upstream PR description)

Summary
/v1/chat/completions (vllm/entrypoints/openai/chat_completion/serving.py:265-266, :345) and /v1/completions (vllm/entrypoints/openai/completion/serving.py:141-142, :192) already read the X-data-parallel-rank header and pass data_parallel_rank through to engine_client.generate. The disagg /inference/v1/generate endpoint did not — even though:

The helper OpenAIServing._get_data_parallel_rank is already inherited by ServingTokens (vllm/entrypoints/openai/engine/serving.py:605).
EngineClient.generate already accepts data_parallel_rank: int \| None = None (vllm/engine/protocol.py:79).

So router-injected DP routing was silently ineffective for the disagg generate endpoint. This is an inconsistency, not a feature — fixing it by adding the same two-line pattern from the OpenAI-compat endpoints.
No behavior change for clients that don't send the header (defaults to None, same as /v1/chat/completions).
Not a duplicate
