# [ROCm] Guard AITER GDN decode fast path by layout

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#42880](https://github.com/vllm-project/vllm/pull/42880) · **Merged:** 2026-05-18 · **Author:** @tuukkjs

**Inclusion reason:** kernel path 'vllm/model_executor/layers/mamba/gdn_linear_attn.py'; keyword 'attention'

## Summary (from upstream PR description)

Purpose
Fix the ROCm Qwen3.5 accuracy regression apparently introduced by #40711 by skipping the optional AITER Triton GDN decode fast-path for non-interleaved GDN projection layouts.
The fused AITER decode path added in #40711 is intended for the Qwen3-Next interleaved GQA layout. Qwen3.5 uses a non-interleaved [q, k, v, z] and [b, a] projection layout, so sending those packed tensors directly to the fused reshape kernel can read the wrong columns. This change keeps the AITER fast-path enabled for interleaved layouts, while routing non-interleaved layouts through the existing generic GDN core path that performs the correct split and rearrange.
AI assistance was used for this PR.
