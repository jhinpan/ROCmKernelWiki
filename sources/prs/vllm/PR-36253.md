# [ROCM] Optimize the fused_topk_bias to use aiter instead of fallback torch ops.

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#36253](https://github.com/vllm-project/vllm/pull/36253) · **Merged:** 2026-03-09 · **Author:** @benenzhu

**Inclusion reason:** kernel path 'vllm/model_executor/layers/fused_moe/router/fused_topk_bias_router.py'; keyword 'moe'

## Summary (from upstream PR description)

Purpose
When running MiniMax M2.5, currently the topk uses fallback pytorch ops, which is really slow.

This PR add a fast path for models like MiniMax M2.5 on ROCm by leveraging aiter's biased_grouped_topk kernel when sigmoid scoring with bias correction is used in fused_topk_bias.
The aiter kernel has a hard limit of 32 experts per group, so we compute the smallest num_expert_group that satisfies num_experts / num_expert_group <= 32 and evenly divides num_experts. Setting topk_group = num_expert_group makes it semantically equivalent to a global top-k with bias correction, avoiding the generic Python fallback path.
Test Plan

Run MiniMax M2.5 inference on Mi355.
Confirm output correctness matches the non-aiter fallback path by comparing the accuracy of the model.

Benchmarking
export VLLM_ROCM_USE_AITER=1
vllm serve /A/MiniMax-M2.5 \
    --tensor-parallel-size 8 \
    --enable_expert-parallel \
    --max-num-batched-tokens 196608 \
    --max-model-len=10240 \
    --max-num-seqs 512 \
    --block-size=32 \
    --trust-remote-code \
    --no-enable-prefix-caching \
    --port=30000
vllm bench serve \
  --model /A/MiniMax-M2.5 \
