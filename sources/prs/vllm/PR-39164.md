# [XPU] Skip VLLM_BATCH_INVARIANT for XPU in EAGLE DP test

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#39164](https://github.com/vllm-project/vllm/pull/39164) · **Merged:** 2026-04-09 · **Author:** @1643661061leo

**Inclusion reason:** keyword 'async'

## Summary (from upstream PR description)

Purpose
This PR disables the forced VLLM_BATCH_INVARIANT=1 setting for Intel XPU in test_run_eagle_dp, aligning its behavior with ROCm.
Motivation:
In test_run_eagle_dp, VLLM_BATCH_INVARIANT=1 is forcefully set to ensure the tokens generated with and without EAGLE are strictly identical. However, similar to the existing ROCm behavior, running EAGLE with DP > 1 on XPU can encounter underlying collective communication hangs (e.g., oneCCL/libfabric provider deadlocks) or strict numerical variance under async speculative decoding setups.
By bypassing the forced batch invariant mode for XPU in this specific test, we avoid unnecessary CI timeouts/hangs and ensure test stability while the upstream async speculative decode correction logic for non-CUDA platforms is further stabilized.
Changes:

Updated the platform check in test_run_eagle_dp to exclude XPU (not current_platform.is_xpu()) from setting the VLLM_BATCH_INVARIANT environment variable.
