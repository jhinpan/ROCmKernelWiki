# [ROCm][Refactor] Enable AWQMarlinConfig on ROCm to use choose_mp_linear_kernel

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#36505](https://github.com/vllm-project/vllm/pull/36505) · **Merged:** 2026-03-23 · **Author:** @mgehre-amd

**Inclusion reason:** kernel path 'vllm/model_executor/kernels/linear/mixed_precision/conch.py'; keyword 'gemm'

## Summary (from upstream PR description)

On ROCm, AWQ models were forced through AWQConfig → AWQLinearMethod → ops.awq_gemm, bypassing the choose_mp_linear_kernel framework entirely. AWQMarlinLinearMethod repacked weights into Marlin format and called ops.marlin_gemm, which is NVIDIA-only.
This PR corrects it with the approach suggested by @mgoin in the quantization SIG meeting.
This change:

Allows AWQMarlinConfig to be selected on ROCm by using is_cuda_alike() instead of is_cuda() in is_awq_marlin_compatible.
Rewrites AWQMarlinLinearMethod to use choose_mp_linear_kernel, adding an AWQ→standard format conversion step in process_weights_after_loading that fixes AWQ's non-standard bit ordering and repacks qweight from output-dim packing to input-dim packing.
Skips the NVIDIA device_capability gate in query_marlin_supported_quant_types on ROCm (since ROCm device capabilities do not map to NVIDIA compute capability semantics).
Fixes ConchLinearKernel to handle symmetric quantization (no zero points) by clearing the raw packed qzeros attribute via register_parameter(name, None).

Before this change, AWQ on ROCm used ops.awq_gemm directly. After this change, choose_mp_linear_kernel selects ConchLinearKernel by default.
