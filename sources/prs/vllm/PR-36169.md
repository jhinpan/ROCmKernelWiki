# feat(grpc): extract gRPC servicer into smg-grpc-servicer package, add --grpc flag to vllm serve

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#36169](https://github.com/vllm-project/vllm/pull/36169) · **Merged:** 2026-03-10 · **Author:** @CatherineSue

**Inclusion reason:** keyword 'async'

## Summary (from upstream PR description)

Purpose
Supersedes #35590 and #33747.
Following discussion with @njhill, we agreed to extract the gRPC servicer implementation into the smg-grpc-servicer package rather than maintaining it in-tree. The servicer wraps AsyncLLM and implements the gRPC proto — by living in a separate package, it can iterate independently without waiting on vLLM release cycles. Proto stubs are provided by smg-grpc-proto.
What changes on the vLLM side:

vllm serve <model> --grpc — lazy-imports smg_grpc_servicer.vllm.server when set
pip install vllm[grpc] — installs smg-grpc-servicer + dependencies
smg-grpc-proto >= 0.4.2 added to runtime deps (proto stubs used by engine)

What's removed:

vllm/entrypoints/grpc_server.py → moved to smg-grpc-servicer
vllm/grpc/ shim and vllm_engine.proto → stubs now from smg-grpc-proto
grpcio-tools build dep and proto compilation hooks in setup.py
tests/entrypoints/test_grpc_server.py → moved to smg-grpc-servicer

Test Plan

vllm serve <model> --grpc --port 8001 starts gRPC server via smg-grpc-servicer
vllm serve <model> (without --grpc) is unaffected
pip install vllm[grpc] installs smg-grpc-servicer + dependencies

Test Result
Verified locally: vllm serve with --grpc fla
