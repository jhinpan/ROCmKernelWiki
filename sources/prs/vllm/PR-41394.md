# [Kernel][ROCm] Native W4A16 kernel for AMD RDNA3 (gfx1100) — fp16 + bf16

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#41394](https://github.com/vllm-project/vllm/pull/41394) · **Merged:** 2026-05-29 · **Author:** @JartX

**Inclusion reason:** kernel path 'csrc/rocm/q_gemm_rdna3.cu'; keyword 'wmma'

## Summary (from upstream PR description)

Motivation
This work was driven by a concrete production problem: on RDNA3 the only fast W4A16 path was ExLlama, which is fp16-only, and casting bf16-trained models down to fp16 introduces numerical instability. Modern model families (Qwen2/Qwen3, Qwen3-Coder, Llama 3.x, Mistral, etc.) are trained and released in bf16; their weight ranges and activation magnitudes routinely exceed fp16's ±65504 dynamic range, producing inf/NaN propagation, silently degraded outputs, and garbled tool-calling / structured-output generations under load. The Triton W4A16 kernel does support bf16, but at ~82 tk/s it's roughly 3× slower than ExLlama fp16, forcing users into a "fast but numerically wrong" vs "correct but unusably slow" trade-off.
This PR removes that trade-off: native bf16 W4A16 at 205–345 tk/s (2.5–4.2× faster than Triton bf16), plus a fp16 path that beats ExLlama by 6–17% for users who don't need bf16. Models stay in their native bf16 dtype, no manual casts, no quality regression.
Summary
Adds a native HIP W4A16 kernel for AMD RDNA3 (gfx1100/1101/1102 — RX 7900 XT/XTX class), registered as RDNA3W4A16LinearKernel ahead of the Triton kernel on the ROCm priority list. Falls through gracefu
