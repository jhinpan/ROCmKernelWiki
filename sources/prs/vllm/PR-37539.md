# [Performance] Remove unnecessary zero-fill of MLA decode output tensor in Aiter backend

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#37539](https://github.com/vllm-project/vllm/pull/37539) · **Merged:** 2026-04-10 · **Author:** @xaguilar-amd

**Inclusion reason:** kernel path 'vllm/v1/attention/backends/mla/rocm_aiter_mla.py'; keyword 'attention'

## Summary (from upstream PR description)

Problem
During the MLA decode phase on ROCm with the Aiter backend, a
vectorized_elementwise GPU kernel is launched to zero-fill the output tensor
before the MLA kernel overwrites it entirely. This adds unnecessary kernel
launch latency on the critical decode path.
Root
In rocm_aiter_mla.py, the output tensor o is allocated with torch.zeros:
o = torch.zeros(
    B,
    self.num_heads,
    self.kv_lora_rank,
    dtype=attn_metadata.decode.attn_out_dtype,
    device=q.device,
)
torch.zeros launches a vectorized_elementwise fill kernel on the GPU.
However, the Aiter MLA kernel pipeline (mla_decode_fwd) unconditionally
overwrites every element of o before it is read:

When num_kv_splits > 1: the Stage 2 Triton reduction kernel stores
acc / e_sum to every valid position in O.
When num_kv_splits == 1 and Stage 2 runs: the FINAL_OUT path copies from
the intermediate buffer to O.
When num_kv_splits == 1 with early return: either logits aliases o
(Stage 1 writes through the alias) or the ASM kernel writes to ptr_RP
directly.

The zero-initialization is therefore redundant.
Fix
Replace torch.zeros with torch.empty, which only allocates memory without launching
any GPU kernel.
