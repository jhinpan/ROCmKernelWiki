# [ROCm][Bugfix] fix cache block size mismatch for aiter unified attention

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#37606](https://github.com/vllm-project/vllm/pull/37606) · **Merged:** 2026-03-20 · **Author:** @divakar-amd

**Inclusion reason:** kernel path 'vllm/platforms/rocm.py'; keyword 'attention'

## Summary (from upstream PR description)

This PR fixes the following issue (Resolves #37548):

We want to use cache block size of 64 for AITER_UNIFIED_ATTENTION. The current logic works as intended when we use the env variable VLLM_ROCM_USE_AITER_UNIFIED_ATTENTION=1
However, cache block size still resolves to 16 when  --attention-config '{"backend": "ROCM_AITER_UNIFIED_ATTN"}' is used.

This PR resolves this mismatch irrespective of how the AITER_UNIFIED_ATTN is set (via ENV var or as an arg) in accordance with the recent refactoring of check_and_update_config (#35122)
The remaining backends (ROCM_AITER_FA, ROCM_ATTN, TRITON_ATTN) will continue to default to cache block size = 16
