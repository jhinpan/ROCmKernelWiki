# [ZenCPU] AMD Zen CPU Backend with supported dtypes via zentorch weekly

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#39967](https://github.com/vllm-project/vllm/pull/39967) · **Merged:** 2026-04-18 · **Author:** @Chinmay-Kulkarni-AMD

**Inclusion reason:** keyword 'gemm'

## Summary (from upstream PR description)

Purpose
Update the AMD Zen CPU platform (ZenCpuPlatform) to correctly declare supported dtypes and switch the zentorch dependency to the weekly release channel.
This PR fixes the two minor issues introduced in #35089

Declare supported_dtypes for Zen CPU: AMD Zen CPUs do not support float16 compute natively. The base CpuPlatform includes torch.float16 in its supported_dtypes, which causes vLLM to accept float16 models on Zen CPUs. This leads to dtype mismatches and the execution errors out. This PR overrides supported_dtypes in ZenCpuPlatform to return only [torch.bfloat16, torch.float32], matching the actual hardware capabilities.
Switch vllm[zen] to zentorch-weekly: The zentorch PyPI release cadence is weekly. Using zentorch-weekly ensures pip install vllm[zen] always pulls the known-good version of weekly build instead of release builds.

Test Plan

Verify that models with native float16 dtype (e.g., bloom-560m, opt-125m) are automatically resolved to bfloat16 on Zen CPU with a warning, instead of silently running in an unsupported dtype.
Run the existing CPU generation tests on an AMD Zen machine:
pytest -v -s tests/models/language/generation -m cpu_model

Verify pip install vl
