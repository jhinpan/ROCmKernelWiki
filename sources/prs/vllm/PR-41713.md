# Eliminate redundant MoE buffer copies in AITER fused experts (without dependency on AITER changes)

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#41713](https://github.com/vllm-project/vllm/pull/41713) · **Merged:** 2026-05-07 · **Author:** @amd-mghanimi

**Inclusion reason:** kernel path 'vllm/model_executor/layers/fused_moe/modular_kernel.py'; keyword 'attention'

## Summary (from upstream PR description)

Addressing the issues raised in previous PRs.
It follows the draft PR on this topic here: #41020
We copied ideas from other works, mostly based on #38597 and similar ideas in ROCm/aiter@da318d0 and #41020.
Purpose
Eliminate redundant __amd_rocclr_copyBuffer DMA kernel launches from the ROCm AITER fused MoE decode path by passing the caller's output tensor directly as AITER's destination buffer.
On DeepSeek-V3.2 TP4 (4x MI355X), this removes 116 copy kernels per decode step and yields a 2.3% per-step improvement (500 us savings), with a secondary benefit from reduced memory bandwidth contention on the custom allreduce.
Based on akii96@df0f043; on MiniMax M2.5  TP=2 MI355X, ISL/OSL=1000/100, conc=64:
__amd_rocclr_copyBuffer:  12524 -> 0   events  (elimination)
Memcpy DtoD:               1307 -> 807 events  (-38%)
Output throughput:        1512 -> 1572 tok/s   (+4.0%)
Median TPOT:              33.6 -> 32.2 ms      (-4.2%)
Similar to #38597 it doesn't need AITER to change. We added a condition to check the size and type of data this assignment as well as checking if the tensor is the root of its own storage: output.data = result in vllm/model_executor/layers/fused_moe/rocm_aiter_fused_
