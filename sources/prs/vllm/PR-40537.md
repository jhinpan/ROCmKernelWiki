# Add system_fingerprint field to OpenAI-compatible API responses

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#40537](https://github.com/vllm-project/vllm/pull/40537) · **Merged:** 2026-04-27 · **Author:** @simon-mo

## Summary (from upstream PR description)

Purpose
This PR adds support for the system_fingerprint field in OpenAI-compatible API responses. The fingerprint is a string that identifies the vLLM server configuration and is stamped on non-streaming responses to help clients understand the serving environment.
The implementation provides two modes:

full (default): Human-readable fingerprint encoding server version, hardware, parallelism config, dtypes, quantization, and a config hash (e.g., vllm-0.11.0-H100-tp8-bf16-a3b21f94)
hash: Opaque fingerprint showing only the config hash (e.g., vllm-a3b21f94)

The fingerprint is computed once at server startup and cached to avoid per-request overhead.
Changes


New module vllm/entrypoints/openai/fingerprint.py: Core fingerprint computation logic with:

build_system_fingerprint(): Constructs the fingerprint string from vLLM config
get_system_fingerprint(): Cached accessor
set_default_fingerprint_mode(): Allows switching modes at startup
Helper functions for device name normalization and dtype shortening



CLI argument in cli_args.py: Added fingerprint_mode parameter to control fingerprint behavior


Server initialization in generate/api_router.py: Sets the fingerprint mode before serv
