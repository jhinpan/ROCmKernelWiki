# [ROCm] Add XGMI backend for MoRI Connector

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#41753](https://github.com/vllm-project/vllm/pull/41753) · **Merged:** 2026-05-22 · **Author:** @simondanielsson

**Inclusion reason:** keyword 'mi300'

## Summary (from upstream PR description)

Purpose
Part of vllm-project/router#142
This PR adds the option to run MoRI with the XGMI backend using "kv_connector_extra_config": {"backend": "xgmi"}. This allows for running PD disagg with MoRI in CI on a single node, without having RDMA drivers installed.
Long term we aim for also adding multi-node tests using the RDMA backend. However this requires #40453 and provisioning the appropriate AMD HW CI resources.

For instance, we can directly add MoRI to the vllm-router CI using this backend: see vllm-project/router#164, without worrying about installing RDMA userspace libraries for the NICs used by the CI machines etc. Without this, you will get an error if you run MoRI in an environment without the correct RDMA userspace libs are installed (i.e. in the official vllm/vllm-openai-rocm image), triggered by MoRI's RdmaBackend.
NB: all devices must be visible to all vLLM instances for MoRI to be able to establish XGMI sessions between P and D instances. E.g. in 1p1d this requires setting HIP_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 , and HIP_VISIBLE_DEVICES=4,5,6,7,0,1,2,3 on P and D, respectively. If running in separate dockers, --pid host is also required.
