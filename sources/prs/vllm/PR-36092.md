# [ROCm] Fix AITER ops fake impl and minor bugs

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#36092](https://github.com/vllm-project/vllm/pull/36092) · **Merged:** 2026-04-10 · **Author:** @ChuanLi1101

**Inclusion reason:** kernel path 'vllm/_aiter_ops.py'; keyword 'rope'

## Summary (from upstream PR description)

Summary
Fix three ROCm-specific bugs in AITER ops and platform code:

_rocm_aiter_fused_topk_fake returns None instead of tuple: The fake/meta implementation for rocm_aiter_fused_topk custom op returned None (with pass body), while the real implementation returns (topk_weights, topk_indices). This would cause failures during torch.compile tracing in FakeTensor mode, since downstream code expects a tuple of tensors.
shuffle_weight @staticmethod has stray self parameter: The shuffle_weight method on rocm_aiter_ops is decorated with @staticmethod but incorrectly includes self as the first parameter. This causes positional argument misalignment - when called as rocm_aiter_ops.shuffle_weight(tensor, layout), self receives tensor and tensor receives layout.
Missing spaces in ValueError messages: Two error messages in rocm.py MLA backend selection had missing spaces due to f-string concatenation (e.g. "TRITON_MLA,does not support" instead of "TRITON_MLA, does not support"), plus a leading space before "The".

Test plan

 Verified the _rocm_aiter_fused_topk_fake fix returns tensors with correct shapes and dtypes matching the real implementation
 Verified shuffle_weight signature now correc
