# [ROCm] [Bugfix] Fix DeepSeek V4 Functionality and Accuracy

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#42810](https://github.com/vllm-project/vllm/pull/42810) · **Merged:** 2026-05-17 · **Author:** @tjtanaa

**Inclusion reason:** kernel path 'vllm/model_executor/layers/mhc.py'; keyword 'attention'

## Summary (from upstream PR description)

Purpose
This PR addresses the following issues

Functionality broken after this PR #41263 (fixed by removing x = self.ffn_norm(x))
Fix the DeepSeek V4 accuracy degradation at high concurrency.

I have added self-review comments to explain the changes.
Point 2
It is a compounded issue.

AITER MHC has accuracy issue when number of tokens is large. New AITER version is coming soon, so the code path is kept documented so that we can easily reenable it in vLLM once we upgrade the AITER version. For now we are falling back to torch implementation.
The prefill mqa topk buffer is corrupted by incorrect logic. It is fixed by calling the torch.ops._C.top_k_per_row_prefill .

Other changes are code cleaning and also invoking faster kernels e.g. replace _topk_indices_torch with torch.ops._C.top_k_per_row_decode .
Test Plan
lmeval score of deepseek-ai/DeepSeek-V4-Pro and deepseek-ai/DeepSeek-V4-Flash
