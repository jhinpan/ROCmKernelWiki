# [Bugfix] Disable FlashInfer CUTLASS MoE on SM110 (Jetson Thor AGX)

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#40808](https://github.com/vllm-project/vllm/pull/40808) · **Merged:** 2026-05-01 · **Author:** @stecasta

**Inclusion reason:** kernel path 'vllm/model_executor/layers/fused_moe/flashinfer_cutlass_moe.py'; keyword 'gemm'

## Summary (from upstream PR description)

flashinfer <= 0.6.8.post1 ships no SM110 MoE cubins. On SM110 the SM100 artifact is reused at runtime and the TMA-WS dispatcher picks tile 256x256x128 which has no SM100 registration, raising Unsupported tile shape config 256256128 for MoE gemm at moe_gemm_template_dispatch_tma_ws.h:486 when running Nemotron-H unquantized BF16 MoE. Drop SM110 from the FlashInferExperts whitelist so the oracle falls back to Triton, analogous to #39825 for SM121.
Surfaced by #36286 which migrated unquantized MoE to the full oracle flow: the oracle now auto-picks FlashInfer CUTLASS whenever _supports_current_device returns True, rather than requiring VLLM_USE_FLASHINFER_MOE_FP16=1 as an opt-in. The SM110 gap was latent before; it now triggers by default on Thor.
Tracked at flashinfer-ai/flashinfer#3134 . Remove once SM110 MoE cubins ship.
Test plan
Before (Thor SM110, nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16): EngineCore crashes with Unsupported tile shape config 256256128 for MoE gemm.
After: the unquantized MoE falls back to Triton and the server starts.
