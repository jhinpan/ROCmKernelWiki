# [ROCm][Quantization] add fp8xfp8 attn support for rocm_aiter_unified_attn

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#36927](https://github.com/vllm-project/vllm/pull/36927) · **Merged:** 2026-03-18 · **Author:** @divakar-amd

**Inclusion reason:** kernel path 'vllm/v1/attention/backends/rocm_aiter_unified_attn.py'; keyword 'attention'

## Summary (from upstream PR description)

As a follow-up of #35316,
This PR adds support for fp8xfp8 attention for rocm_aiter_unified_attn
For fp8xfp8 computation, the aiter triton kernel expects Q to be in fp8 as well, otherwise it descales it to fp32. (LINK). However, Q scales are not supported in the kernel (LINK)
To handle this, we absorb q_scale & k_scale into the softmax_scale, and absorb v_scale into the output_scale (if fused quantized output is used) or apply it post-attention.
Testing on gpt-oss-120b (On top of #35316)

  **Quark quantising script for gpt-oss-120b**

#/bin/bash
exclude_layers="*lm_head* *router*"
python3 quantize_quark.py 
  --model_dir /data/models/openai/gpt-oss-120b 
  --quant_scheme mxfp4_fp8 
  --kv_cache_dtype fp8 
  --attention_dtype fp8 
  --exclude_layers $exclude_layers 
  --num_calib_data 512 
  --output_dir /data/models/gpt-oss-120b-w-mxfp4-a-fp8-kv-fp8-fp8attn-no_lmhead_router 
  --model_export hf_format 
  --multi_gpu
