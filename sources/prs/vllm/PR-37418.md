# [Bugfix][ROCm] Fix MoRI + AITER FP8 dispatch compatibility for defer_input_quant

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#37418](https://github.com/vllm-project/vllm/pull/37418) · **Merged:** 2026-03-19 · **Author:** @Duyi-Wang

**Inclusion reason:** kernel path 'vllm/model_executor/layers/fused_moe/mori_prepare_finalize.py'; keyword 'moe'

## Summary (from upstream PR description)

Purpose
Fix a compatibility issue between MoriPrepareAndFinalize and AiterExperts introduced by the MoE Oracle refactor (#32414, #32567).
After the refactor, AiterExperts.expects_unquantized_inputs unconditionally returns True, which causes defer_input_quant=True to be passed to MoriPrepareAndFinalize.prepare(). However, MoRI's prepare step needs to perform FP8 quantization before dispatch to reduce network traffic (use_fp8_dispatch), and the old code raised NotImplementedError on defer_input_quant=True — making it impossible to use MoRI + AITER with FP8 quantized models.
Changes:

rocm_aiter_fused_moe.py: Make AiterExperts.expects_unquantized_inputs conditional — return False when paired with MoRI (since MoRI handles FP8 quantization in the dispatch phase), True otherwise (AITER handles quantization internally via fused kernels).
mori_prepare_finalize.py: Remove the NotImplementedError on defer_input_quant=True. Instead, when defer_input_quant=True, skip the FP8 dispatch quantization so that future expert backends that handle quantization internally can work correctly with MoRI.
