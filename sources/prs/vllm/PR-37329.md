# [Bugfix] Fix ConchLinearKernel channelwise quantization (group_size=-1)

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#37329](https://github.com/vllm-project/vllm/pull/37329) · **Merged:** 2026-03-20 · **Author:** @mgehre-amd

**Inclusion reason:** kernel path 'vllm/model_executor/kernels/linear/mixed_precision/conch.py'; keyword 'gemm'

## Summary (from upstream PR description)

ConchLinearKernel.apply_weights passed group_size=-1 directly to the conch mixed_precision_gemm kernel for channelwise quantization. Inside the Triton kernel this computes stride_mul = block_k / group_size = 64 / -1 = -64, causing all K-blocks after the first to read scale values from out-of-bounds negative offsets. The result is silently corrupt output (no crash).
Fix: map group_size=-1 to the actual input dimension K before passing it to the kernel. With group_size=K, stride_mul = block_k / K < 1, which truncates to 0 after int32 cast, so every iteration correctly reads the single per-channel scale row.
