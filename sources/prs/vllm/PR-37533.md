# [ROCm] fix sleep mode not releasing GPU memory problem on ROCm

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#37533](https://github.com/vllm-project/vllm/pull/37533) · **Merged:** 2026-03-23 · **Author:** @aaab8b

**Inclusion reason:** keyword 'mi300'

## Summary (from upstream PR description)

Purpose
On ROCm, hipMemRelease does not return physical VRAM to the free pool
while the virtual-address reservation (from hipMemAddressReserve) is still
held. This causes sleep mode to report memory as freed at the HIP runtime
level, but the GPU VRAM remains occupied at the hardware level (confirmed via
rocm-smi), preventing other applications (e.g. RL training frameworks) from
using the freed memory.
Cycle cuMemAddressFree → cuMemAddressReserve (requesting the same address)
at the end of unmap_and_release on the ROCm path. This forces the driver to
actually release the physical pages while immediately re-reserving the same
virtual address so that a subsequent create_and_map (wake_up) works without
changing any tensor pointers.
Only the #else (USE_ROCM) branch of unmap_and_release is modified — no
impact on the NVIDIA CUDA path.
Test Plan
Use the following script can reproduce the problem. Below is the script:
import torch
from vllm import LLM
if __name__ == '__main__':
    llm = LLM(model="Qwen/Qwen2.5-0.5B-Instruct", enable_sleep_mode=True)
    def run_inference(prompt):
        outputs = llm.generate(prompt)
        for output in outputs:
            prompt = output.prompt
