# [ROCm][Bugfix] Fix fused_mla_dual_rms_norm for AITER API rename _fused_qk_rmsnorm

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#42606](https://github.com/vllm-project/vllm/pull/42606) · **Merged:** 2026-05-15 · **Author:** @rbrugaro-amd

**Inclusion reason:** keyword 'fp4'

## Summary (from upstream PR description)

AITER PR #2958 renamed the public fused_qk_rmsnorm  to the private _fused_qk_rmsnorm and prepended q_out/k_out output-buffer parameters.  This breaks vLLM's MLA dual RMS norm fusion pass at runtime with an ImportError when running against the updated AITER.
Changes:

check_aiter_fused_qk_rmsnorm(): probe for the new private name
first, falling back to the old public name for backward compat.
_fused_mla_dual_rms_norm_impl(): import the aiter module once, then
use hasattr to dispatch between new _fused_qk_rmsnorm and old
fused_qk_rmsnorm, avoiding per-call exception overhead and
preventing unrelated ImportErrors from being swallowed.
pass_manager.py: gate MLADualRMSNormFusionPass on
check_aiter_fused_qk_rmsnorm() so the pass is silently skipped
when neither AITER variant is available, instead of crashing at
runtime.

Test plan

 python -m pytest tests/compile/passes/test_fuse_mla_dual_rms_norm.py -v on ROCm with AITER 0.1.13 (old API) — validates backward-compat path
 Same test on ROCm with AITER post-PR#2958 (new API) — validates new _fused_qk_rmsnorm path
 E2E: serve Kimi-K2-Thinking-MXFP4 (TP=4, MI355X) with fuse_mla_dual_rms_norm: true — confirm no ImportError, fusion pass matche
