# [NVFP4][Hopper/AMD Instinct] Add Triton kernels for NVFP4 dequantization and QDQ emulation

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#40033](https://github.com/vllm-project/vllm/pull/40033) · **Merged:** 2026-04-30 · **Author:** @fxmarty-amd

## Summary (from upstream PR description)

Purpose
Add Triton kernels for NVFP4 dequantization and quantize-dequantize emulation to accelerate NVFP4 quantization emulation on devices that do not support this dtype natively (AMD Instinct MI3xx, H100), following #35733 and #35737.
The Triton kernels automatically replace the torch eager reference implementation when running on CUDA devices, with significant perf improvements, and avoids launching many independent kernel when using --enforce-eager, with back and forth HBM read/write.
These fused kernels  also help to stop hitting pytorch/pytorch#180341 and ROCm/rocm-systems#5071 where many stacked kernels calls from dequantize_to_dtype and ref_nvfp4_quant_dequant result in HSA crashes in recent ROCm versions / pytorch nightly (vllm bench serve with NVFP4 emulation on MI355X is not runnable without HSA_TOOLS_DISABLE_REGISTER=1 due to these crashes - adding this env var is very slow).
This PR is submitted independently from #35737, but closely related to it.
