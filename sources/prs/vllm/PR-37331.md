# [Bugfix] Reject channelwise quantization (group_size <= 0) in ExllamaLinearKernel

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#37331](https://github.com/vllm-project/vllm/pull/37331) · **Merged:** 2026-03-20 · **Author:** @mgehre-amd

**Inclusion reason:** kernel path 'vllm/model_executor/kernels/linear/mixed_precision/exllama.py'; keyword 'kernel'

## Summary (from upstream PR description)

ExllamaLinearKernel.can_implement did not reject channelwise quantization where group_size=-1. Python's modulo semantics mean N % -1 == 0 for any N, so the existing divisibility check silently passed. At runtime, process_weights_after_loading then computed groups = K // -1 = -K and crashed with:
RuntimeError: Trying to create tensor with negative dimension -2048
Add an explicit group_size <= 0 guard before the divisibility check so Exllama cleanly reports that it does not support channelwise quantization, and the kernel selector can fall through to a kernel that does (e.g. ConchLinearKernel).
Tested on AMD Strix Halo (gfx1151) with
nm-testing/TinyLlama-1.1B-Chat-v1.0-W8A16_channel-e2e (w8a16 per-channel, VLLM_DISABLED_KERNELS=ConchLinearKernel, dtype=float16):
Before fix: RuntimeError: Trying to create tensor with negative dimension -2048: [-2048, 2560]
After fix: "Group size (-1) must be positive, Exllama does not support channelwise quantization"
