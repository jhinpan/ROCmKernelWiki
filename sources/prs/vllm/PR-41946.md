# [Bugfix] [ROCm] [DSV4] [Perf] Add aiter mhc support

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#41946](https://github.com/vllm-project/vllm/pull/41946) · **Merged:** 2026-05-13 · **Author:** @tjtanaa

## Summary (from upstream PR description)

Purpose
This PR integrates the aiter mhc kernel based on AITER v0.1.13, there are API changes in newer aiter versions. I will follow up with a new PR when we upgraded to new AITER version.
This PR also clean up the mhc kernels so that tilelang is lazily imported, avoid causing import error on platform that does not support tilelang.
IR Ops is not used because there seems to have some report regarding to some overhead with ir op abstraction. Kernel abstraction is also considered but since it does not manage weights nor require preprocess_weight_after_loading logic. So CustomOp is picked instead to capitalized on its hardware dispatching logic directly in the layers/mhc.py to avoid introducing complexity and inference overhead for now.
This aiter mhc enablement PR is addressing the following issues

Main point: Optimize aiter mhc for ROCm.

mhc-pre: aiter
mhc-post aiter
hc-head ATOM


[Critical] During integration it also bugfix the broken ROCm path caused by PR #41536
During integration it also remove the dependency to tilelang on platform that doesn't support tilelang

CustomOp is used to capitalize on its hardware platform dispatching logic, forward_cuda and forward_hip.
