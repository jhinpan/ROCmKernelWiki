# [ROCm][Bugfix]: dynamically align BLOCK_DMODEL with Lv in MLA decode kernel

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#41119](https://github.com/vllm-project/vllm/pull/41119) · **Merged:** 2026-05-11 · **Author:** @vllmellm

## Summary (from upstream PR description)

Purpose
Fixes #40966
This PR resolves a Triton compilation error, ValueError('Cannot make_shape_compatible: incompatible dimensions at index 1: 256 and 512')  occurring in MLA-based models Mistral-Small on ROCm.
Key Changes:
Dynamic Dimension Alignment: Updated the triton_decode_attention kernel to align BLOCK_DMODEL with the local latent rank (Lv) instead of the total head dimension (Lk) when is_mla=True. This ensures shape compatibility for tl.dot operations.
Regression-Free Generalization: Replaced hardcoded dimension checks with generalized next_power_of_2 logic, supporting a wider range of MLA configurations while maintaining compatibility with DeepSeek-V3/V3.1.
Hardware Tuning: Optimized the BLOCK size to 16 for HIP/ROCm (MI300X) to balance shared memory pressure.
Test Plan

Comprehensive Regression Testing (MLA Models): Verify that the dynamic alignment logic maintains stability and accuracy across various MLA-based architectures.


Models: DeepSeek-V3.1 (TP4), DeepSeek-V2-Lite (TP2), and Kimi-K2.5 (TP8).
Evaluation: Compare GSM8K accuracy (LM-Eval) and serving throughput/latency against the original hardcoded kernel.
