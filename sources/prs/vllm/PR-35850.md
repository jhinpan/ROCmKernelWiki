# [ROCm] Support MLA with nhead<16 and FP8 KV cache for TP=8 (Kimi K2.5/Linear)

**Repository:** [vllm-project/vllm](https://github.com/vllm-project/vllm) · **PR:** [#35850](https://github.com/vllm-project/vllm/pull/35850) · **Merged:** 2026-03-06 · **Author:** @ChuanLi1101

**Inclusion reason:** kernel path 'vllm/v1/attention/backends/mla/rocm_aiter_mla.py'; keyword 'attention'

## Summary (from upstream PR description)

Summary

Support AITER MLA for num_heads < 16 (e.g., TP=8 with Kimi K2.5 giving 8 heads/rank, or Kimi-Linear giving 4 heads/rank). Uses head-repeat to expand to 16 heads before calling the AITER MLA decode kernel, then contracts the output back. This reuses the existing optimized gqa_ratio=16 ASM kernel without requiring new kernel variants.
Relax head-count assertion to accept num_heads of 4, 8, or any multiple of 16 in [16, 128]. Previously only {16, 128} were accepted.
Auto-fallback from TritonMLA to AITER MLA when FP8 KV cache is used. TritonMLA does not support FP8 KV cache (raises NotImplementedError). The fallback applies to both auto-selected and user-specified backends.

Fixes #35641
Test plan

Verify amd/Kimi-K2.5-MXFP4 runs with TP=8, AITER enabled (8 heads/rank, previously crashed with assertion error)
Verify moonshotai/Kimi-Linear-48B-A3B-Instruct runs with TP=1, --kv-cache-dtype fp8_e4m3 (32 heads, previously crashed)
Verify TP=2 / TP=4 continue to work (16/32 heads/rank, existing path)
Verify explicit --attention-backend TRITON_MLA + --kv-cache-dtype fp8_e4m3 triggers fallback warning
Verify non-FP8 TritonMLA path is unaffected
