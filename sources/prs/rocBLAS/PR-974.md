# Add --c_noalias_d option for rocblas-bench; cleanup gemm_ex tests

**Repository:** [ROCm/rocBLAS](https://github.com/ROCm/rocBLAS) · **PR:** [#974](https://github.com/ROCm/rocBLAS/pull/974) · **Merged:** 2020-02-04 · **Author:** @leekillough

**Inclusion reason:** kernel path 'clients/include/testing_gemm_batched_ex.hpp'; keyword 'gemm'

## Summary (from upstream PR description)

Right now rocblas-bench always passes D == C in gemm_ex tests. There is no way to measure the performance of gemm_ex when C and D are different arrays. Both D == C and D != C are important use-cases which should be able to measured for performance.
Rather than breaking the existing behavior, which may be relied upon by scripts, a new option --c_noalias_d is added, which says that C and D should be separate instead of combined into one array.
In the future, we may want to expand correctness tests to take this c_noalias_d flag into account, and call gemm_ex with either separate or overlapping C and D arrays.
Cleanup of gemm_ex:

Unnamed namespaces should  never be used in headers, because it may violate ODR rules.
Remove unnecessary checking of C in testing_gemm_ex.hpp -- D is sufficient, and is what is tested in the batched versions.
Preparation for upcoming refinement of BFloat16 expected results.
