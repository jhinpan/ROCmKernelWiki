# New Tensile client plus extensive rocBLAS refactoring changes

**Repository:** [ROCm/rocBLAS](https://github.com/ROCm/rocBLAS) · **PR:** [#779](https://github.com/ROCm/rocBLAS/pull/779) · **Merged:** 2019-11-07 · **Author:** @leekillough

**Inclusion reason:** kernel path 'clients/gtest/gemm_gtest.cpp'; keyword 'gemm'

## Summary (from upstream PR description)

Refactor the new Tensile client, combining gemm and gemm_strided_batched into one  RocblasContractionProblem construction (with gemm using a batch_count of 1).
Add logic to determine the directory of librocblas.so at runtime, and to search for Tensile host files in paths relative to librocblas.so's directory location. Exact details to be determined later.
Redefine rocblas_half to _Float16, and replace all _Float16 instances in rocBLAS with rocblas_half, except for the definition of rocblas_half. Simplify code to not have to use float_to_half() and half_to_float() functions. half_to_float() is replaced with an implicit conversion to float (no loss), while float_to_half() is replaced with an explicit conversion to rocblas_half (it should be explicit since it involves loss of precision, although I don't think that the compiler enforces this).
Remove stride_alpha and stride_beta from Level-3 BLAS routines. As discussed in email, Tensile is unlikely to support vectored alpha and beta anytime soon, and Tensile constructs problems with alpha and beta by value, which is hard to do with batched alpha and beta.
