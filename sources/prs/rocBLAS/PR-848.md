## Summary (from upstream PR description)

This is a potential fix for SWDEV-213288.

In gemm, this allows for A = nullptr and B = nullptr when k == 0. In this case, we don't reference A or B so I don't believe there's a reason that A or B need to be checked.
We do not allow alpha to be nullptr in this case yet. This could be addressed in the future.
Added a test & changed bad_arg test name.

This should be able to fix SWDEV-213288 if we want to support this. Alternatively we could not change anything and just say for the future that nothing can be a nullptr in gemm when we are not quick-returning.
