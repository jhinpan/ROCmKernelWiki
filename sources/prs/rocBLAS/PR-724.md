**Inclusion reason:** keyword 'kernel'

## Summary (from upstream PR description)

Wasiq pointed out the negative increment handling offset is constant across batches so pulled it out of the kernel for both batched variants via the offset/shift argument we already added for rocSOLVER.    So do we expect the negative shift being large and so should make offsets rocblas_stride or assume the += N*inc is still fine as int32.   I would lean toward making it a rocblas_stride to allow this optimization.
