# Refactoring of rocBLAS tests

**Repository:** [ROCm/rocBLAS](https://github.com/ROCm/rocBLAS) · **PR:** [#415](https://github.com/ROCm/rocBLAS/pull/415) · **Merged:** 2018-11-12 · **Author:** @leekillough

**Inclusion reason:** kernel path 'clients/gtest/gemm_ex_gtest.cpp'; keyword 'gemm'

## Summary (from upstream PR description)

Refactor host and device memory allocation in terms of host_vector<> and device_vector<> classes

Greatly simplified syntax -- much simpler than overly-complicated unique_ptr usage.
Automatic allocation and deallocation of memory using RAII principles
No need to use .get() or .data() to access address of data; automatic decay of object into pointer to data
device_vector<> has memory guards to detect out of bounds memory corruption during testing


Add rocblas_local_handle class as an automatically created and destroyed rocblas_handle
Explicitly specify both input and output data types in cblas_gemm<>() calls, to avoid ambiguity
Use rocblas_int type instead of int type in some size calculations and loop variables, for consistency in case rocblas_int > int
Use C++11 random number generator
Use static_cast<>() instead of C-style casts in some places
Remove unnecessary casts of pointer arguments in calls, e.g. (const T*)&alpha
Remove spurious return left in testing_scal.hpp
Add alpha == nullptr tests to GEMV
