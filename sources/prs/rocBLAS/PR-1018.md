# Gemm ex profile

**Repository:** [ROCm/rocBLAS](https://github.com/ROCm/rocBLAS) · **PR:** [#1018](https://github.com/ROCm/rocBLAS/pull/1018) · **Merged:** 2020-02-27 · **Author:** @mahmoodw

## Summary (from upstream PR description)

Summary
These changes add a gemm_ex_profile API which accepts events as additional arguments. These events are passed through to the tensile infrastructure that is already in place and used during kernel launch. (Old client and new client)
Implementation
I added default event parameters to the following functions. (default to nullptr as per previous behaviour)
The following carry all parameters to the final tensile launch as always

gemm_ex template
gemm_ex_batched_template
gemm_ex_typecasting
These are the final link between rocBLAS and Tensile
call_tensile_ex (used for the old client)
runContractionProblem (for the new client)

Originally the event parameters were defaulted to nullptrs by the macro and sent through in a similar manner.
I have added this API to a separate header file for a hidden approach. The idea is to separate this implementation from our public APIs and documentation to avoid the necessity of explicit testing and maintenance.
Alternatives
The alternative discussed was to store events in the handle. The reason I lean back towards the current approach is because full control of the events should be given to the developer using the API. Someone using this feature
