# Tune launch overhead

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#220](https://github.com/ROCm/FlyDSL/pull/220) · **Merged:** 2026-03-18 · **Author:** @coderfeli

## Summary (from upstream PR description)

Summary
Optimizes the CPU-side dispatch path for cached @flyc.jit kernels, reducing per-call overhead from ~180µs to ~17µs (~10x improvement). This brings FlyDSL dispatch close to Triton's ~14µs and within ~3x of PyTorch's ~5µs.
Problem
When a @flyc.jit kernel is called repeatedly with the same argument signature (cache hit), the original code re-executes the full argument conversion pipeline on every call:

inspect.Signature.bind() — reconstruct bound args dict
convert_to_jit_arguments() — create DLPack capsules + MLIR TensorAdaptor objects
fly_pointers() — extract ctypes pointer lists from JitArguments
raw_lookup() + CFUNCTYPE() — re-resolve the C function pointer
ArgumentPacker.pack() — pack pointers into (c_void_p * N) array
Steps 2–4 account for ~160µs and are entirely redundant when the argument types/shapes haven't changed.
