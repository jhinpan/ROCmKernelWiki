# [Feat] Add GFX11 WMMA atom (RDNA3 / RDNA3.5, wave32)

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#544](https://github.com/ROCm/FlyDSL/pull/544) · **Merged:** 2026-05-21 · **Author:** @yozhijk

**Inclusion reason:** kernel path 'python/flydsl/expr/rocdl/universal.py'; keyword 'mfma'

## Summary (from upstream PR description)

Motivation
Adds support for the RDNA3 / RDNA3.5 WMMA(16,16,16) wave32 atom so kernels can target gfx1100-gfx1152 (incl. gfx1151 Strix Halo) through the same fx.make_mma_atom + fx.make_tiled_mma + fx.gemm API already used for CDNA3 MFMA and gfx1250 WMMA.
Technical Details
Layout details (RDNA3-specific, see in-file comments + GPUOpen "WMMA on RDNA3" blog):

A/B: 8 VGPRs/lane, 16 elements; lanes 0-15 and 16-31 hold IDENTICAL fragments (stride 0 on the lane/16 axis = broadcast).
C/D (f32 accum): rows are INTERLEAVED between the two lane halves (M = v*2 + lane/16), unlike gfx1250 which packs lane halves contiguously. Getting this wrong shows up as a row permutation in the output.

Lowering targets the legacy v16-operand RDNA3 WMMA ABI via existing ROCDL ops:

rocdl.wmma.f32.16x16x16.f16   (f16  inputs)
rocdl.wmma.f32.16x16x16.bf16  (bf16 inputs, represented as i16)
rocdl.wmma.i32.16x16x16.iu8   (8-bit int  inputs)
rocdl.wmma.i32.16x16x16.iu4   (4-bit int  inputs)

Files:

include/flydsl/Dialect/FlyROCDL/IR/MmaAtom.td : new FlyROCDL_MmaOpGFX11_WMMA type def, mirrors the gfx1250 entry.
lib/Dialect/FlyROCDL/GFX11/MmaAtom.cpp        : layout helpers
(thr/val for A/B and CD_F32), verify(),
