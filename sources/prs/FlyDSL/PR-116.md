# [MLIR][python]Migrate Python bindings to PyConcreteType<> and fix TypeID ODR violation

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#116](https://github.com/ROCm/FlyDSL/pull/116) · **Merged:** 2026-02-10 · **Author:** @jli-melchior

**Inclusion reason:** keyword 'mfma'

## Summary (from upstream PR description)

Major Changes
1. FlyExtension.cpp / FlyROCDLExtension.cpp: Migrate from legacy mlir_type_subclass() to PyConcreteType<> CRTP pattern (required by new MLIR Python binding API). Types are defined inside namespace mlir::python::MLIR_BINDINGS_PYTHON_DOMAIN::fly, using ::mlir:: global qualifiers to avoid the mlir::python::mlir namespace collision when NB_DOMAIN=mlir.
2. CMakeLists.txt (TypeID ODR fix): Remove MLIRFlyDialect / MLIRFlyROCDLDialect from _fly.so / _fly_rocdl.so PRIVATE_LINK_LIBS. These static archives were being linked into both the extension modules AND FlyPythonCAPI.so (via EMBED_CAPI_LINK_LIBS → MLIRCPIFly), creating duplicate TypeID static variables. The dialect registered under FlyPythonCAPI.so's TypeIDs but _fly.so looked up types with its own copy, causing "storage uniquer isn't initialized" at runtime. Now all symbols are resolved from FlyPythonCAPI.so.
3. CMakeLists.txt (PassRegistry ODR fix): Remove MLIRFlyToROCDL from _mlirRegisterEverything.so PRIVATE_LINK_LIBS. This static archive transitively depends on MLIRPass, which was being embedded as a local copy inside _mlirRegisterEverything.so.
