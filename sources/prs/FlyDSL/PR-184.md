# [Fix] Hide LLVM symbols and fix JitArgument type dispatch for vllm/aiter integration

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#184](https://github.com/ROCm/FlyDSL/pull/184) · **Merged:** 2026-03-12 · **Author:** @jli-melchior

**Inclusion reason:** kernel path 'examples/01-vectorAdd.py'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation
When FlyDSL is used inside vllm/aiter with PyTorch on ROCm, two issues arise:


LLVM symbol conflicts: libFlyPythonCAPI.so (LLVM 23) and libamd_comgr.so (LLVM 20) both statically link LLVM. Without symbol isolation, the two LLVM instances share global state (Target Registry, intrinsic definitions), causing SIGABRT during JIT compilation (CallInst: Calling a function with a bad signature).


JIT argument type mismatch: aiter passes torch.nn.Parameter (a torch.Tensor subclass) and raw int cuda_stream pointers to FlyDSL kernels. The JitArgument registry did not handle subclass lookup, and the Stream type silently dropped the raw int stream value during __fly_ptrs__(), breaking CUDA graph capture.


Technical Details
LLVM Symbol Isolation (commits 1-2)

Add linker version script (flydsl_exports.ld) that exports only mlir* C API, mlir:: C++ symbols, and PyInit_*, hiding all llvm:: and LLVM* symbols via local: *; catch-all.
Add -fvisibility=hidden compile option for FlyDSL's own code as defense in depth.
Platform-guarded with if(UNIX AND NOT APPLE).
