# [gfx1250] optimize FP4 GEMM for large tile 256x256

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#340](https://github.com/ROCm/FlyDSL/pull/340) · **Merged:** 2026-04-07 · **Author:** @aoli26

**Inclusion reason:** kernel path 'kernels/gemm_common_gfx1250.py'; keyword 'wmma'

## Summary (from upstream PR description)

Motivation
This PR improves the gfx1250 tile256 FP4 GEMM path by reducing register/LDS pressure and by simplifying the TDM load pipeline without changing the external kernel interface.
Technical Details
Main changes:

Optimized the large-tile FP4 compute schedule in kernels/gemm_fp8fp4_gfx1250.py with a bank-friendly col-band/quadrant ordering to improve tile256 interleave behavior and reduce VGPR pressure.
Replaced the old advance_tdm_descriptor descriptor-advance flow with explicit per-stage LDS base selection plus explicit SGPR address increments. In other words, the kernel now rebuilds the issued descriptor from:

the current logical stage's LDS destination, and
the current global address state for A / B / A_scale / B_scale.


Moved TDM issue points into mid-compute using split signal/wait pipeline fences, so loads can overlap with WMMA work more explicitly.
Reduced epilogue LDS pressure by placing all pipeline stages in a single LDS arena and letting the TDM-store epilogue reuse the dead LDS prefix when it is safe.
Added supporting pipeline/TDM utilities in kernels/gemm_common_gfx1250.py, kernels/pipeline_utils.py, and python/flydsl/expr/rocdl/tdm_ops.py.
Hardened tests/kernel
