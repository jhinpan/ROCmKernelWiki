# [Pass][fly-gpu-to-llvm]  Add fly-gpu-to-llvm pass to preserve asyncObject for graph capture

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#161](https://github.com/ROCm/FlyDSL/pull/161) · **Merged:** 2026-03-02 · **Author:** @jli-melchior

**Inclusion reason:** kernel path 'examples/01-vectorAdd.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
MLIR's upstream gpu-to-llvm pass always generates mgpuStreamCreate / mgpuStreamSynchronize / mgpuStreamDestroy runtime calls, discarding any user-supplied stream (asyncObject) from gpu.launch_func. This makes CUDA/HIP Graph Capture impossible because graph capture requires all GPU operations to execute on the capture stream — creating a new stream during capture triggers hipErrorStreamCaptureUnsupported. The previous workaround used a thread-local (TLS) hack in FlirRocmRuntimeWrappers.cpp to intercept mgpuStreamCreate and redirect it to a capture stream, which was fragile, implicit, and incompatible with multi-stream scenarios.
Technical Details
This PR replaces the TLS stream interception hack with a custom fly-gpu-to-llvm pass — a drop-in replacement for the upstream gpu-to-llvm pass that fixes stream handling at the MLIR pattern level:


fly-gpu-to-llvm pass (lib/Conversion/FlyGpuToLLVM/FlyGpuToLLVM.cpp):

A drop-in replacement for the upstream gpu-to-llvm pass with the same options (use-bare-pointers-for-host, use-bare-pointers-for-kernels, intersperse-sizes-for-kernels).
Reuses all upstream conversion patterns by iterating loaded dialects' ConvertToLLVMPatternInterf
