# [MoE] Optimize reduction by converting model_dim loop to 2D grid dispatch in decode scenarios

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#85](https://github.com/ROCm/FlyDSL/pull/85) · **Merged:** 2026-02-03 · **Author:** @aoli26

**Inclusion reason:** kernel path 'kernels/moe_gemm_2stage.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation

The MoE reduction kernel previously used a sequential for-loop to iterate over the model_dim dimension within each thread block. This approach limits parallelism and can lead to suboptimal GPU utilization, especially for smaller batch sizes in decode scenarios. This PR optimizes the kernel by converting the model_dim iteration into a 2D grid dispatch, enabling better thread block distribution across the GPU.
Technical Details

Kernel Changes (kernels/moe_gemm_2stage.py):

Replaced the range_constexpr(0, model_dim, step) for-loop with a 2D grid index (block_idx("y")) to parallelize work across the model_dim dimension
Changed grid dispatch from 1D (m_tokens, 1, 1) to 2D (m_tokens, num_model_dim_tiles, 1) where num_model_dim_tiles = ceil(model_dim / (BLOCK_SIZE * VEC_WIDTH))
Removed the loop variable step and simplified the tile index computation using tile_n_idx = block_idx("y")

Test Changes (tests/kernels/test_moe_gemm.py):

Updated decode test cases to use more realistic batch sizes (bs=1 and bs=8) instead of (64 and 256) tokens
Renamed test case IDs from decode-S/L to decode-bs1/bs8 for clarity
