# [Build] Prefer Ninja over Make in build.sh

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#364](https://github.com/ROCm/FlyDSL/pull/364) · **Merged:** 2026-04-08 · **Author:** @sjfeng1999

**Inclusion reason:** keyword 'lds'

## Summary (from upstream PR description)

Ninja provides significantly better build performance for MLIR-based projects compared to Unix Makefiles:

Faster incremental builds: Ninja's dependency graph resolution is more efficient, which matters for projects with heavy TableGen (.td -> .inc) codegen pipelines.
Better parallelism: Ninja uses a global dependency graph with global parallel scheduling, avoiding the serialization bottleneck of Make's recursive subdirectory traversal.
More precise rebuilds: Ninja avoids unnecessary rebuilds caused by timestamp-based staleness checks on generated .inc files.
LLVM/MLIR recommended: Ninja is the officially recommended generator for LLVM/MLIR projects and is used in upstream CI.

Falls back to Unix Makefiles when ninja is not installed.
