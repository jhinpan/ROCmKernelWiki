# [Bugfix] Fix HIP graph capture segfault on PyTorch 2.9 / ROCm 7.1

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#171](https://github.com/ROCm/FlyDSL/pull/171) · **Merged:** 2026-03-03 · **Author:** @jli-melchior

**Inclusion reason:** kernel path 'python/flydsl/compiler/jit_argument.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
CUDA/HIP graph capture (torch.cuda.CUDAGraph) segfaults during hipStreamEndCapture when running GEMM kernel graph tests under pytest on the rocm/pytorch:rocm7.1_ubuntu24.04_py3.12_pytorch_release_2.9.1 Docker image. The same tests pass on PyTorch 2.8. This PR addresses three independent issues that together enable reliable graph capture on PyTorch 2.9 / ROCm 7.1.
Technical Details
1. Duplicate sys.path entry causing LLVM double-initialization (tests/conftest.py)
The primary cause of the segfault. In containerized environments where the workspace is bind-mounted at multiple paths (e.g., /home/.../flydsl-prev/ and /data/.../flydsl-prev/), conftest.py added build-fly/python_packages via the resolved container path while PYTHONPATH (set by after_build.sh) already contained the same directory via the host mount path. Python's simple string comparison (if _p not in sys.path) failed to detect the duplicate because the path strings differed despite pointing to the same inode (verified via stat).
