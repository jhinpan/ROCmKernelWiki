# add(rocdl): Support pointer casts and bf16 16x16x16 MFMA

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#288](https://github.com/ROCm/FlyDSL/pull/288) · **Merged:** 2026-03-26 · **Author:** @fsx950223

**Inclusion reason:** kernel path 'python/flydsl/compiler/jit_executor.py'; keyword 'mfma'

## Summary (from upstream PR description)

Motivation
After commit cf3ab62 ([FEAT-DSL] Update FlyToROCDL Conversion to support full dsl types), the MakePtrOpLowering pattern lost its fallback for Shared/Global address space pointers, causing fly.make_ptr with shared memory pointers to fail legalization. This blocks any kernel that uses LDS (shared memory) views.
Additionally, FlyDSL lacked support for the CDNA3 (gfx942) bf16 _1k MFMA variant (mfma_f32_16x16x16bf16_1k), which uses vector<4 x i16> inputs instead of vector<2 x i16>. This is the native bf16 MFMA for MI300X and is required for bf16 tile-programming kernels.
Technical Details
1. MakePtrOpLowering shared/global pointer fix
Restores the Shared/Global fallback path in MakePtrOpLowering::matchAndRewrite that was removed by cf3ab62. When a fly.make_ptr targets a non-Register, non-BufferDesc address space (e.g., Shared), the lowering now:

Converts the FlyDSL pointer type to an LLVM pointer type
If the source value already has the target type, passes it through
Otherwise, emits an LLVM::BitcastOp

2. bf16 16x16x16 MFMA _1k support
Three changes to MmaAtomCallLowering:
