# [Perf] Vectorize MoE reduce kernel via layout API for f16/bf16

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#360](https://github.com/ROCm/FlyDSL/pull/360) · **Merged:** 2026-04-08 · **Author:** @coderfeli

**Inclusion reason:** kernel path 'kernels/moe_blockscale_2stage.py'; keyword 'gemm'

## Summary (from upstream PR description)

Use buffer-backed layout API (make_buffer_tensor + copy_atom_call with BufferCopy128b) for f16/bf16 MoE reduction, replacing scalar buffer_load per-element with 8-wide vector loads. This gives up to 1.1x improvement at small and large batch sizes.
Key changes:

Add max_size parameter to make_buffer_tensor (default True) to handle dynamic tensor shapes safely with JIT cache reuse
MoE reduce: vector path via layout API for f16/bf16, scalar fallback for f32 (no BufferCopy256b available)
Switch from per-element num_records computation to max_size=True for X and Y buffer resources
