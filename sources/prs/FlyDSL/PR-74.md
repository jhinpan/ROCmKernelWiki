# [MoE] Support non-atomic reduce path for Stage2 large prefill workloads

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#74](https://github.com/ROCm/FlyDSL/pull/74) · **Merged:** 2026-01-29 · **Author:** @aoli26

**Inclusion reason:** kernel path 'kernels/moe_gemm_2stage.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
MoE GEMM Stage2 kernel uses atomic operations to accumulate results from multiple expert outputs into the final output tensor. For large prefill workloads (e.g., tokens=32768, topk=8, model_dim=7168), atomic contention becomes a significant performance bottleneck.
This PR introduces an alternative reduce mode that avoids atomic contention by:

Writing per-(token, slot) results to an expanded intermediate buffer [tokens*topk, model_dim]
Reducing over the topk dimension to produce the final [tokens, model_dim] output

This approach trades off extra memory bandwidth for reduced atomic contention, which can be beneficial for specific workload shapes.
Technical Details
New Components in kernels/moe_gemm_2stage.py:


compile_moe_reduction(): Compiles a vectorized reduction kernel that sums over the topk dimension

Uses VEC_WIDTH=8 for coalesced memory access
Supports f16/bf16/f32 data types



compile_moe_gemm2_ex(): Extended compilation interface with automatic mode selection

mode=MoeGemm2Mode.AUTO: Auto-select based on shape matching rules
mode=MoeGemm2Mode.ATOMIC: Force atomic accumulation (original behavior)
mode=MoeGemm2Mode.REDUCE: Force reduce mode



MoeGemm2Mode: Enu
