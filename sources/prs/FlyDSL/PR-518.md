# [Refactor] Refactor the allreduce kernel by high-level FlyDSL APIs

**Repository:** [ROCm/FlyDSL](https://github.com/ROCm/FlyDSL) · **PR:** [#518](https://github.com/ROCm/FlyDSL/pull/518) · **Merged:** 2026-05-15 · **Author:** @yanboshao

**Inclusion reason:** kernel path 'kernels/custom_all_reduce_kernel.py'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation

Refactor the custom allreduce kernels to favor high-level FlyDSL APIs over low-level MLIR-style patterns.
Technical Details


Replace many arith-style operations with Python-native operators (+, -, *, /, comparisons, and select-style expressions) to make kernel logic easier to follow.
Simplify constant handling: remove redundant constant wrapping where FlyDSL can infer types, while keeping explicit ea.constant(..., type=...) only at type-sensitive boundaries (for example, select operands and index/type-critical paths).
Convert vector/data-path code to fx.Vector-centric usage and reduce scattered raw IR conversions by centralizing low-level interactions in small helpers.
Add numeric proxy compatibility updates in python/flydsl/expr/numeric.py (with_signedness, extui) to align with existing proxy-style APIs.
