# [AMD] Add Kimi-K2.6 in nightly tests for MI30x and MI35x

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#23848](https://github.com/sgl-project/sglang/pull/23848) · **Merged:** 2026-05-05 · **Author:** @michaelzhang-ai

**Inclusion reason:** kernel path 'test/registered/amd/accuracy/mi30x/test_kimi_k26_eval_amd.py'; keyword 'attention'

## Summary (from upstream PR description)

Summary
Replaces moonshotai/Kimi-K2.5 with moonshotai/Kimi-K2.6 in the AMD nightly test suites for MI30x (MI325/MI300X) and MI35x (MI355X). Adds full accuracy + performance test coverage for K2.6 and removes the K2.5 wiring from both nightly workflows.
Kimi-K2.6 shares the same architecture as Kimi-K2.5 — per the model card the deployment method is directly reused. A diff of the two HF config.json files confirms the only delta is eos_token_id (163585 → 163586):
$ diff <(curl -s https://huggingface.co/moonshotai/Kimi-K2.5/raw/main/config.json | python3 -m json.tool) \
       <(curl -s https://huggingface.co/moonshotai/Kimi-K2.6/raw/main/config.json | python3 -m json.tool)
12c12
<     "eos_token_id": 163585,
---
>     "eos_token_id": 163586,
42c42
<         "eos_token_id": 163585,
---
>         "eos_token_id": 163586,

So the K2.6 tests reuse the K2.5 AMD server arguments verbatim (mixed prefill/decode: --prefill-attention-backend aiter --decode-attention-backend triton, SGLANG_USE_AITER=1, SGLANG_ROCM_FUSED_DECODE_MLA=0).
