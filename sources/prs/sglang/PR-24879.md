# [AMD] support fp8 blockwise quantization combine for mori ep

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#24879](https://github.com/sgl-project/sglang/pull/24879) · **Merged:** 2026-05-13 · **Author:** @billishyahao

**Inclusion reason:** kernel path 'python/sglang/srt/layers/moe/token_dispatcher/moriep.py'; keyword 'moe'

## Summary (from upstream PR description)

Motivation
This patch is to add FP8 blockwise quantization support for the combine in Mori EP dispatcher, complementing the existing FP8/FP4 dispatch quantization. Fix issue #24866
Work with ROCm/mori#311
cc @Duyi-Wang @HaiShaw

Modifications

Introduce DispatchDtype and CombineDtype enums to replace boolean flags (fp8_dispatch, fp4_dispatch), making the dtype configuration more extensible and type-safe.
Add CombineDtype.fp8 (fp8_blockwise) as a new combine quantization mode alongside the existing fp8_direct_cast.
Add new env var SGLANG_MORI_COMBINE_DTYPE (auto|bf16|fp8|fp8_direct_cast) for explicit combine dtype control.
Unify dispatch dtype env var: SGLANG_MORI_DISPATCH_DTYPE (auto|bf16|fp8|fp4) replaces deprecated SGLANG_MORI_FP8_DISP / SGLANG_MORI_FP4_DISP.
Deprecated env vars (SGLANG_MORI_FP8_DISP, SGLANG_MORI_FP4_DISP, SGLANG_MORI_FP8_COMB) are still supported with deprecation warnings.
Auto-detect default combine dtype from model weight type: FP4 models default to fp8_blockwise combine, FP8 models default to bf16 combine.
Pass dispatch_dtype / combine_dtype enums (instead of booleans) through init_mori_op() and _MoriEPDispatcherImplBase.


Accuracy Tests
