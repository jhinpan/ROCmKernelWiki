Motivation

This PR introduced an optimized Triton-based sparse MLA kernel as an alternative to the existing TileLang implementation for DpSk V4. The kernel is selectable via environment variable SGLANG_HACK_FLASHMLA_BACKEND=triton with zero changes to the serving logic.
Key changes:

Add Triton kernel implementations for sparse MLA, controlled by env var SGLANG_HACK_FLASHMLA_BACKEND=triton
Fix autotuning recompilation, add CUDA graph early-exit
Reduce more autotune configs for saving more kernel compilations on first startup

Modifications


Modified debug_flash_mla_adapter.py: add 'triton' backend dispatch path, lazy-load tilelang
New files under python/sglang/srt/layers/attention/nsa/triton_decode/:

__init__.py: adapter bridging flash_mla interface to Triton kernels
triton_mla_kernels_decode_common.py: shared utilities
triton_mla_kernels_decode_dsv4.py: DSV4-specific kernel
triton_mla_kernels_decode_fused.py: fused attention kernel
triton_mla_kernels_decode_optimized.py: optimized entry point
