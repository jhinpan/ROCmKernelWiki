# [MoE] Add Aiter MoE runner backend and purge aiter.fused_moe from quant methods

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#23597](https://github.com/sgl-project/sglang/pull/23597) · **Merged:** 2026-05-01 · **Author:** @ch-wan

**Inclusion reason:** kernel path 'python/sglang/srt/layers/moe/moe_runner/aiter.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
Part of the MoE refactor roadmap tracked in #8715.
Today, aiter.fused_moe is called directly from seven quantization methods (fp8.py, mxfp4.py, unquant.py, quark_int4fp8_moe.py, quark/schemes/quark_w4a4_mxfp4_moe.py, compressed_tensors/schemes/compressed_tensors_w8a8_fp8_moe.py). Each call site duplicates roughly the same ~15 arguments, re-implements apply_router_weight_on_input and topk_weights casting, and is invisible to the unified MoeRunner framework introduced in #9269. This PR adds a proper aiter MoE runner backend so the quant methods can all funnel through MoeRunner with an AiterMoeQuantInfo payload, mirroring what triton.py, marlin.py, triton_kernels.py, and flashinfer_trtllm.py already do.
The explicit goal is: no quant method should reach for aiter.fused_moe directly anymore.
Modifications
New runner backend


python/sglang/srt/layers/moe/moe_runner/aiter.py

AiterQuantType — string-valued enum that mirrors aiter.QuantType (NONE / PER_TOKEN / PER_128X128 / PER_1X32) so the quant methods do not need to import the real AITER enum at module load time.
