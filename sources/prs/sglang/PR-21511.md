# [AMD] Enable FP8 KV cache and FP8 attention kernel for NSA on MI300/MI355 with TileLang backend

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#21511](https://github.com/sgl-project/sglang/pull/21511) · **Merged:** 2026-04-03 · **Author:** @1am9trash

**Inclusion reason:** kernel path 'python/sglang/srt/layers/attention/nsa/tilelang_kernel.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation

Enable FP8 KV cache and FP8 attention kernel for NSA on MI300/MI355 with TileLang backend.
Modifications


Upgraded TileLang to a55a823 to enable FP8 gemm support on AMD GPUs.
Added an FP8 attention kernel, sparse_mla_fwd_decode_partial_fp8, while reusing the existing reduce kernel.
Fused quantization path:

On MI355, reused fused_qk_rope_cat_and_cache_mla for both Q and KV quantization.
On MI300, added a Triton kernel, set_mla_kv_buffer_fp8_quant, for KV cache quantization.



To enable this feature, set --kv-cache-dtype fp8_e4m3 in the server launch command:
DSV32 server cmd:
python3 -m sglang.launch_server \
  --model DeepSeek-V3.2 \
  --tp 8 \
  --port 9000 --trust-remote-code \
  --nsa-prefill-backend tilelang --nsa-decode-backend tilelang \
  --disable-radix-cache --mem-fraction-static 0.85 --kv-cache-dtype fp8_e4m3

GLM5 server cmd:
export SGLANG_ROCM_FUSED_DECODE_MLA=0 
export ROCM_QUICK_REDUCE_QUANTIZATION=INT4 
export SAFETENSORS_FAST_GPU=1 
python3 -m sglang.launch_server \
  --model-path GLM-5-FP8 \
  --tp 8 \
  --port 9000 --trust-remote-code \
  --tool-call-parser glm47 --reasoning-parser glm45 \
  --mem-fraction-static 0.85 \
  --model-loader-extra-config
