# [MLX] Support Qwen3.5 (dense) Model

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25754](https://github.com/sgl-project/sglang/pull/25754) · **Merged:** 2026-05-30 · **Author:** @yeahdongcn

**Inclusion reason:** kernel path 'python/sglang/srt/hardware_backend/mlx/kv_cache/attention_contract.py'; keyword 'attention'

## Summary (from upstream PR description)

Motivation

Qwen3.5 hybrid models do not follow the older uniform self_attn decoder-layer layout. The MLX backend failed to start Qwen3.5 models because attention discovery assumed the first decoder layer was a standard softmax-attention layer, while Qwen3.5 can start with a linear-attention layer.
Qwen3.5 also advertises image understanding. Server warmup therefore selected the VLM image path, which reaches Qwen3-VL fast image processing and fails on Apple Silicon MLX with Torch not compiled with CUDA enabled. /model_info should stay truthful, but MLX warmup needs to route through text generation until MLX image warmup is supported.
After Qwen3.5 could start, radix cache support also needed to become model-layout aware. The previous MLX KV-cache path was mostly designed around Qwen3-0.6B dense attention. Qwen3.5 requires a unified radix cache that can reuse softmax-attention KV while also preserving native mlx-lm auxiliary state for non-softmax layers.
Modifications


Added shared MLX attention contract helpers for duck-typed attention detection, head-count aliases, and head-dimension lookup.
Updated MLX attention patching to discover attention per layer and patch only supported s
