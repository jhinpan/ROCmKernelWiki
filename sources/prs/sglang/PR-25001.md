# [LoRA] MLA attention LoRA: q_b_proj / kv_b_proj support

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25001](https://github.com/sgl-project/sglang/pull/25001) · **Merged:** 2026-05-13 · **Author:** @jybsuper

**Inclusion reason:** kernel path 'python/sglang/srt/lora/deepseek_mla_correction.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
DeepSeek-style MLA attention has four projections that an adapter checkpoint may target — q_a_proj, kv_a_proj_with_mqa, q_b_proj, kv_b_proj — but on main only the *_a_* pair is wired up (via the fused fused_qkv_a_proj_with_mqa, added in #22323). Adapters that include q_b_proj or kv_b_proj (e.g. Kimi-K2.5 LoRA fine-tunes) either fail target-module validation at load time, or silently drop those modules.
kv_b_proj is the harder case. In the absorbed-MLA path the runtime never calls kv_b_proj.forward() — the K/V contribution is folded into two BMMs against the pre-computed w_kc / w_vc:
q_nope_out      = q_nope     @ w_kc                # K-half of kv_b absorbed into Q
attn_bmm_output = attn_output @ w_vc                # V-half of kv_b absorbed into O input

so a standard ColumnParallelLinearWithLoRA wrapper would never fire. The LoRA delta has to be added back manually:
q_nope_out      += (q_nope     @ B_kc @ A   ) * scaling           # K-side correction
attn_bmm_output += (attn_output @ A.T @ B_vc.T) * scaling           # V-side correction
