Motivation

In last week's aiter bump, we discovered a small-batch accuracy issue which is caused by aiter commit 7ac56a.
In fused_moe.py's cktile_moe_stage1(), small batches take the split_k > 1 code path; in that path, aiter assumes the MoE weights are stored in an interleaved layout, which leads to incorrect results. On large batches split_k == 1, so accuracy is unaffected.
In this PR, we switch the MoE to the new flydsl implementation and add the matching weight layout handling (from Kk's branch last week), which resolves the issue. We also drop the cherry-picked aiter commit in this PR, and adapt to the new aiter API.
