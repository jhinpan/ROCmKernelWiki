# [docs] DeepSeek-V4 cookbook: split Quantization axis, add H100 SGLang FP8

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#26057](https://github.com/sgl-project/sglang/pull/26057) · **Merged:** 2026-05-22 · **Author:** @zijiexia

**Inclusion reason:** keyword 'flash'

## Summary (from upstream PR description)

Motivation
The DeepSeek-V4 cookbook currently encodes the FP4 / FP8 choice into the hardware radio label itself (H200 (FP8) vs H200 (FP4), etc.). That conflates two orthogonal dimensions, hides the H100 SGLang-FP8 path entirely, and forces the user to mentally translate between "hardware I have" and "checkpoint I want to run."
This PR splits the two: hardware row is just the GPU (B200 / B300 / GB200 / GB300 / H200 / H100), and a new Quantization row picks FP4 (default) or SGLang FP8. SGLang FP8 is greyed out everywhere except H100 and H200, and on H100 the Pro variant stays greyed (only Flash FP8 ships).
It also fills in the previously-Pending update benchmark cells from the upstream cookbook rerun.
Modifications
docs_new/src/snippets/autoregressive/deepseek-v4-deployment.jsx — structural refactor; no command changes.

Hardware radio: drop (FP4) / (FP8) suffixes, remove the h200-fp4 entry.
New Quantization axis: FP4 (default) / SGLang FP8 (subtitle "H100/H200 only").
Internal effHw(hardware, quantization) translates the new (hw, quant) pair back into the existing spec keys (h200-fp4, h200, h100, h100-fp8), so HW_SIZE_SPEC / PD_TP_SPEC / VERIFIED_RECIPES keep working unchanged.
