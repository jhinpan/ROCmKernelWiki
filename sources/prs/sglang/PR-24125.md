# [AMD] Skip redundant CatArrayBatchedCopy in GLM-5 NSA TileLang decode

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#24125](https://github.com/sgl-project/sglang/pull/24125) · **Merged:** 2026-05-13 · **Author:** @Jacob0226

**Inclusion reason:** kernel path 'python/sglang/srt/layers/attention/nsa_backend.py'; keyword 'attention'

## Summary (from upstream PR description)

Motivation
In GLM-5 NSA TileLang decode on ROCm, the fused-rope path dispatches a redundant CatArrayBatchedCopy<OpaqueType<1u>, ...> kernel once per layer per decode step that rebuilds an already-existing tensor.
The cause: fused_qk_rope_cat_and_cache_mla produces a contiguous q_cat of shape (M, num_heads, kv_lora_rank + qk_rope_head_dim). The pre-patch flow then

slices q_cat into q_nope_fused / q_pe_fused,
passes them as separate args to attn_mqa,
nsa_backend.forward_decode calls concat_mla_absorb_q_general(q_nope, q_rope) to rebuild q_all,
on ROCm that helper falls back to torch.cat([q_nope, q_rope], dim=-1), dispatching CatArrayBatchedCopy to produce a tensor byte-identical to the q_cat we already had.

The cat is pure overhead — same data, same layout, fresh allocation + copy.
Modifications
(1) forward_absorb_core in deepseek_common/attention_forward_methods/forward_mla.py now passes q_cat directly to attn_mqa with q_rope=None on the decode path. Prefill keeps the split form because nsa_backend.forward_extend asserts q_rope is not None.
(2) forward_decode in layers/attention/nsa_backend.py now tracks q_all explicitly:

When the caller passes split q_nope / q_rope, q_all = None
