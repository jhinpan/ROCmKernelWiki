# [AMD][Dockerfile] Support build-arg AITER_COMMIT for rocm.Dockerfile

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#21949](https://github.com/sgl-project/sglang/pull/21949) · **Merged:** 2026-04-03 · **Author:** @Duyi-Wang

**Inclusion reason:** keyword 'gfx942'

## Summary (from upstream PR description)

Motivation
Previously, the AITER commit/tag was hardcoded via ENV AITER_COMMIT in each base-image stage of rocm.Dockerfile. This meant switching to a different AITER version required editing the Dockerfile directly — there was no way to parameterize it at build time via --build-arg, unlike other dependencies (e.g. TRITON_COMMIT, SGL_BRANCH).
Changes

docker/rocm.Dockerfile: Rename ENV AITER_COMMIT to ENV AITER_COMMIT_DEFAULT in all four base-image stages (gfx942, gfx942-rocm720, gfx950, gfx950-rocm720). Add ARG AITER_COMMIT="" with a fallback ENV AITER_COMMIT="${AITER_COMMIT:-${AITER_COMMIT_DEFAULT}}", so users can override via --build-arg AITER_COMMIT=<ref> while keeping the current default.
scripts/ci/amd/amd_ci_install_dependency.sh: Update the grep/sed patterns to match the renamed AITER_COMMIT_DEFAULT so CI version extraction continues to work correctly.

Usage
# Use default AITER version (v0.1.11.post1) — no change from before
docker build --build-arg GPU_ARCH=gfx942 -f docker/rocm.Dockerfile .

# Override AITER version at build time
docker build --build-arg GPU_ARCH=gfx942 --build-arg AITER_COMMIT=v0.1.11.post1 -f docker/rocm.Dockerfile .
