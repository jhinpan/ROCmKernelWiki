# [AMD][MoRI] Auto-select dispatch quantization type from MoE weight dtype.

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#21040](https://github.com/sgl-project/sglang/pull/21040) · **Merged:** 2026-03-25 · **Author:** @Duyi-Wang

**Inclusion reason:** kernel path 'python/sglang/srt/layers/moe/token_dispatcher/moriep.py'; keyword 'moe'

## Summary (from upstream PR description)

Motivation
Previously, MoRI EP dispatch quantization type (BF16/FP8/FP4) was controlled entirely by environment variables (SGLANG_MORI_FP8_DISP / SGLANG_MORI_FP4_DISP), requiring users to manually set them to match the model's weight type. This was error-prone and inconvenient.
This PR makes MoRI EP automatically detect the dispatch quantization type from the loaded MoE weight dtype, so that the correct dispatch path is selected without manual configuration:

BF16 weights → BF16 dispatch (no quantization)
FP8 weights (float8_e4m3fn / float8_e4m3fnuz) → FP8 dispatch
MXFP4 weights (float4_e2m1fn_x2) → FP4 dispatch

The two boolean env vars are replaced by a single SGLANG_MORI_DISPATCH_DTYPE env var (auto/bf16/fp8/fp4) for advanced users who need to force a specific dispatch type.
Modifications

moriep.py:

Removed _get_mori_dispatch_quant_flags() (env-var-only approach).
Added fp8_dispatch / fp4_dispatch parameters to init_mori_op().
Changed mori_op to a @property with lazy initialization — the op is created on first access rather than eagerly in __init__, since set_quant_config is called after construction during process_weights_after_loading.
set_quant_config() in _MoriEPDispatcher
