# Fix LFM2 ShortConv Mamba State Indexing

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#23975](https://github.com/sgl-project/sglang/pull/23975) · **Merged:** 2026-04-30 · **Author:** @hubertlu-tw

**Inclusion reason:** kernel path 'python/sglang/srt/models/lfm2.py'; keyword 'moe'

## Summary (from upstream PR description)

Motivation
This PR fixes LFM2/LFM2-MoE short-convolution state indexing in SGLang.
LFM2 uses a hybrid cache:

request/token pool indices identify request rows
Mamba/short-conv state indices identify persistent convolution state rows

These are separate namespaces. The LFM2 short-conv path was using req_pool_indices directly as convolution state indices. The fix maps request indices to Mamba state indices before calling the convolution kernels.
Root Cause
HybridReqToTokenPool allocates a separate Mamba state slot per request and records the mapping:
req_index_to_mamba_index_mapping[req_pool_idx] = mamba_pool_idx
The correct API is:
mamba_indices = req_to_token_pool.get_mamba_indices(req_pool_indices)
But Lfm2ShortConv.forward() and Lfm2MoeShortConv.forward() passed req_pool_indices directly:
conv_state_indices=req_pool_indices.to(torch.int32)
cache_indices=req_pool_indices.to(torch.int32)
This can read/write the wrong Mamba/conv-state slot. Slot 0 in MambaPool is reserved as the padded dummy slot, while real Mamba slots are allocated from 1..size.
Fix
In both LFM2 short-conv implementations:
req_pool_indices = forward_batch.req_pool_indices
mamba_indices = forward_batch.req_to_token
