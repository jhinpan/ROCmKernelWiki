# [AMD]  Auto-fallback NSA indexer to page_size=1 when aiter preshuffle gluon kernel is unavailable (Deepseek v3.2)

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25205](https://github.com/sgl-project/sglang/pull/25205) · **Merged:** 2026-05-14 · **Author:** @yctseng0211

**Inclusion reason:** kernel path 'python/sglang/srt/layers/attention/nsa/index_buf_accessor.py'; keyword 'attention'

## Summary (from upstream PR description)

Motivation
#23562 unconditionally bumped the ROCm NSA indexer to page_size=64, Preshuffle=True, KVBlockSize=64, plus indexer_k_quant_and_cache(..., preshuffle=True) and the new cp_gather_indexer_k_quant_cache aiter path. All of these require aiter's gluon kernel, which aiter itself gates on:
# aiter/ops/triton/attention/pa_mqa_logits.py
if triton_version >= Version("3.5.0"):
    enable_gluon_pa_mqa_logits = True
else:
    enable_gluon_pa_mqa_logits = enable_aot_gluon_pa_mqa_logits  # AITER_ENABLE_AOT_GLUON_PA_MQA_LOGITS=1
...
if enable_gluon_pa_mqa_logits:
    ...
else:
    assert KVBlockSize == 1
    assert not Preshuffle, "Preshuffle mode is only supported on gluon kernel."
The aiter dependency from #23562 (PR ROCm/aiter#2879) is satisfied (the pinned aiter commit a6bb499 includes it), but the Triton-version dependency wasn't documented or enforced, so on the default rocm700 CI base image (Triton<3.5, no AOT bundle) we hit the legacy aiter branch and crash.
This PR makes the NSA indexer auto-detect at startup whether the preshuffle path is usable, and gracefully falls back to the previous page_size=1 / KVBlockSize=1 / Preshuffle=False configuration when it isn't, so the rocm700 C
