# [docs] Qwen3.5 cookbook: multi-node, MTP TP overrides, dense mamba flag

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#26695](https://github.com/sgl-project/sglang/pull/26695) · **Merged:** 2026-05-29 · **Author:** @zijiexia

**Inclusion reason:** keyword 'flash'

## Summary (from upstream PR description)

Summary

Add multiNodeFlags / prependMultiNodeNote helpers (mirroring the DeepSeek-V4 cookbook) so 397B H100 BF16 correctly emits TP=16 across 2 nodes with --nnodes / --node-rank / --dist-init-addr wiring and a multi-node note above the command.
MTP-conditional TP overrides: 35B / 27B H100 BF16 → TP=2, 122B H100 FP8 → TP=4 (all skip --mem-fraction-static when MTP is on).
Tune base TP / mem-frac: 122B H100 BF16 mem 0.8 → 0.88; 122B H200 BF16 TP=4, 122B H200 FP8 TP=2, 122B B300 BF16 TP=2 (all drop --mem-fraction-static); 35B H100 BF16 mem 0.8 → 0.88.
Dense models on NVIDIA + MTP now emit --mamba-scheduler-strategy extra_buffer (the existing mambaCache rule now bypasses its UI-only condition gate).
B300 0.8B / 2B BF16 workaround: --max-running-requests 4064 to dodge a CUDA grid-dim overflow in the GDN packed_decode Triton kernel during FlashInfer autotune warmup.
--mem-fraction-static is now only emitted when the spec sets mem, so configs can opt out cleanly.

Test plan

 Toggle each (model, hardware, quantization, MTP) combination in the cookbook UI and confirm the generated command matches the updated spec.
 397B H100 BF16: multi-node note + 2-node flags render above sglang serve.
