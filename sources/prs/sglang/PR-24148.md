# [AMD] Add _skip_rope_for_aiter_fused_mla method and check to avoid double rotating with gfx950 and Aiter backend

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#24148](https://github.com/sgl-project/sglang/pull/24148) · **Merged:** 2026-05-13 · **Author:** @amd-mvarjoka

**Inclusion reason:** kernel path 'python/sglang/srt/models/deepseek_common/attention_forward_methods/forward_mla.py'; keyword 'attention'

## Summary (from upstream PR description)

Aiter backend can be used for DeepSeek 3.2 and models with similar model architecture like the GLM5 to run the models on AMD Instinct. There is some differences in the optimizations and code path used for the MI30X and MI35X GPUs. The accuracy is fine when running on MI300X GPUs. However, there is currently an issue with the model output and accuracy when running on MI35X series GPUs.
Steps to reproduce the issue
Use some recent container, for example:
rocm/sgl-dev:v0.5.10.post1-rocm720-mi35x-20260503
Server launch command:
SGLANG_USE_AITER=1 \
python3 -m sglang.launch_server \
  --model deepseek-ai/DeepSeek-V3.2 \
  --port 8000 \
  --tensor-parallel-size 8 \
  --attention-backend aiter \
  --nsa-prefill-backend aiter \
  --nsa-decode-backend aiter \
  --trust-remote-code \
  --disable-radix-cache

Run Gsm8k benchmark command with lm-eval:
pip install lm-eval[api]
lm_eval               0.4.11
lm-eval --model local-completions --tasks gsm8k --model_args base_url=http://localhost:8000/v1/completions,model=deepseek-ai/DeepSeek-V3.2,tokenized_requests=False,tokenizer_backend=None,num_concurrent=64,timeout=180,max_retries=5 --batch_size 64
