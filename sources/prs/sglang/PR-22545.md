# feat: add weekly workflow to update CI test est_time values

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#22545](https://github.com/sgl-project/sglang/pull/22545) · **Merged:** 2026-04-10 · **Author:** @ch-wan

## Summary (from upstream PR description)

Motivation
The est_time values in CI test registration calls (register_cuda_ci, register_cpu_ci) drift from actual execution times over time. These values drive the LPT load-balancing algorithm that partitions tests across parallel CI jobs. Inaccurate estimates lead to unbalanced partitions, wasting CI resources.
This PR adds automation to keep est_time values up to date by computing them from real CI data.
Modifications

Add scripts/ci/update_est_time.py: Python script that fetches logs from recent scheduled PR Test runs on main, parses per-file elapsed times from successful jobs (including successful jobs within failed/cancelled runs), computes the median of the last 10 executions per test file, and updates est_time literals via regex.
Add .github/workflows/weekly-update-est-time.yml: Weekly workflow (Saturday 00:00 UTC) that runs the script and creates a PR with any changes.
Currently only NVIDIA backends (CUDA + CPU) are supported. Other backends (AMD, NPU, etc.) will be added in the future.
