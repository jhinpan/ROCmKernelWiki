# [ROCm]fix(aiter): cast fp8 prefill output back to model dtype

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#22626](https://github.com/sgl-project/sglang/pull/22626) · **Merged:** 2026-04-14 · **Author:** @xiaobochen-amd

**Inclusion reason:** kernel path 'python/sglang/srt/layers/attention/aiter_backend.py'; keyword 'attention'

## Summary (from upstream PR description)

Motivation
MiniMaxAI/MiniMax-M2.5 produces corrupted output with --attention-backend aiter --kv-cache-dtype fp8_e4m3.
The root cause is that the fp8 aiter prefill kernel can return bf16 while the model compute dtype is fp16, which introduces a dtype mismatch in the forward pass.
Modifications
Cast the fp8 aiter prefill output back to the model dtype before it is consumed by the rest of the model.
Accuracy Tests

Reproduced the issue on MiniMaxAI/MiniMax-M2.5
Before the fix: corrupted output
After the fix: output is correct

Speed Tests and Profiling
No dedicated benchmark yet. This change only adds a dtype cast on the fp8 prefill output, so speed impact is expected to be negligible.
