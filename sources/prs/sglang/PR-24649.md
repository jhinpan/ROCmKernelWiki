# [Xeon] CPU CI enhancement for Intel Xeon platforms

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#24649](https://github.com/sgl-project/sglang/pull/24649) · **Merged:** 2026-05-28 · **Author:** @MingxuZh

**Inclusion reason:** keyword 'quant'

## Summary (from upstream PR description)

Summary
This PR improves Xeon CI reliability and coverage for CPU tests by fixing Hugging Face cache/token setup on self-hosted Xeon runners, expanding base-b-test-cpu registrations, and running the suite in 2 auto-partitioned shards to keep runtime manageable.
Motivation
The previous Xeon workflow had a few practical issues:

It mounted a fixed Hugging Face cache path (/home/sdp/.cache/huggingface) that does not match current Xeon CI runner environments.
Some model-dependent tests require Hugging Face authentication, but HF_TOKEN was not injected into the container.
Xeon base-b-test-cpu coverage was narrower than desired for AMX/CPU-engine validation.
As more tests are included, a single-shard execution can become slow and unstable near timeout limits.

This PR addresses these gaps so Xeon CI can run a broader and more representative CPU test set with better stability.
What Has Been Changed
1) Xeon workflow updates (.github/workflows/pr-test-xeon.yml)

Added workspace cleanup before checkout for self-hosted runner hygiene.
Set checkout clean: false to avoid workspace cleanup conflicts.
Replaced fixed HF cache mount with runner-local cache mount:

from ${HF_HOME} (/home/sdp/.cache/
