# Flux2 nvfp4 quantization correctness on Blackwell (B200)

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#23625](https://github.com/sgl-project/sglang/pull/23625) · **Merged:** 2026-05-02 · **Author:** @Johnsonms

**Inclusion reason:** kernel path 'python/sglang/multimodal_gen/runtime/layers/mlp.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
FLUX.2-dev-NVFP4 generated pure-white images (mean pixel ≈252, std ≈2) on B200 (Blackwell,
sm_100) while the BF16 checkpoint produced correct output on the same hardware.
A two-day investigation, plus subsequent code review, surfaced three correctness bugs that
exist on upstream main — all of which this PR fixes — and one investigation thread that
turned out not to need a code change. Restoring NVFP4 image quality on Blackwell requires all
three real fixes together:

Mixed checkpoint omits 64 input_scale tensors, so runtime activation scales default to 1.0
CUTLASS TMA scale permutation applied unconditionally; cuDNN/flashinfer expects raw
row-major scales
Custom SGLang NVFP4 loader silently falls back to native diffusers BF16 on current main
(3 sub-fixes restore the custom path)

A fourth thread — the BFL nibble-swap convention — consumed real debugging time and produced
strong byte-level evidence (cos_sim ≈ 0 without swap, ≈ 0.99 with swap). It is documented for
postmortem completeness, but per code review the runtime already defaults to the correct
