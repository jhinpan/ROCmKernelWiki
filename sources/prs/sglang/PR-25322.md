# Deprecate /rerun-stage; scrub CUDA target_stage infra

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25322](https://github.com/sgl-project/sglang/pull/25322) · **Merged:** 2026-05-15 · **Author:** @hnyls2002

**Inclusion reason:** kernel path '.github/workflows/_pr-test-sgl-kernel-build.yml'; keyword 'kernel'

## Summary (from upstream PR description)

Summary

Deprecate /rerun-stage; handler now posts a -1 reaction + deprecation comment pointing to /rerun-test, /rerun-failed-ci, or the run-ci / run-ci-extra labels
Remove all target_stage / pr_head_sha / include_wheel_build infrastructure from the CUDA workflow chain
AMD workflows kept untouched — AMD team's UI-dropdown dispatch still works

Background

/rerun-stage dispatches a single stage out of pr-test.yml. Stage granularity is too coarse to map to one feature: rerunning a stage re-pays the cost of unrelated tests. Users who know which test files to verify should use /rerun-test instead
Six-month usage: /rerun-stage had ~111 PR-comment hits, mostly from 2 contributors; /rerun-test had 268 hits and /rerun-failed-ci had 320 hits
AMD team (5 engineers, ~177 dispatches over 6 months) triggers stages via the Actions UI dropdown (target_stage_select), not via the slash command, so the AMD path is intentionally preserved

Changes
Python handler (scripts/ci/utils/slash_command_handler.py)

Delete handle_rerun_stage() (~213 lines)
/rerun-stage branch now sends a deprecation comment + -1 reaction; AMD users are pointed to the Actions UI dropdown
slash-command-handler.yml keeps the /rer
