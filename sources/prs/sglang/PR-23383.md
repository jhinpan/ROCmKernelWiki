# [AMD] Fix Grok-2 nightly: avoid multimodal misdetection from auto-populated vision_config

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#23383](https://github.com/sgl-project/sglang/pull/23383) · **Merged:** 2026-04-27 · **Author:** @bingxche

**Inclusion reason:** kernel path 'python/sglang/srt/configs/model_config.py'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation
The nightly-8-gpu-grok2 job has been failing because the SGLang server fails to launch:
ValueError: Unrecognized model in alvarobartt/grok-2-tokenizer.
Should have a `model_type` key in its config.json.

Failing run: https://github.com/sgl-project/sglang/actions/runs/24681631067/job/72180128217
Root cause
xai-org/grok-2 is a text-only model that dispatches to SGLang's native Grok1ForCausalLM, but its HF config.json declares "model_type": "git" (a hack to satisfy HF). HF's GitConfig.__post_init__ then auto-populates a vision_config = GitVisionConfig().
Commit 34ddf13 (#19163) introduced the has_multimodal_subconfig heuristic to detect VLMs without a native SGLang implementation that should be loaded through the transformers backend:
has_multimodal_subconfig = (
    self.hf_config is not self.hf_text_config
    or hasattr(self.hf_config, "vision_config")
    or hasattr(self.hf_config, "audio_config")
)
