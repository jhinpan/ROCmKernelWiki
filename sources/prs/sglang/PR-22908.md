# [AMD] Resolve Qwen3.5 MTP (speculative decoding) radix cache conflict.

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#22908](https://github.com/sgl-project/sglang/pull/22908) · **Merged:** 2026-04-21 · **Author:** @ChangLiu0709

**Inclusion reason:** kernel path 'python/sglang/srt/server_args.py'; keyword 'attention'

## Summary (from upstream PR description)

Motivation
When using speculative decoding (e.g., EAGLE) with Qwen3_5MoeForConditionalGeneration, SGLang raises a hard ValueError in _handle_mamba_radix_cache():
ValueError: Speculative decoding for Qwen3_5MoeForConditionalGeneration is not compatible
with radix cache when using --mamba-scheduler-strategy no_buffer. To use radix cache with
speculative decoding, please use --mamba-scheduler-strategy extra_buffer and set SGLANG_ENABLE_SPEC_V2=1.

This blocks users from running Qwen3.5 MoE models with speculative decoding out of the box. The error message asks users to set --mamba-scheduler-strategy extra_buffer and SGLANG_ENABLE_SPEC_V2=1, but this silently fails on ROCm/non-CUDA devices where extra_buffer is not supported (AssertionError: Mamba extra_buffer is only supported on CUDA devices with FLA backend).
Modifications


python/sglang/srt/server_args.py: In _handle_mamba_radix_cache(), replace the hard ValueError with device-aware automatic resolution:

On CUDA: Automatically switch to extra_buffer mamba scheduler strategy and enable SGLANG_ENABLE_SPEC_V2, so Qwen3.5 MoE speculative decoding works out of the box without any manual flags.
On ROCm / non-CUDA: Automatically disable
