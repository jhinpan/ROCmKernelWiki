# [diffusion] Fix diffusion serve warmup defaults

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#26247](https://github.com/sgl-project/sglang/pull/26247) · **Merged:** 2026-05-27 · **Author:** @mickqian

**Inclusion reason:** kernel path 'python/sglang/multimodal_gen/configs/pipeline_configs/base.py'; keyword 'fp8'

## Summary (from upstream PR description)

Summary

Keep sglang serve warmup enabled by default, but make it server-based instead of first-request-based.
After HTTP /health is ready, send one lightweight internal warmup request through the scheduler; only print The server is fired up and ready to roll! after that warmup succeeds.
Gate non-health HTTP traffic until server-based warmup completes, so real generation requests cannot race ahead of warmup.
Build the server warmup request from the shared warmup helper and use model-default negative prompt / guidance so the negative text embedding cache is populated.
Use a non-empty placeholder prompt for image-input warmup requests, which is required by Qwen-Image-Edit style processor paths.
Preserve explicit CLI/config warmup=false, preserve --warmup-resolutions scheduler warmup, and keep disagg role warmup out of HTTP server warmup.
Clarify warmup and layerwise-offload logs to avoid misleading or colored output.

Root Cause
The first fix made sglang serve default to warmup before ServerArgs logging, but that still used request-based warmup: the first real generation request was copied as a warmup request. That is not the desired serve behavior because the server can report ready
