# [MUSA] Fix startup with patched torchada

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#26437](https://github.com/sgl-project/sglang/pull/26437) · **Merged:** 2026-05-28 · **Author:** @popsiclexu

**Inclusion reason:** kernel path 'python/sglang/jit_kernel/utils.py'; keyword 'gemm'

## Summary (from upstream PR description)

Summary

Bump MUSA torchada requirements to >=0.1.57 so SGLang picks up MooreThreads/torchada#70.
Skip CUDA PDL arch probing on MUSA runtime.

Motivation
SGLang can fail during MUSA startup with:
AttributeError: module 'triton.language.extra' has no attribute 'cuda'
The torchada-side patch is available in MooreThreads/torchada#70, so this updates the dependency and avoids the CUDA-specific PDL path on MUSA.
Validation
Test startup script
python3 -m sglang.launch_server \
  --model-path "$MODEL_PATH" \
  --served-model-name "./DeepSeek-V2-Lite-Chat" \
  --mem-fraction-static 0.75 \
  --disable-overlap-schedule \
  --host "$HOST" \
  --port "$PORT" \
  --attention-backend fa3 \
  --cuda-graph-bs $(seq 1 2 64) \
  --tp-size 1 \
  --chunked-prefill-size -1 \
  --max-prefill-tokens 8192 \
  --disable-piecewise-cuda-graph
