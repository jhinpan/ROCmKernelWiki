## Summary (from upstream PR description)

Summary

Updated est_time for 57 test files (CUDA/CPU only, AMD untouched) based on actual CI runtime data
Analyzed 6 recent scheduled PR Test runs (~1487 data points across 256 test files)
Excluded timeout cases (elapsed >= 1190s) from analysis

Motivation
The LPT (Longest Processing Time) partition algorithm relies on accurate est_time to balance test distribution across CI jobs. Current estimates are significantly off for many tests, causing:

Partition imbalance: some jobs finish in 11min while others take 25min
Wasted CI time: over-estimated tests waste partition budget
