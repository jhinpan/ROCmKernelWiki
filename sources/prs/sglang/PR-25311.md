# perf(mla): TMA bulk-store set_mla_kv_buffer (up to 12× over baseline)

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25311](https://github.com/sgl-project/sglang/pull/25311) · **Merged:** 2026-05-15 · **Author:** @ch-wan

**Inclusion reason:** kernel path 'python/sglang/jit_kernel/benchmark/bench_set_mla_kv_buffer.py'; keyword 'fp8'

## Summary (from upstream PR description)

Motivation
The MLA paged-KV scatter-write (set_mla_kv_buffer) was a 1D Triton kernel (BLOCK=128, grid (n_loc, ceil(total_dim/BLOCK))). It is reasonable at very small batch sizes but degrades linearly with n_loc — 83.5 µs at bs=16384 on GB300. For DeepSeek-V4 prefill (61 layers × thousands of locs per step) this is a meaningful chunk of layer time.
This PR introduces two changes, both backed by the new dispatcher in set_mla_kv_buffer_triton:

A TMA bulk-store JIT CUDA kernel for bs ≥ 768, where the kernel issues one cp.async.bulk.global.shared::cta per row instead of per-element vector stores, packing 4-8 items per CTA. Cuts the bs=4096 wall-time from 21.6 µs to 1.76 µs.
A single-CTA-per-loc Triton path for bs < 768, by switching the Triton kernel's BLOCK from 128 to next_pow2(nope_dim + rope_dim). Same Triton kernel as before, but now one CTA covers the whole row in one tile — eliminates the 5× CTA fan-out the legacy BLOCK=128 path had and the per-loc launch overhead that came with it. Cuts bs=128 from 1.41 µs to 0.94 µs.

Modifications
