# [ROCm] Eliminate redundant contiguous copy in MLA attention on ROCm MXFP4

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25463](https://github.com/sgl-project/sglang/pull/25463) · **Merged:** 2026-05-29 · **Author:** @rbrugaro-amd

**Inclusion reason:** kernel path 'python/sglang/srt/models/deepseek_common/attention_forward_methods/forward_mla.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation
On the ROCm MXFP4 decode path (_use_aiter_gfx95 with w_vc.dtype == torch.uint8), the batched_gemm_afp4wfp4_pre_quant kernel outputs attn_bmm_output in (heads, batch, v_head_dim) layout. The current code then does:
attn_bmm_output = attn_bmm_output.transpose(0, 1).flatten(1, 2)
The .transpose(0, 1) makes the tensor non-contiguous, so .flatten(1, 2) triggers an implicit .contiguous() copy — appearing as a direct_copy_kernel_cuda (elementwise_kernel_manual_unroll) in profiling traces at ~4µs per layer.
With 61 MoE layers this adds up to ~268µs per decode step of unnecessary data movement.
Changes
Pre-allocate the output buffer in (batch, heads, v_head_dim) layout (the target shape) and pass a transposed view (heads, batch, v_head_dim) to the GEMM kernel. The aiter batched_gemm_a16wfp4 Triton kernel already accepts arbitrary output strides via explicit stride_cb, stride_cm, stride_cn parameters, so it writes correctly into the non-contiguous view.
After the GEMM, .flatten(1, 2) on the already-contiguous (batch, heads, v_head_dim) buffer is a zero-cost view — no copy needed.
Scope: Only affects the _use_aiter_gfx95 and self.w_vc.dtype == torch.uint8 branch (MXFP4 on MI355X/gf
