# [docs] DeepSeek-V4 cookbook: balanced MegaMoE cap, H200 Pro FP4 mem-frac, nsa-* compat, PD-disagg fixes

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#26164](https://github.com/sgl-project/sglang/pull/26164) · **Merged:** 2026-05-23 · **Author:** @zijiexia

**Inclusion reason:** keyword 'gemm'

## Summary (from upstream PR description)

Summary
Five small fixes to the DSV4 deployment-command generator (docs_new/src/snippets/autoregressive/deepseek-v4-deployment.jsx).
1. Blackwell + Balanced + MegaMoE → cap per-rank dispatch buffer at 4096
Balanced recipe always runs MTP (1/1/2); the draft pass needs more GMEM headroom than max-throughput's =8320. Adds SGLANG_OPT_DEEPGEMM_MEGA_MOE_NUM_MAX_TOKENS_PER_RANK=4096 whenever megamoe !== \"disabled\" && recipe === \"balanced\" (megamoe is already gated to Blackwell HW).
2. H200 Pro (FP4) Low-Latency: --mem-fraction-static 0.88 → 0.83
Pro runs flashinfer_mxfp4 + MTP 3/1/4 and needs more headroom for draft-model + MTP buffers than the balanced / max-throughput recipes. Other H200 FP4 Pro recipes keep 0.88.
3. Context-Parallel: revert flag names to nsa-* for :latest image compatibility
The --enable-nsa-prefill-context-parallel → --enable-dsa-prefill-context-parallel rename landed in #25821 on 2026-05-20. The :latest release image predates that PR. To avoid breaking the published cookbook for users on :latest, emit the deprecated nsa-* names and prepend a user-visible shell-comment block to the generated command pointing main-branch users to swap nsa- → dsa-.
