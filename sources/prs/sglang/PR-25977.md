Motivation
On MI355, the Triton MLA attention dispatch for DeepSeek V4 extend/prefill has two issues:


c128 layers (L31-type, non-MoE): Fall through to the slow separate gather_dequant + unified_sparse_decode fallback path because _should_use_fused_nosplitk() rejects total_topk < 200. The fused dual-scope kernel already exists and works for c4 layers with larger topk. c128 layers with total_topk=192 are blocked solely by this threshold, which was calibrated for decode workloads.


TP>1 configurations (h_q <= 64): Both c128 and c4 layers are blocked by a h_q <= 64: return False guard, causing c4 layers to fall into a 3-chunk fallback (5 GB intermediate buffer exceeds 2 GB limit). The fused kernel avoids buffer allocation entirely, so this limit is irrelevant.
