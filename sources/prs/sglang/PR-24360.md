# [AMD] Replace naive triton RMSNorm with aiter RMSNorm for diffusion model

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#24360](https://github.com/sgl-project/sglang/pull/24360) · **Merged:** 2026-05-08 · **Author:** @yichiche

**Inclusion reason:** kernel path 'python/sglang/multimodal_gen/runtime/layers/layernorm.py'; keyword 'kernel'

## Summary (from upstream PR description)

Motivation
Replace the default Triton-based RMSNorm with aiter's optimized HIP RMSNorm kernel in the diffusion multimodal_gen path on ROCm, reducing per-kernel RMSNorm time by ~30% (430 us → 290 us, ~0.2% of denoise total time).
Modifications
Key changes in layernorm.py:

Add forward_aiter method to RMSNorm that dispatches to aiter.rmsnorm2d_fwd (plain) or aiter.rmsnorm2d_fwd_with_add (fused residual-add variant).
Reshape 3-D inputs to 2-D before calling aiter, since the underlying C++ op (rmsnorm_quant_kernels.cu) interprets input.size(1) as hidden_size.  Without the reshape a 3-D tensor like (1, 90000, 5120) causes the dispatch macro to reject n=90000 with "not support n: 90000".
Guard on dtype (fp16/bf16 only) and variance_size_override to fall back to the native path when aiter cannot serve.
