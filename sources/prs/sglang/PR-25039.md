# [AMD] Disable unittest fail-fast for deepseekv4 perf test

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25039](https://github.com/sgl-project/sglang/pull/25039) · **Merged:** 2026-05-13 · **Author:** @yctseng0211

**Inclusion reason:** kernel path 'test/registered/amd/test_deepseek_v4_flash_fp4.py'; keyword 'flash'

## Summary (from upstream PR description)

Motivation
The 4 DSv4 test files (flash_fp8, flash_fp4, pro_fp8, pro_fp4) each define both an accuracy test (test_a_gsm8k) and a performance test (test_b_perf_8k_1k) that share a single very-expensive server launch in setUpClass.
run_suite.py's run_one_file launches each test file with python3 <file> -f which enables unittest fail-fast, so an accuracy assertion failure would skip the perf measurement and lose the perf table from the GitHub step summary.
This is a minimal-impact mitigation: each affected file now strips
-f/--failfast from sys.argv locally before calling unittest.main(),
so both test methods always run. A future PR can fully separate acc
and perf into independent test files / CI jobs if needed.
