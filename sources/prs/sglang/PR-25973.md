# Fix PD decode radix cache double-counting cached_tokens

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25973](https://github.com/sgl-project/sglang/pull/25973) · **Merged:** 2026-05-28 · **Author:** @hippothewild

**Inclusion reason:** keyword 'decode'

## Summary (from upstream PR description)

Motivation
Fixes #25972.
In prefill/decode (PD) disaggregation with --disaggregation-decode-enable-radix-cache, usage.prompt_tokens_details.cached_tokens is double-counted and can exceed prompt_tokens (e.g. 128 cached for an 87-token prompt). This corrupts both the OpenAI usage field and sglang_cached_tokens_total{engine_type="decode"}.
Root cause: the decode node writes req.cached_tokens twice with no reset between:

_commit_transfer_to_req (disaggregation/decode.py) sets it from the prefill-reported value shipped in the metadata buffer.
prepare_for_prebuilt (disaggregation/decode_schedule_batch_mixin.py) then adds pre_len - already_computed, where already_computed starts at 0 on the decode node.

With decode radix cache on, _match_prefix_and_lock populates prefix_indices so pre_len > 0, and the shared prompt prefix already counted by prefill is added again. With it off, pre_len == 0 and the bug does not manifest — matching the observed condition.
Modifications

decode.py: seed req.already_computed from the prefill-reported cached_tokens at commit time, so the later += only adds decode-side reuse beyond what prefill counted.
decode_schedule_batch_mixin.py: clamp the delta with max
