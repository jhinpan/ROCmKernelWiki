# [AMD] mirror nightly images to local registry and prefer LAN pulls

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#23073](https://github.com/sgl-project/sglang/pull/23073) · **Merged:** 2026-04-17 · **Author:** @yctseng0211

**Inclusion reason:** keyword 'mi300'

## Summary (from upstream PR description)

Motivation
For preventing docker rate limit issue on mi300x

Mirror nightly rocm/sgl-dev images to the in-network registry after the Docker Hub publish step completes, for both the standard AMD nightly workflow and the ROCm 7.2 nightly workflow.
Persist the published IMAGE_TAG as a short-lived artifact immediately after docker push rocm/sgl-dev succeeds, so the mirror job can reuse the exact same tag even if a later push step fails.
Update AMD CI container startup scripts to resolve images in this order: local runner cache, in-network registry, then public Docker Hub.
Add exponential-backoff retry logic only around Docker Hub login and public pulls, while keeping LAN registry pulls as a single direct attempt.
