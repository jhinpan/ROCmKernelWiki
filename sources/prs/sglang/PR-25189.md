# [perf] DeepSeekV3: drop redundant FP32 upcasts in trtllm MoE paths

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#25189](https://github.com/sgl-project/sglang/pull/25189) · **Merged:** 2026-05-22 · **Author:** @maocheng23

**Inclusion reason:** kernel path 'python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py'; keyword 'gemm'

## Summary (from upstream PR description)

Summary
Drop the explicit .to(torch.float32) upcasts on router_logits before each trtllm_*_moe call for DeepSeekV3 routing. flashinfer ≥ 0.6.8 (trtllm_fp4_block_scale_moe, trtllm_fp8_block_scale_moe, trtllm_fp8_per_tensor_scale_moe) accept BF16 router_logits directly, so the explicit FP32 upcasts are no longer required.
flashinfer is pinned at 0.6.11.post1 in python/pyproject.toml, well past the 0.6.8 cutoff.
Changes
python/sglang/srt/layers/moe/moe_runner/flashinfer_trtllm.py — three sites

FP4 block-scale path (fused_experts_none_to_flashinfer_trtllm_fp4): drop the if routing_method_type == DeepSeekV3: router_logits = router_logits.to(torch.float32) block.
FP8 block-scale path (trtllm_fp8_block_scale_moe_wrapper call): drop the inline ternary .to(torch.float32) if DSV3 else router_logits.
FP8 per-tensor path (trtllm_fp8_per_tensor_scale_moe_wrapper call): simplify the FP32/BF16 conditional to an unconditional .to(torch.bfloat16).

python/sglang/srt/models/deepseek_v2.py
MoEGate.forward continues to emit FP32 router_logits. A TODO: will check the dtype to be bf16 is added to the SM100/103 + 256-expert fast path as a marker for the follow-up that would migrate the gate output to BF
