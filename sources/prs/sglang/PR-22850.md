# [AMD] Reduce NSA indexer kernels (weights_proj,  k-cache store kernel fusion)

**Repository:** [sgl-project/sglang](https://github.com/sgl-project/sglang) · **PR:** [#22850](https://github.com/sgl-project/sglang/pull/22850) · **Merged:** 2026-04-19 · **Author:** @1am9trash

**Inclusion reason:** kernel path 'python/sglang/srt/layers/attention/nsa/nsa_indexer.py'; keyword 'gemm'

## Summary (from upstream PR description)

Motivation

Redundant kernels in the NSA indexer on HIP:
weights_proj:

The ReplicatedLinear layer uses fp32 params_dtype, preventing tgemm from dispatching to the tuned bf16 fused kernel and falling back to torch GEMM instead. An additional x.to(fp32) cast is also required before the GEMM.
Total: 3 kernels (dtype cast + fp32 GEMM + reduction).

Indexer k-cache store:

Key quantization (act_quant) and cache write (set_index_k_scale_buffer) are two separate kernel launches.

Modifications

weights_proj:

Switch params_dtype to bf16 (aligned with the CUDA path) and remove the redundant input dtype cast. The GEMM now dispatches to aiter::wv_splitk_small_fp16_bf16_kernel in a single kernel.
Perf impact: 3 -> 1 kernel, ~10 µs saved per layer.

Indexer k-cache store:

Replace the two-step quant + store with the fused indexer_k_quant_and_cache kernel from AITER.
Perf impact: 2 -> 1 kernel, ~4 µs saved per layer.

Accuracy Tests

TP8, GSM8k:

MI300 (GLM-5-fp8): 0.950
MI355 (GLM-5.1-fp8): 0.951

Speed Tests and Profiling

GLM-5.1-FP8 server command on MI355:
export SGLANG_ROCM_FUSED_DECODE_MLA=0
export ROCM_QUICK_REDUCE_QUANTIZATION=INT4
export SAFETENSORS_FAST_GPU=1
python3 -m sglang.launc
